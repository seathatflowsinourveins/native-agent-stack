Evidence class: source_review (GitHub metadata, upstream docs, publisher release data) with adversarial refutation of every packet; some judges and refuters also ran unretained spot probes on the host (MCP Inspector tools/list on local servers, an import probe of vercel/workflow, /dev/kvm and docker presence checks), cited in their votes but with no retained raw output; one retained local_integration execution for the single integrate_now row (agent-lab tools/mcp-conformance/check.sh, including a negative fixture that observes the --strict exit-6 failure path). Nothing here promotes a catalog layer verdict.

**Disposition policy.** Dispositions are per (category, repository): the same repository judged as a coding harness and as a protocol SDK answers two different questions, so the majority vote in each category stands (agentclientprotocol/agent-client-protocol and agentclientprotocol/codex-acp keep different dispositions per category). Only one cross-category override is applied, by the canonical-record precedence rule (dagger/container-use). refuted means claims in the evidence packet did not hold; not_adopted means the evidence held but the candidate does not fit the criteria.

## Method

- Discovery: 12 finders (six categories x web and GitHub-search angles, Sonnet), a completeness critic (Opus) and a gap round; 356 unique repositories, 297 not yet in the catalog; gates: 290 pass, 64 flagged (license unknown), 2 excluded (archived or no push in 12 months).
- Shortlist: three independent Opus judges per category on the enriched metadata; 38 of 372 category-rows shortlisted by majority, 334 rejected with the reasons retained in the JSON.
- Evidence: one extraction packet per shortlisted repository (Sonnet, primary sources only), then an accuracy lens and a fit lens (Opus) trying to refute each packet.
- Selection: three Opus judges per category on the preregistered criteria C1-C6; majority disposition, conservative on no majority; a completeness critic over the merged result; coordinator resolutions applied in code and listed below.

## Preregistered criteria

Preregistered criteria (apply exactly these, cite evidence for each): C1 native-auth fit: runs on the user's existing native sign-ins (Claude Code subscription login, Codex/ChatGPT login, GitHub login, Google login) or a local model; a separate paid API key is a recorded penalty, not an exclusion. C2 programmatic control: SDK or headless/exec mode with structured events, resumable sessions, custom tools or MCP. C3 isolation and ownership: works per worktree/sandbox without hidden global state; deterministic code can own the effects. C4 evidence quality: upstream tests and CI, release cadence in the last 6 months, permissive or source-available license recorded, maintenance signals. C5 non-duplication: adds capability beyond the incumbents; overlap without an executed comparison means keep_but_compare with a named comparison, never adoption. C6 portability: Linux/WSL2 x86_64 and macOS arm64 install path. Rules: agreement between judges never promotes; only an executed local comparison later promotes to adopted. Dispositions: integrate_now (recommend an integration unit today: name the exact acceptance command a bounded local_integration check would run), targeted_candidate (worth a comparison, name it), keep_but_compare (overlaps an incumbent; name the comparison that would overturn), not_adopted (does not fit; say why), refuted (claims in the evidence did not hold).
