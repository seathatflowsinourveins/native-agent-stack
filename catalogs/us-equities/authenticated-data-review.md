## Timing findings that change the implementation contract

**Massive:** `list_tickers(date=..., active=False)` can investigate inactive symbols on an explicit date. Its `get_ticker_details(date=...)` docstring, however, says SEC information is compared to the filing's period-of-report date. A quarter-end date can precede filing acceptance, so such fields cannot enter an as-known fundamental feature merely because a historical date was supplied. Preserve the difference between ticker identity history and information availability. [Pinned SDK source](https://github.com/massive-com/client-python/blob/481e5c270ea85e8eae5e96f8b9fda34e5e2a674a/massive/rest/reference.py#L140-L160), [ticker endpoint](https://massive.com/docs/rest/stocks/tickers/all-tickers).

**Databento:** `corporate_actions.get_range` defaults to `pit=False`. Its implementation sorts `ts_record` and applies `groupby(event_unique_id).agg('last')`: a latest-style per-column collapse that can combine latest non-null values instead of preserving an intact source row. Use `pit=True` to retain returned revisions, an explicit bounded `index='ts_record'` query for revision ingestion, and a separate decision-time cutoff. Retention alone does not create an as-known dataset. [Pinned revision handling](https://github.com/databento/databento-python/blob/e675ef30369f5ee9f68b04606080c519adf3be69/databento/reference/api/corporate.py#L34-L180).

Its security-master range defaults to `ts_effective`; that is effective time, distinct from vendor record/creation time and our local observation time. Keep issuer, security and listing IDs separate. Do not join by ticker alone, or assume the vendor's normalized ticker always matches a market feed's spelling. [Pinned range API](https://github.com/databento/databento-python/blob/e675ef30369f5ee9f68b04606080c519adf3be69/databento/reference/api/security.py#L33-L110), [official schema and symbology limits](https://databento.com/docs/schemas-and-data-formats/security-master).

**OpenFIGI:** the documented mapping interface supplies identifiers, not a general historical as-of or first-observed guarantee. Maturity and expiration filters describe the instrument's terms. Retain every mapping candidate and require explicit exchange/security-level disambiguation; a present-day crosswalk cannot reconstruct an as-known equity universe. This is a limit of the reviewed interface, not a claim that historical services can never exist. [Official mapping contract](https://www.openfigi.com/api/documentation).

## Storage, validation and rights

ArcticDB's `read(as_of=...)` and explicit-version snapshots can preserve data we already observed. They cannot recover missing prior vendor revisions. Its pinned source warns about concurrent pruning during snapshot construction. Current code uses **Business Source License 1.1**, with an Additional Use Grant excluding its defined third-party Database Service and a per-version two-year change to Apache-2.0. Keep the deployment scope and license explicit; this does not imply that internal research use is prohibited. [Snapshot/source semantics](https://github.com/man-group/ArcticDB/blob/7d30a6eefe709e5379f1dd7f38b03074750cf1be/python/arcticdb/version_store/library.py#L2689-L2733), [pinned license](https://github.com/man-group/ArcticDB/blob/7d30a6eefe709e5379f1dd7f38b03074750cf1be/LICENSE.txt).

Pandera is useful when the same schema recurs: require keys, joint revision uniqueness, finite values and explicit nullability, then collect failures with `lazy=True`. At the provenance boundary, use `strict=True`, `coerce=False`, `add_missing_columns=False` and `drop_invalid_rows=False`; retain original responses and rejection details. A valid schema still says nothing about economic truth or historical availability. [Native validation API](https://github.com/unionai-oss/pandera/blob/1c9a139436ae2657dd2cb100655b84138d7da443/pandera/api/pandas/container.py), [schema documentation](https://pandera.readthedocs.io/en/latest/dataframe_schemas.html).

OpenBB's pinned license declares **AGPLv3**, despite GitHub's `NOASSERTION` metadata result. Its fetcher pipeline does not itself impose this repository's revision/availability contract, and OpenBB does not supply the underlying provider data rights. Broad connector coverage is insufficient reason to add it to an already working direct SDK path. [Pinned license](https://github.com/OpenBB-finance/OpenBB/blob/3e071fcc2cd9f891cac6040ae60296dba76dab46/LICENSE), [fetcher pipeline](https://github.com/OpenBB-finance/OpenBB/blob/3e071fcc2cd9f891cac6040ae60296dba76dab46/openbb_platform/core/openbb_core/provider/abstract/fetcher.py#L73-L85), [provider documentation](https://docs.openbb.co/odp/python/extensions/providers).

Massive and Pandera clients use MIT; Databento and the OpenFIGI examples use Apache-2.0. Client licenses are separate from dataset access and redistribution rights. Massive's individual and business data uses differ; Databento reference access requires its own entitlement. No alternative provider entitlement was exercised here. [Massive product terms](https://massive.com/stocks), [Databento access model](https://databento.com/pricing).

## Next acceptance and stopping rule

Preserve the already accepted component versions and build on the [earlier API-drift findings](data-readiness-review.json). In particular, Alpaca-py 0.44.0 lacks the current corporate-action REST `region` and `data_quality` fields; current complete-only defaults are not a completeness guarantee. Keep economic event dates, provider processing/revision timestamps and local receipt times distinct. [Alpaca corporate-actions contract](https://docs.alpaca.markets/us/reference/corporateactions-1).

The next dataset acceptance should freeze a small symbol/window set before requests, retain every attempt and page, hash original payloads, record explicit feed/adjustment, and validate source identities and timestamps before any return labels. Missing historical observation times stay unknown. When an alternative is needed, run only its bounded acceptance from the JSON review and compare its additional evidence against the existing path.

Stop expanding this wave at those six decisions. None of the unresolved findings is fixed by adding another runtime. Native account access, data coverage, revision eligibility and simulation merit remain separate evidence gates.
