# Foundation convergence: native boundaries before more services

This wave reviewed **10 finalists in two bounded rounds**, refreshed their primary repository/release identities, captured **59 source files** and reused **10 previously reviewed files** at unchanged Context Mode/QMD pins. Three pinned discovery lists supplied comparators and further leads. Selected implementation and regression-test excerpts informed decisions; downloaded files and workflow definitions do not establish a complete audit or passing upstream CI. The [typed source matrix](foundation.json) contains pins, dates, licenses, hashes, prospective commands and limits.

The concrete addition is [native ai-memory lifecycle acceptance](../../../blueprints/us-equities/memory-lifecycle/README.md): **31 native tool calls, 23 fixture checks and three expected rejections**, using an empty isolated store with no models, imported sessions or access to existing memory. The accepted service was unchanged. Expired pinned pages disappear from default search, but exact-path reads remain available until an explicit sweep. An ingestion-time lookup finds a superseded version; deletion removes its current and historical query results. Git checkpoints can retain history, so this is neither secure erasure nor market point-in-time evidence.

Round one focused on missing acceptance for incumbent lifecycle and hook behavior. Round two examined SDK transport, scoped memory and Apple Silicon retrieval alternatives, then checked three maintained discovery lists. The outcome supports one new measured boundary and conditional follow-ups, not another parallel memory service. Coding-memory benchmark and repository-local context leads remain discovery-only; this is a bounded stopping point, not universal landscape saturation.

The coordinator's full-star enumeration is an identity/freshness audit. It is not counted as deep source review; the detailed review scope here is the ten named finalists.

The next useful native checks are an isolated RTK Codex hook/permission fixture for the exact adopted release and a held-out retrieval evaluation tied to encoder identity, full corpus, query shaping and write/reindex cost. Replacing an embedding model should never silently mix old vectors, omit failed records or report text-fallback scores as semantic retrieval. Neither follow-up was executed here.

All unexecuted commands in the matrix are explicitly prospective. The actual memory fixture used the installed 2.3.1 ELF, whose release commit differs from inspected main. Claude's GitHub stable release is 0.2.156 while PyPI reports 0.2.157; MCP reports 2.2.0 on both release/package surfaces. MLX Embeddings reports 0.1.0 with a March release and May source revision, so it is not described as a newly released encoder. Version recency is a maintenance signal, not evidence of superior task quality.

This lane made no model calls or installations and changed no native client settings, active index, credentials, service or durable project memory. Current provider usage remains separate from Context Mode/RTK estimates and artifact compression. Cross-platform source support does not certify macOS execution, and historical Codex/Claude receipts do not certify every future session.
