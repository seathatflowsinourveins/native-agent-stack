# Daily ecosystem upkeep

Run one maintenance cycle for this host within the deploying owner's current authorized maintenance scope. This versioned task describes the existing upkeep function; it grants no additional permission. Apply the latest qualified choice through supported upstream installation and lifecycle procedures. A new release or a freshness report is a candidate, not acceptance.

Use `~/.local/state/native-agent-stack-upkeep/` for private run artifacts, an inventory, pending work and a compact `status.json`. Preserve native session identifiers and returned outputs there. The Dagu upkeep step allows 45 minutes and the native coordinator allows 80 turns. Complete at most one component or practice change per cycle; rotate across adopted layers using oldest actionable work first. Dagu's local scheduler queue dispatches one run at a time. Account separately for manual invocations and other active clients or workers.

Run heavy work at nice 19. On 2026-10-06, do not start a heavy phase that would enter 10:35-13:45Z or 19:50-00:10Z on 2026-10-07. No user-manager restart is allowed in those windows. Pause between steps and never kill a running case. Defer the phase and record it in status. Never read or copy a credential value or credential file, invoke OmniRoute `/api/providers/client` or GET `/api/settings`, use sudo, or merge a pull request. Native sign-in and OS consent remain owner actions.

A shared service cutover requires the documented at-rest backup, recovery procedure and a reconciled idle window; defer its cutover while another session owns it. Prefer the newest qualified version within the accepted task role; a different model family or tool requires the relevant comparison before changing the default.

Follow `docs/lanes.md`, the PR template and required checks when publishing; auto-adopt only after source-cited independent review and successful applicable native/CI gates. A passed workflow or a version number alone never changes a research winner. Update the existing public checkpoint only for accepted work, following `observability/grand-dashboard/README.md`. Roll back the exact changed selection if its post-cutover check fails and record the returned failure.

Write `status.json` with UTC start/end, source revision, native session id, layers inspected, selected candidate, decision (retain/trial/adopt/defer), actual check exits/output locations, provider usage when available, changes, rollback selection, holds and next action. Keep usage unknown where unavailable. Emit a concise final result naming this file. A cycle with no eligible change is a successful retain decision; it is not a claim that every layer is current or universally best.

This authorization covers adopted userspace tools, native client defaults, existing service lifecycle and the existing evidence/publication workflow. Keep native sign-in and OS consent interactive when required. Broker orders, live trading, paid hosting, new paid-provider fallback and destructive data migration remain outside this unattended task.
