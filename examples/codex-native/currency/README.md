# Proposed Codex release currency

This draft composes Dagu 2.18.2, GitHub CLI 2.102.0, the publisher's complete Linux package and systemd 259. It stages a release beside the prior version, requires the co-op's release review and two real queued-task canaries, and selects the new executable for future launches only. No user unit, default launcher or provider configuration is installed by this checkout. The native 0.162.0 stage is distinct from this automation proposal.

## Workflow and lifecycle

`currency.sh stage` checks the protected marker, reads the selected identity wrapper's final `exec` path, queries a stable upstream release and refuses a backward version move. It downloads the complete x86_64 Linux musl package, checks both its API digest and publisher checksum, and extracts only into a fresh versioned path. It records all archive-member bytes, permissions and link targets, including Code Mode, ripgrep, sandbox and voice resources. Native version output is a staging check.

Reusable package provenance lives in `CURRENCY_STATE/stages/<version>`. Failed downloads and their native checksum results remain in the specific run. Transaction, canary approval and exact launcher backup live in `CURRENCY_STATE/runs/<Dagu run id>`, so a later upstream outage cannot roll back an earlier accepted upgrade. A pre-existing manually staged path without this provenance refuses automatic overwrite. After a reviewed initial cutover, a daily check of the same selected version records `CURRENT`.

`currency.sh canary` gives the co-op adapter the candidate executable, prior executable, result path and upstream notes file. It allows 20 minutes. The adapter owns two parked-lane launches, release-note review, queued tasks, native smoke calls and cleanup on timeout. It must preserve explicit model, effort and provider choices, exclude paper-open-e2e, avoid credential/environment-store reads and emit sanitized native metadata rather than conversations. With no eligible real queued tasks it refuses; it invents no work. Caller PATH selects the vendor binary for these two launches without rendering a temporary launcher.

The adapter writes a JSON receipt containing:

- `evidence_class: native_proven`, exact `version` and `previous_version`.
- `release_review`: tag, reviewer, tagged release URL, official install-documentation URL, notes SHA256, `approved_for_canary: true`, `declared_breaking_items` and `compatibility_items` arrays. Empty arrays mean that the reviewer found none; source review must support that choice.
- Exactly two distinct `lanes`, each with lane/thread, `was_parked: true`, exact `selected_executable`, a named completed `queued_task`, and seven distinct `tools_smoke` results with `ok: true`.
- `baseline` and `current`: exact version/turn, observed tool-call total, per-tool `tool_counts` whose sum matches that total, nonnegative observed native/MCP/provider error and recovery/retry counts. An idle baseline may have zero calls and an empty map; current smoke/task work requires positive calls. Current also names the candidate binary SHA256. Unknown observed counters cannot pass; hidden provider/transport totals stay null rather than being converted to zero. Wrapper calls and nested tool invocations use separate counters and are never added as one total.
- Current provider error events must be zero. Every observed native/MCP failure must have an `error_dispositions` entry with category, positive count, `candidate_caused: false`, source URL, explanation and failure-text SHA256, backed by the native receipt evidence. This permits a proven pre-existing tool guard or task-helper error while refusing unexplained errors. Native/MCP disposition counts must exactly cover the observed failures. Differences in calls and observed retries remain visible for review; source judgment comes from the co-op, not a guessed regular expression.
- Each lane's nonempty `evidence` array of sanitized receipt paths and SHA256 values. Existing files must resolve inside this run's state directory. The gate checks the actual files, not only the JSON declaration.

The gate seals the transaction and receipt hashes after these checks. Promotion rechecks evidence, the full vendor package, upstream notes, the protected marker and launcher custody. It renders from the authenticated run backup and rechecks the current launcher immediately before atomic replacement. All cooperating default-selection writers must hold the same `CURRENCY_STATE/currency.lock`; atomic rename alone is not conflict detection. A failed canary retains the previous default. A failed or aborted promotion restores the exact prior wrapper only when this run owns the selected bytes and protection allows restoration; foreign edits refuse rollback.

The Dagu run is bounded to 30 minutes and the proposed service to 35 minutes. Native API/download commands have five-minute bounds. Service termination does not establish that a detached lane stopped: the co-op adapter must close or park only its exact two owned canary sessions and retain the failed receipt. Running paper sessions are excluded from dispatch, cleanup and selection changes. No live model, service-restart or recovery acceptance is claimed by the local tests.

## Proposed unit review

The service and timer are under `adoption/templates/systemd/codex-currency.{service,timer}` and are proposals only. `environment.example` contains only reviewed paths and native executable lookup. The co-op adapter is deliberately an owner-supplied executable; this PR does not duplicate private lane-launch or task-queue code. Its implementation, native two-lane result and cleanup contract must be reviewed before any future installation. No unit is copied into a user manager, enabled, started or reloaded by this work.

At adoption, the marker and state paths in the environment and unit must refer to the same owned state root. Protect a window by creating `CURRENCY_PROTECTED`; remove it only through its owner's lifecycle. Startup skips are recorded, and the marker is checked again at each consequential boundary. Records append `## CODEX-CURRENCY` with actual UTC, tag and install-doc citation; upstream command failures append `## OMNI-ERROR` immediately.

## Verification classes

`python3 -m unittest discover -s tests -p test_codex_currency.py` exercises constructed receipts and temporary fake distributions. Its19 tests are local integration checks with synthetic inputs, never tools_smoke or a model canary. Native `dagu validate`, `bash -n`, rendered proposal-only `systemd-analyze --user verify` and `python3 scripts/validate.py` check their specific integration contracts. The initial Dagu validation rejected an entrypoint `name` key; that failed condition is retained in the dated decision and corrected by using the filename identity. The [sanitized current native canary receipt](../../../evidence/receipts/codex-0162-stage-canary-20261008.json) separately records both completed 0.162.0 queued tasks and seven shared MCP smoke checks; it does not execute or accept this standing workflow. Future automation PASS requires its own co-op native receipts and prior-turn comparisons.
