# U2 pin currency: Next.js 16.3.6 to 16.3.8 (2026-10-01)

Unit U2 of `docs/decisions/2026-10-01-definitive-sota-wsl-program.md` gives every selected pin behind its latest
release a dated hold with a reason, or a move after qualification, Next.js first. This record is that decision for
Next.js. The other pins of U2 keep their own records.

## Decision

Move the application-delivery recipe's lock and the stack pin from Next.js 16.3.6 to 16.3.8.

## Why

- The v16.3.8 release notes list seven security advisories as fixed in that release
  (https://github.com/vercel/next.js/releases/tag/v16.3.8, published 2026-09-30T16:13:46Z, tag commit
  `b0fad0d45eb4c4430fda5eeeb442e8a5af08a5f6`, not a prerelease). The most severe is GHSA-cjq9-62q9-8jv4
  (CVE-2026-94483, high: server-side request forgery in Image Optimization); five are medium and one is low. The
  advisories' own metadata gives the patched version as "16.3.?" for six of them and 16.3.8 for GHSA-h694-7cp9-m8p3;
  the release notes are the association used here.
- This recipe's exposure to them was not established. The move removes the vulnerable versions from its lock, which
  is what the 2026-09-25 bump to 16.3.6 did for GHSA-vcvr-r3jv-pc5j.

## How it was qualified

- The two-file patch (package.json and pnpm-lock.yaml; sha256
  `570ac44d237b6641a5087fe57b079aaf61dcb781b6496a721b0224dd17ea60d0`) changes next, @next/env and the eight
  @next/swc-* entries; every other lock entry is byte-identical. The registry integrity of next 16.3.8 is
  `sha512-U7QEZaTini6wKrb8A8hqLLqYQyCetegKjCpJOyxk642vWoMoU1x5PyZCJFvgYgiptA8xc5j/9xYlZFO7w9Sjmw==`.
- First attempt, failed and kept: at 12:13Z the frozen install exited 1 with ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION
  for the ten packages published on 2026-09-30. pnpm's minimum release age rule is a supply-chain control, so it was
  not bypassed: no exclusion, no policy change (pnpm v12.4.2,
  https://github.com/pnpm/pnpm/blob/9502f3c457717dae3a4ddbf4315a8c4aee16fdb4/pnpm/crates/package-manager/src/minimum_release_age.rs).
- After the window the unchanged candidate passed the recipe's bounded checks on linux-wsl2-x86_64 with Node 24.21.0
  and pnpm 12.4.2: frozen install, peer check, typecheck and production build, each exit 0
  (`evidence/receipts/nextjs-1638-qualification-20261001.json`). The work was delegated to the Codex catalog lane's
  builder; this record's author read the retained outputs and did not re-run them.

## Not run

`make verify` with its PostgreSQL, API and browser stages; a cold-store install; the install on the new
distribution, which is unit U10. pnpm is not in the Linux pin manifest, so the builder installed 12.4.2 into a
task-private prefix; adding it to the profile pins is unit U8.

## Alternatives

- Hold at 16.3.6 with a release-age exclusion: rejected, it disables the supply-chain control for a convenience of
  hours.
- Hold at 16.3.6 without a move: rejected once the window passed, with seven open advisories, one of them high.
- Another framework: out of scope for a security patch; a comparison is the layer's own question.

## Overturn

A regression in `make verify` at 16.3.8, a new advisory against 16.3.8, or a newer patch release.
