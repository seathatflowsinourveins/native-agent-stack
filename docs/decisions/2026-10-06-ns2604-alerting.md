# NativeStack2604 alerting: clock-offset-check, service coverage and the root-filesystem rules

Date: 2026-10-06. Base: `ecfa112764c664d35377dd66b8cfcb67e5a94d60` (`origin/main`).
Status: repository change to the new-WSL install plan's templates; the host apply,
the delivery test and the user's phone confirmation are the co-op's and the
user's (see "Host apply" below). North-star action served: the paper and
simulation host's clock and disk raise an alert that reaches the user, because a
clock off by more than 100 ms trips the trading engine's quote guard and a full
root disk stops the Collector and Prometheus from persisting.

## Problem, as observed on NativeStack2604

- The command center's E2E truth sweep (workflow `wf_6f2c775d-293`, item
  `task-ns2604-coop-20261006T042311Z` section 1) found that no rule on 2604 can
  raise a critical alert: Prometheus held only `EcosystemServiceUnavailable`
  (warning) and `EcosystemAcceptanceTargetDown` (test); Grafana-managed rules and
  the Loki ruler held none.
- `~/.local/bin/clock-offset-check`, run every minute by a user timer and on a
  clock step or zone change by `clock-change-check`, logged three CRIT lines at
  02:26-02:28Z (offset -214.6 to -223.3 ms) and five WARN lines; nothing alerted.
- Read-only on 2026-10-06 at about 04:30Z: of 121 lines since that boot, 45
  carried no `_SYSTEMD_USER_UNIT` while all 121 carried
  `SYSLOG_IDENTIFIER=clock-offset-check` (command-center correction #8: match the
  identifier, not the unit). CRIT lines carry PRIORITY 2 or 3 depending on the
  path in the script, so the message prefix, not the priority, identifies them.
- Prometheus scraped 3 targets; Alertmanager, Loki, Grafana, OmniRoute, Dagu,
  Ollama and agentsview were unobserved. The exporter at 21889 exports
  `system_filesystem_usage_bytes` and `httpcheck_status` without the old
  `ecosystem_` namespace, so the 2026-10-05 ENOSPC rules could not be copied
  verbatim. `/api/v1/status/flags` showed an empty `enable-feature`, so this
  Prometheus does not ingest created-timestamp zeros.

## Decision

1. **Clock lines through the Collector into Prometheus rules.** The plan's
   observability design defers the Loki ruler ("Loki ruler evaluation is deferred
   because its measurement-only slot is outside this ownership; Prometheus service
   rules are active after deployment", `install-plan.json` alerting row notes,
   line 2632; `SOURCES.md:532`) and names the Collector's connectors as the way
   events become Prometheus counters (Loki row notes, line 2385). `otel.yaml` adds
   `journald/clock_offset_check` (`matches: SYSLOG_IDENTIFIER=clock-offset-check`,
   `start_at: beginning`, cursor in `file_storage`), `transform/clock_offset_check`
   (a `level` of ok/warn/crit/other and a closed `reason` vocabulary) and
   `count/clock_offset_check`, exported as
   `clock_offset_check_lines_total{level,reason}`. The lines themselves never
   leave the Collector.
2. **Rules** (`prometheus-alerts.yaml`, group `nativestack2604-clock`): a recording
   rule counts increments and newly born series in the last 10 minutes;
   `EcosystemClockOffsetCritical` (critical) reads its CRIT count,
   `EcosystemClockOffsetWarning` its WARN count, `EcosystemClockOffsetCheckUnparsed`
   a line that is none of the three, and `EcosystemClockOffsetCheckSilent` fires
   when no line has arrived for 15 minutes.
3. **Coverage.** Scrape jobs for Alertmanager (whole) and for Loki and Grafana
   (short `metric_relabel_configs` allowlists); Collector `http_check` targets for
   OmniRoute `/api/health`, Dagu `/api/v1/health`, Ollama `/api/version` (each with
   a warning rule) and agentsview `/api/ping` (observed only: the plan runs it as
   an on-demand daemon). `EcosystemServiceUnavailable` covers the new scrape jobs.
   The http_check exporter retains a successful coded label set for its default
   5-minute expiration when failure produces an uncoded zero; with the 2-minute
   hold, an outage after a healthy response alerts in about 7 minutes, plus
   collection/scrape/evaluation alignment. Missing data from startup waits only
   the hold. This deliberately retains the shared exporter; a qualified dedicated
   health exporter with a shorter expiration overturns this choice if that
   latency fails the operational need.
4. **Disk.** The seven root-filesystem rules of the old template (lines 62-147,
   the five post-incident rules and the two older ones) are ported to
   `system_filesystem_usage_bytes`, with their promtool scenarios.
5. **Alerting integrity.** Upstream mixin rules `AlertmanagerFailedToSendAlerts`
   (warning) and `PrometheusRuleFailures` (critical).
6. **Delivery to the host.** `copy_config` installs `prometheus-alerts.yaml` and
   its tests only when absent, so a changed rule never reached an existing host.
   `observability_config.py alerting` now publishes the pair like
   `prometheus.yaml`: the shipped digests are recognized as the plan's
   (`PRISTINE`), an operator edit is refused and kept, and the new pair's promtool
   unit tests pass in a scratch directory before any live file is replaced.

## Alternatives and why not

| Alternative | Why not here | What would overturn it |
| --- | --- | --- |
| Loki ruler (LogQL alert on the lines) | The plan defers it to the measurement-only Loki slot's owner; the lines would still need a journald path into Loki. | The Loki owner qualifies the ruler on 2604. |
| Unit filter (`units:`) | Misses about 37-39% of the lines (45 of 121; correction #8). | journald keeps unit fields for short-lived runs. |
| `start_at: end` | It passes `--lines=0`, and journalctl then prints nothing after a stored cursor (measured: 0 rows with `--lines=0 --after-cursor`, 5 with `--no-tail`), so lines logged while the Collector is down are lost. | A receiver option that resumes from the cursor without `--no-tail`. |
| A gauge of the last level (`signal_to_metrics`) | A CRIT followed by an OK between two scrapes would be lost; a counter keeps every line. | None foreseen. |
| `increase()` alone | Misses a series' first line; 2604 has no created-timestamp-zero ingestion (PR #723 proposes it in a rendered unit). The rule stays correct with it. | Ingestion enabled on 2604 and the `unless` term shown redundant. |
| Full Loki and Grafana scrapes | About 9,700 more series beside 6,700 under the 512 MB retention size. | A retention or size change that leaves the 7-day window intact. |
| Dagu's native `/api/v1/metrics` | The initial probe reported 401; a repair-time unauthenticated GET returned 200. Authentication and metrics qualification remain with the service owner. | The service owner qualifies the exposed metrics and their scrape cost. |
| An agentsview down alert | The plan runs it on demand (`agentsview daemon start`); a down alert would page whenever it is idle. | agentsview becomes a resident service. |

## Completeness critic

### External vLLM embedding endpoint extension

The CC's 2026-10-06 VLLM-OBSERVABILITY direction adds a scrape of its externally owned
`vllm-embed` runtime at `127.0.0.1:28231/metrics`. Live read-only observation returned vLLM
0.31.0, healthy HTTP responses and an embedding-named model; pinned sources and metric names
are recorded in the install plan's `SOURCES.md`. The plan observes this endpoint without
installing an engine or adding an ownership row. The seven-tool client HOLD is unchanged.

The selected outage owner remains `EcosystemServiceUnavailable`: its existing `up == 0`
condition and two-minute hold already cover the new job, with warning/local-ecosystem labels.
A separate vLLM alert would duplicate that outage. Its dedicated native promtool scenario
checks no firing at 115 seconds, firing at 120 seconds and clearing at 130 seconds. The native
rule engine is the acceptance oracle; synthetic series do not prove live scrape ingestion,
notification delivery or embedding correctness. CC apply/read-back follows GPT review and ACK.
No live vLLM stop/restart, model request, client/configuration change or host apply occurred.

Extension validation used the installed plan-native promtool 3.15.0: rule/config checks returned 0
and `test rules --run=vLLM` returned `SUCCESS`, with one JUnit scenario and zero failures.
It asserts no firing at 115 seconds, firing at 120 seconds and recovery at 130 seconds.
The plan checker retained 84 owners and the 23 bounded committed-file/checker/renderer tests passed.
The attempted whole fixture run hit the analysis tool's 30-second ceiling; no whole-run pass is
claimed by that worker attempt. The resumed parent subsequently completed the
whole native fixture run with `SUCCESS` and exit0 on the extended rule/test files;
the selected vLLM firing/recovery result remains distinct from a live outage.

Generative metric series can be initialized on this embedding server. Their presence does not
qualify generation throughput, TTFT or decode latency. The metric-name surface, scrape health,
actual embedding requests and model-quality acceptance remain separate evidence classes.

Repair critic: lifecycle identity deliberately omits arbitrary matcher and
command text; hook counts therefore group by native lifecycle/status rather
than individual scripts. Real deployed ingestion still needs independent
read-back after apply. Clock delivery, Telegram firing/resolution and the
user's phone confirmation remain host gates. The next scoped sweep must check
upstream event/schema changes against these closed vocabularies and revisit a
qualified dedicated health exporter if the disclosed latency is inadequate.
