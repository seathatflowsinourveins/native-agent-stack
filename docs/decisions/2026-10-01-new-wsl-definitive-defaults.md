# The new WSL's definitive defaults: one default per slot (2026-10-01)

## Decision

Every slot of the new WSL architecture names exactly one default, or says why it has none: two trading slots have no
blind default today, and a slot the two families split on installs nothing until its measurement returns. The clean
install installs the defaults and nothing else. The other finalists of a slot are recorded as alternatives, and the
head-to-head that used to gate the slot is now the default's overturn check: the one comparison, and the result in
it, that would replace the default.

The user asked for this on 2026-10-01 at about 20:35Z, verbatim: "WE NEED DEFINTIVE CONVERGENCED ARCHITECTURE, WITH
EVIDACNE FORM UPSTREAM EVL, NO MORE ONE OF ,OR MISSING LAYERS, A FINALIZED CLEAN ARCHITECTURE, a clean resoluted form
codex convergence , via gpt powered sdks harness frameworks of research etc, deerflow,gptr,openhand and beyond, using
them as they are already harness built , evl the best repos in each layer for our new wsl codex-cc ecosystem".

What a default is, what makes it definitive, and what neither is:

1. Every slot has an install decision: one tool, or the option that installs nothing, chosen blind on the frozen
   criteria, with its alternatives and its overturn check recorded. A first-round row's decision is one blind judge's
   pick that a critic reviewed; the row's label gives that critic's verdict for its layer (upheld, revised or
   undetermined). A decision-round row's is the pick of two deciders in one family.
2. A default is definitive only when both deciders of both model families named it and both critics returned
   converged. That holds for the rows the tables print in bold, and for no first-round row.
3. The blind rounds' evidence class is source review plus the published evaluations it cites. The local model
   server's settlement adds measured local integration checks. A default decided on documented fit says so and
   claims no measured lead.
4. The bar is not the same in both directions for such a default. It did not have to show a measured gain, while a
   challenger replaces it only with one: an interval that excludes zero, plus the slot's gates. Measured against
   measured, the bar is the same both ways (U11 C). An option that installs nothing is the default unless a
   challenger shows such a gain. Where a documented-fit default is also the source host's selection of record, the
   asymmetry may not protect it: its replacement is decided by a symmetric measurement (identical gates, then the
   higher primary score on an interval, then measured secondaries), and the blind round's pick decides only a tie
   that the measurement leaves.
5. None of this is merit acceptance under the U11 design. The full-field re-vote, the measured comparison (U11 C) and
   new-host acceptance stay separate and open, and any of them can replace a default through its overturn check.
6. The comparisons that back or overturn a default run before the clean install, on the current workstation or on a
   throwaway rehearsal distribution. The clean WSL never installs comparison arms.

## What "blind" covered, and what it did not

Covered: the packets carried no adoption labels, pins or receipts of the project's own use, reviewer names were
removed, and the finalists came in two seeded orders. Not covered, as an independent read of this change found:

- **The deciders' environment.** Both families' deciders ran inside the project's own agent environment. The Claude
  deciders' agent definition and the instruction block injected into every subagent name tools the source host has
  installed, ai-memory and SocratiCode among them. The GPT units ran with the user configuration ignored, yet their
  logs show the project's command prefix and its review-routing wording, which the project's Codex instruction
  template carries beside the same tool names; whether that template was loaded was not verified. A decider could
  therefore tell what the source host uses.
- **Hints inside two packets.** The code-search packet's only comparison on record is the project's own SocratiCode
  run. The memory packet's first-round notes call ai-memory the "provisional owner candidate" and the others
  "challenger finalists", and its second-reviewer notes kept routing wording (see the artifact's README).
- **Tool parity.** The GPT units had shell network access but no page fetching. Facts hosted outside GitHub could not
  be re-read on that side. The practice this record's own anti-pattern row asks for, a rerun of the degraded units,
  has not been applied to the decision round yet; it is requested for the units whose critics list an unverified
  deciding fact.

What follows from it: where a family picked the source host's incumbent (ai-memory by both families, SocratiCode by
the GPT family, rootless Docker by both), incumbency cannot be ruled out as an influence. Memory and code search are
now decided by a measurement, and the engine carries a requested re-decision. The trading lane checked its own rows the
same way and flags, per row, whether a default coincides with its record. The foundation rows do not carry that flag
yet; their coincidences are the three named here. The round is blind to the packets'
adoption labels, not to the environment, and later rounds run their judges outside the project's agent environment.
