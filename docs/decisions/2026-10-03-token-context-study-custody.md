## Protocol and acceptance boundaries

Before freeze, bind exact tasks, answer keys, corpus bytes, candidate release/bundle bytes, client/model/effort, native invocation, tool availability, fixed AB/BA schedule and statistical gates. Calibrate native counters and A/A behavior first. Preserve native provider caches; disable only benchmark response replay. Do not alter accounts, native sign-ins, global permission policy, gateways or peer configuration to manufacture an uncontaminated arm.

Read the actual model-visible instruction/tool input for both arms. `--ignore-user-config` alone is not evidence that global Codex instructions disappeared. Claude SDK settings default to no settings sources, which is not proof of native CLI parity. Keep identical baseline context except for the declared treatment. Use upstream native test commands and existing harness formats; distinguish upstream tests, local integration tasks and synthetic fidelity controls.

Count returned payloads, primers, hints, retries and recovery with `gpt-tokenizer` 4.0.0 / `o200k_base`, separately from exact native request/trajectory usage. The maintained `tools/token-report/token_manifest.py:159` requires that exact package version; older dated 3.4.0 artifacts retain their original scope. For Claude, ordinary input, cache creation, cache read and output are distinct; thinking is inside output. For Codex, cached input, cache-write input and reasoning are subsets. Do not sum cumulative turn snapshots, replayed history, root aggregates and included children, global/project reports or artifact reductions. Preserve unknown cost as unknown; list-price estimates and subscription spend differ.

The native [Codex response-completion type](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/protocol/src/protocol.rs#L1929) describes one exact upstream response, with optional usage; a type declaration does not prove local capture. The native [exec conversion](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/exec/src/event_processor_with_jsonl_output.rs#L118) derives `turn.completed` usage from the last thread total. Calibrate actual response records and identity linkage rather than summing those snapshots. Released ccusage's [parser](https://github.com/ccusage/ccusage/blob/d9821088b98aa536c7a385aa1a4579d6fa02269b/rust/adapters/codex/src/parser.rs) and [current main parser](https://github.com/ccusage/ccusage/blob/8e08b6acf8f066d814387a34c66655e42ee8e0ef/rust/adapters/codex/src/parser.rs) differ on response-ID/compaction records. This is a qualification gap for the released comparator, not permission to promote main or fabricate historical counters.

Require exact critical-fact/exit/recovery fidelity, quality gates fixed before trials, and a negative control that fails the same check. A protection verdict requires observed long-session context/compaction and retained constraints; a short output cannot prove it. A saving verdict requires complete trajectory counters at accepted quality. Invoke-rate denominators distinguish eligible main/child opportunities, actual attempts, useful successes and deliberate bypasses. Show both clients and delegated children in fresh native sessions before installing a winner through its supported native CLI.

No comparative run or host candidate activation has started. Source preparation can proceed while architecture binds the exclusive target/pool window and read-only retrieval corpus revision. Only winners become active defaults; temporary upstream test artifacts do not become host profile changes.
