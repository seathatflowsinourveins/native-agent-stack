# Decision: AN-13's M4 and M5 after the two-family lanes (2026-09-28)

**Decision practice (2026-09-28):** apply instruction edits only after the declared two-family evidence procedure, using
the [Anthropic prompt-audit rubric at 33375500](https://github.com/anthropics/skills/blob/33375500bcea98d610eb30ce10ac4e59b89c390d/skills/claude-api/shared/prompt-audit.md) and [behavioral validation guidance](https://code.claude.com/docs/en/best-practices).
The local convergence rule remains [`2026-09-27-prompt-audit-resolution.md:54-60`](2026-09-27-prompt-audit-resolution.md), "Rule":
- both lanes agree: apply;
- both reject: keep;
- otherwise, one blind adjudication in both orders by both families;
- a text is applied only when all four adjudications choose it. Otherwise the lines stay unchanged and both positions
  are recorded, because a split stays pending.

A judgment that the audit voids does not count. That rule is not in those lines: it comes from the lane-A template's
outcome actions, where only four valid judgments apply a text
([`outcome-actions.md:9-12`](../../evidence/artifacts/prompt-audit-20260927/lane-a/final/adjudication/outcome-actions.md)),
and from the convergence tool, which voids a flagged judgment
([`tools/sota-convergence/README.md:1503-1505`](../../tools/sota-convergence/README.md)).

AN-13 is the operator's headless `/doctor prompt-audit` run over this repository. #444 records it in
`evidence/artifacts/prompt-audit-20260927/an13/`, which is not on `main` until #444 merges. It also gives the
dispositions of the run's findings M1-M5:
- M1-M3 are left to the operator. M2 and M3 concern the user-level instruction file, and M1 follows M2.
- M4 and M5 were single-family findings that needed a second-family lane before any edit. This record gives them
  that lane. For M4, #444 also asks for the native before-and-after comparison the report describes.

The frozen packet quotes the finding texts and the report's proposed rewrites verbatim. The evidence is in
[`evidence/artifacts/prompt-audit-an13-m45-20260928/`](../../evidence/artifacts/prompt-audit-an13-m45-20260928/).

The adjudicators were blind to authorship. They split on whether to keep the installer sentence:

Both valid GPT-6 judgments chose the text in position B. So the two GPT-6 judgments disagree only across presentation
orders, and show no stable preference. No judgment chose to keep the current lines.

## Method

1. **Packet.** One packet was frozen at `9f8db582` (`round1/packet.md`, sha256 `0feb54e2…`). It holds:
   - the report's finding texts and rewrites, verbatim;
   - excerpts with `git blame`;
   - the constraints on each edit;
   - 13 dated sources: ten from the prompt audit's first round, plus U1 (the pinned upstream skill), U2 (upstream's
     commit `3be5aad3`) and U3 (the Opus 5 guide on over-verification). For U1, the coordinator checked the hash
     against the manifest and the installed copy.
2. **Round 1.** Two independent lanes judged the same packet, and neither saw the other's return:
   - **GPT-6:** the packaged runner (`tools/sota-convergence/landscape-sweep/codex_call.sh`: codex-cli 0.157.1,
     `gpt-6-astra`, effort `max`, read-only, live web search), after a passing probe.
   - **Claude:** one `evidence-reviewer` on Opus 5.5. Its role has no web tool, and its brief said it had no shell or
     web access. Its transcript shows only Read, Glob, Grep and one advisor call (`tool-counts.json`).
3. **Adjudication.** M5 split, so it got one blind round:
   - **The inputs.** Each input holds the current lines, the two texts as Return A and Return B, the question, the
     choices and the rules. It carries neither lane's reasons nor its sources.
   - **The shared packet.** It holds M5's section of the round-1 packet, a one-sentence round-1 summary, sources S1
     and S10, and six repository paths.
   - **The order.** Which lane is Return A in the A/B order was drawn with `secrets.choice` and withheld from the
     judges.
   - **The judges.** Each family judged both orders: two runner jobs and two `blind-adjudicator` agents. The judges
     read a plain export of `main` at `9f8db582`. The two Claude judges also used only Read, Glob, Grep and one
     advisor call each.
   - **Isolation.** Before dispatch, the base worktree the lanes had read was removed. The work directory holding
     the identified returns was moved from the scratch directory's top level into a holding directory. The audit
     voids any access to either (`scripts/isolation.log`).
4. **Audit.**
   - The void patterns, the audit script and the adjudication builder were hashed into `scripts/frozen-sha256.txt`
     before dispatch.
   - The package keeps no timestamped record of that step. The file's modification time on this host, 14:21:23Z,
     is before the GPT-6 judges started at 14:21:39Z (runner records), but it is not a receipt.
   - What the files do show: the audit records the patterns' hash, which equals the frozen one, and `sha256sum -c`
     passes on the published scripts.
   - The audit was adapted from X9 round 3's audit in #444, not from the lane-A template that the anti-pattern log
     names. See Checks.

## Checks

- `sha256sum -c packet.sha256`, run in `round1/`, passes on the published packet.
- **The adjudication builder's checks.**
  - Both orders carry the same evidence: identical packets, and inputs equal after swapping A and B.
  - It found none of its leak words, which are model ids and lane attributions, and no host paths in the inputs and
    packets.
  - The packets do quote source S1 ("Claude responds well…") and name OpenAI's guide.
- **The audit** (`adjudication/audit-m45.json`):
  - The two GPT-6 judgments are clean.
  - Both Claude judgments are void. Each has four hits of the MAPPING pattern, from two of its alternatives, and all
    are false positives. `adjudication/audit-m45-windows.json` gives each hit's window:
    - the family-attribution alternative matched "Codex lane", twice, in the adjudicator's own agent definition,
      which gives "the Codex lane" as an example of a leak;
    - the alternative for the first-round Claude lane's agent type matched `evidence-reviewer` in one Glob result,
      once in its text and once in its structured form. The result listed
      `<adj>/root/.claude/agents/evidence-reviewer.md`, a file of the export.
  - None of the hits says which lane wrote which text.
- **A reproduction after the fact** (`adjudication/audit-control-m45.json`, from `audit_control_m45.py`) ran after
  the judges:
  - The unchanged copies reproduce the published audit.
  - One planted access per judgment adds its own hit in all four copies, and all four planted copies are void.
  - It has no criterion that real runs stay clean. So it passes while both Claude copies are void, and it cannot
    catch this round's false positives. It is not the pre-dispatch control.
- **This round broke the log's rule and skipped its template.**
  - The rule, "Proving a judge audit's void patterns on synthetic cases only", names the lane-A template
    (`evidence/artifacts/prompt-audit-20260927/lane-a/final/adjudication/`).
  - That template already covers both false positives:
    - family-attribution phrases apply only to context the judge did not fetch, and the judge's own definition is
      exempt (`void_patterns_final.py`, `audit_final.py:89`);
    - its self-test requires both kinds of payload to come back clean (`audit_selftest_final.py:131`, `:136-138`);
    - its root scan fails on any exported file whose name or text matches MAPPING (`root_scan_final.py`).
  - This round adapted X9 round 3's audit instead, and ran none of these checks before dispatch.
  - A reproduction afterwards applied both checks to this round's audit and patterns, without running the
    template's own scripts (`adjudication/template-checks-m45.json`, from `reproduce_template_checks_m45.py`). Both
    fail:
    - the self-test's two payloads, run through this round's audit, come back void;
    - a scan of the export like the root scan, with this round's MAPPING, matches 8 paths and the text of 242 of the
      8,223 files at `9f8db582`.
  - The anti-pattern log records this as a new row.
- **The outcome does not depend on the voids.** The two valid GPT-6 judgments chose different texts, so no text can
  have four votes. Had the Claude judgments been valid, the Claude lane's text would have had three of four, and the
  rule still applies no text on three.

## Alternatives considered

- **M4, apply D1-D3 locally.** Rejected:
  - it breaks the pin, and a skills update would reinstall the pinned file over it;
  - upstream deliberately kept those parts;
  - it changes the second client and every project;
  - it changes the scheduled comparison's treatment arm.
- **M4, drop the preload or end the trial now.** Deferred to the scheduled 2026-10-25 comparison, which decides it on
  tokens, elapsed time and review-found defects. The deferral does not answer the trial's immediate-removal rule;
  see Limitations.
- **M5, hunk E.** Rejected by both lanes because it credits the installer to the wrong owner.
- **M5, a new adjudication round now.** Not run. The rule allows one adjudication round. A new round would need the
  lane-A template's checks to pass before dispatch, and a corrected packet (see Limitations).

## Limitations and residuals

- **M5 stays pending.** Its lines are unchanged and both texts are recorded.
- **M4's lanes did not test the trial's immediate-removal rule.**
  - The skills trial removes a trial skill at once if it "gives instructions that conflict with CLAUDE.md/AGENTS.md
    once actually read in full" (`2026-09-25-skills-trial-and-usage.md:284-286`).
  - The packet did not include that rule, and neither return mentions it. The packet quotes the skill's gate lines
    only as lines that hunk D1 deletes.
  - One candidate conflict was raised after this round: the skill's "If you haven't run the verification
    command in this message, you cannot claim it passes" against `AGENTS.md:16`, "Reuse passing evidence when its
    inputs still match".
  - This record does not decide that question. Its M4 result covers the report's rewrite only.
- **The adjudication packet stated a wrong premise.**
  - Its round-1 summary told all four judges that `receipt.json:88` credits the installer to project-readiness. The
    receipt names only the validator.
  - The premise favours the text that keeps the installer sentence.
  - The Claude B/A judgment repeated it. The Claude A/B judgment read the receipt correctly, as a record of the
    validator and not of the installer.
  - A new round's packet must drop it.
  - This round's outcome is unaffected: the two valid judgments split either way.
- **No behavior was measured** for either text or for the skill's wording. The decisions rest on sources, pins and
  tests.
- **The lanes had different access.** The Claude lane had no web tool and relied on the packet's sources. The GPT-6
  lane searched the web.
- **The report is not published.** #444's AN-13 package keeps only its result records, so this record cannot link the
  report text. The packet quotes the two findings verbatim.
