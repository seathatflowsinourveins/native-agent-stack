**M4.** The report proposed rewriting the skill's pressure wording (M4a, hunks D1 and D2) and its "ALWAYS before"
trigger list (M4b, hunk D3). Both lanes rejected that edit. They share three reasons:
- **The pin.** The skill is vendored and pinned by ref, tree and `skill_md_sha256` in
  [`adoption/skills/manifest.json`](../../adoption/skills/manifest.json).
  - Both lanes checked that the installed copy and the upstream file at the pin have the manifest's hash
    (`2befe7fc…`).
  - The packet's first source records that upstream `main` serves the same blob on 2026-09-28, so there is no newer
    revision to re-pin to.
- **Upstream's own choice.** Upstream's latest change to this file, `3be5aad3` (2026-07-24), dropped the "persuasion
  sections". It kept the Iron Law, the gate function and the rationalization table: "This is the eval-gated class: the
  bet is that discipline holds without the persuasion prose — evals on this branch decide". Hunks D1 and D2 replace
  those kept parts with shorter text. The GPT-6 lane notes that D1's replacement still requires fresh full-command
  verification, and that the sources do not show the rewrite helps either client.
- **The reviewed preload.** The project-side alternative, dropping the builder's preload or ending the trial, would
  change a reviewed, test-pinned contract:
  - [`test-envelope.mjs:505`](../../examples/claude-native/workflows/test-envelope.mjs) and
    [`test-contract-mutations.mjs:70-73`](../../examples/claude-native/workflows/test-contract-mutations.mjs) pin it;
  - all three copies of `isolated-builder.md` carry it.

The Claude lane added the following:

    exits 1.
  - `tools/adoption/install_skills.py:127` would reinstall the pinned upstream folder over the edit.
- **The edit reaches beyond this repository.**
  - The user-level path resolves to the shared skills folder (`skills_status.py:12`).
  - The manifest enables the skill for Codex, so the edit would change the second client and every project.
- **The project-side alternative is already scheduled.** The skills trial's 2026-10-25 review adds "a with/without

## Method

1. **Packet.** One packet was frozen at `9f8db582` (`round1/packet.md`, sha256 `0feb54e2…`). It holds:
   - the report's finding texts and rewrites, verbatim;
   - excerpts with `git blame`;
   - the constraints on each edit;
   - 13 dated sources: ten from the prompt audit's first round, plus U1 (the pinned upstream skill, its hash checked
     against the manifest and the installed copy), U2 (upstream's commit `3be5aad3`) and U3 (the Opus 5 guide on
     over-verification).
2. **Round 1.** Two independent lanes judged the same packet, and neither saw the other's return:
   - **GPT-6:** the packaged runner (`tools/sota-convergence/landscape-sweep/codex_call.sh`: codex-cli 0.157.1,
     `gpt-6-astra`, effort `max`, read-only, live web search), after a passing probe.
   - **Claude:** one `evidence-reviewer` on Opus 5.5, with no web access.
3. **Adjudication.** M5 split, so it got one blind round:
   - The inputs hold two returns, Return A and Return B, with only their texts, reasons and sources. Which lane is
     Return A in the A/B order was drawn with `secrets.choice` and withheld from the judges.
   - Each family judged both orders: two runner jobs and two `blind-adjudicator` agents.
   - The judges read a plain export of `main` at `9f8db582`.
   - Before dispatch, the base worktree the lanes had read was removed. The work directory holding the identified
     returns was moved from the scratch directory's top level into a holding directory. The audit voids any access
     to either (`scripts/isolation.log`).
4. **Audit.** The void patterns, the audit script and the adjudication builder were hashed at 14:21:23Z
   (`scripts/frozen-sha256.txt`), before the GPT-6 judges started at 14:21:39Z. The audit records the patterns'
   hash, and `sha256sum -c` still passes on the published scripts.

## Checks

- `sha256sum -c round1/packet.sha256` passes on the published packet.
- The adjudication builder checked that both orders carry the same evidence: identical packets, and inputs equal
  after swapping A and B. It found no model names or host paths in the inputs and packets.
- **The audit** (`adjudication/audit-m45.json`):
  - The two GPT-6 judgments are clean.
  - Both Claude judgments are void. Each has four hits from two patterns, and all are false positives:
    - the family-attribution pattern matched "Codex lane" twice in the adjudicator's own agent definition, which
      names that phrase as an example of a leak;
    - the pattern for the first-round Claude lane's agent type matched `evidence-reviewer` twice in one tool result
      that listed `root/.claude/agents/evidence-reviewer.md`, a file of the export.
  - None of the hits says which lane wrote which text.
- **The audit's control** (`adjudication/audit-control-m45.json`) ran after the judges:
  - The unchanged copies reproduce the published audit.
  - One planted access per judgment adds its own hit in all four, and all four planted copies are void.
  - On the two valid GPT-6 judgments, that shows the audit can fire. On the Claude judgments, the verdict could not
    change, because the unchanged copies are already void.
- **This round broke a rule already in the log.** The rule is to dispatch only after the void patterns pass this
  control on real runs as well as synthetic cases (`docs/harness-defaults.md`, "Proving a judge audit's void patterns
  on synthetic cases only"). The anti-pattern log records this as a new row.
- **The outcome does not depend on the voids.** The two valid GPT-6 judgments chose different texts, so no text can
  have four votes. Had the Claude judgments been valid, the Claude lane's text would have had three of four, and the
  rule still applies no text on three.

## Alternatives considered

- **M4, apply D1-D3 locally.** Rejected:
  - it breaks the pin, and a skills update would reinstall the pinned file over it;
  - upstream deliberately kept those parts;
  - it changes the second client and every project;
  - it changes the scheduled comparison's treatment arm.
- **M4, drop the preload or end the trial now.** Deferred to the scheduled 2026-10-25 comparison, which decides it on
  tokens, elapsed time and review-found defects.
- **M5, hunk E.** Rejected by both lanes because it credits the installer to the wrong owner.
- **M5, a new adjudication round now.** Not run. The rule allows one adjudication round, and a new round would need
  void patterns that pass the control before dispatch.

## Comparison that would overturn it

- **M4:**
  - The 2026-10-25 comparison finds that the preload adds tokens or elapsed time without reducing review-found
    defects on the builder. Then drop or replace it in every builder copy, together with the tests, the bootstrap note
    and the #381 table.
  - Or upstream revises these sections. Then re-pin.
- **M5:**
  - A new round whose void patterns pass the control before dispatch, and whose four valid judgments choose one text.
  - Or matched child runs in that directory show the current lines leading to edits of the enclosing root's guidance
    or actions.
