## Corrections and failed conditions

- The documented chatgpt.com installer redirect returned HTTP403 to a read-only fetch. The failed attempt is retained privately; the tagged README's supported direct release route and tagged extraction routine supplied the stage.
- The standalone installer has no supported stage-only defer switch. Its deferred-selection mode requires daemon-only scope, and its complete standalone flow changes selection. `CODEX_NON_INTERACTIVE` does not prevent those changes. Only the publisher archive and native extraction were used.
- The initial concern that hcom's login-shell reconstruction necessarily defeats caller PATH was overturned by [b2a7c192 terminal.rs:521](https://github.com/aannoo/hcom/blob/b2a7c192/src/terminal.rs#L521) and [launcher.rs:1188](https://github.com/aannoo/hcom/blob/b2a7c192/src/launcher.rs#L1188): the runner receives an already resolved absolute tool path. This is source evidence; actual canary selection still needs a native runner-path receipt.
- Dagu's schema allowed a root `name` property, but native 2.18.2 validation returned `entrypoint document must not define name`. The proposal now takes entrypoint identity from its filename. No service authentication configuration was changed to address the isolated CLI's default-auth warning.
- Publication validation rejected local native turn identifiers in the public receipt. Exact locators remain in the private evidence; the public receipt uses bounded turn scopes and native timestamps. Metadata still follows the repository's publication privacy rules even when it contains no conversation content.
- Independent source review found stale approvals, cross-run rollback custody, resource binding, evidence containment, foreign-launcher custody, protected restoration and missing execution bounds. The draft now seals current-run evidence, shares verified package provenance, isolates rollback state, binds full archive resources/modes/links, resolves receipt paths, renders the authenticated backup under the proposed shared lock, guards restoration and bounds native execution. These are integration fixes supported by synthetic tests; they do not substitute for a live canary.

## Completeness critic and limits

The independent critic identified the complete package/checksum scope and the full-changelog compatibility leads omitted from the headline release notes. Its landscape comparison included native Codex update, native package-manager updates, Dagu/systemd orchestration, GitHub CLI and Renovate's maintained release-PR class. Native updater activation supplies no protected two-lane gate; Renovate remains an uninstalled release-pin PR candidate. No hand-built model runner or vendor fork was introduced.

Keep checksum identity, native version/preservation results, local integration fixtures, source review, real lane acceptance and installed timer execution distinct. No cross-provider improvement, automatic adoption, scheduler execution or general architecture convergence is claimed. The two current native canaries qualify this staged release; co-op adapter implementation/acceptance, cooperating selector lock ownership and explicit unit review/installation remain required before this proposal becomes standing host automation. Existing automatic_model_calls policy and native client profiles are not changed by this draft. A maintained upstream that directly ships this scoped protected canary/selection lifecycle would replace the local glue after source and native acceptance agree.
