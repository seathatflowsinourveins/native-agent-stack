These contracts describe a clean intended division, not an already non-overlapping deployment. Context-mode's native timeline instructions and ai-memory's prior-work instructions both advertise historical recall. No supported switch removing that overlap while retaining output processing was established. Native model-choice evidence and a source-native routing repair must settle that boundary [C2, A1].

Exact symbol references, conceptual code search, code graphs, syntax-pattern search and scoped Markdown retrieval stay with their owning lanes. A token tool processing their returned artifact does not acquire their indexing or search job. Their per-client owner decisions must be joined from those lanes rather than selected again here.

Automatic hook firings measure participation separately from model selection. ## Exclusion gates and contested comparison

No exclusion passes. Headroom in each client is an overlap watch candidate against context-mode/native selected-text handling; RTK on Codex has a native-only integration gap to resolve; context-mode on Claude cannot be excluded from its accepted zero. ai-memory remains a memory-lane question. Unique functionality must not be excluded by an overlapping subtask.

For each client, exclusion requires all three: never selected unprompted in the **complete native run**, another selected slot provides equivalent task-class coverage, and one upstream-native routing fix plus matched rerun does not change the result. An unavailable slot has an exposure defect; a selected-but-failed request has an execution defect. Neither is a “never selected” routing result. A unique never-selected slot is NOT-READY after its fix round.

Every exclusion must be overturned by a later organic selection, regression of the chosen equivalent, or an upstream-harness A/B favoring the excluded tool on that contract.

Proposed comparison: use the existing pinned promptfoo 0.123.1 workflow, or Inspect for full agent trajectories. Compare native handling, context-mode and Headroom separately on (a) parsing/aggregation and (b) overview plus exact recovery, then compare context-mode timeline with ai-memory for historical recall. Use the same unseen artifacts, fresh isolated native sessions, unnamed outcome prompts, tool-native surface hashes and valid indexes/scopes. Grade correctness, material omissions, requested quote recovery and recovery after context pressure before comparing elapsed time and complete provider usage. Record exposure, attempted selection, completed use, meaningful contribution and automatic hook participation separately. Preserve failed attempts and unknown usage. F9 owns routing changes; the pilot owner owns execution and adjudication. No new custom runner is authorized by this proposal.

## Completeness critic and overturn

The independent critic required distinct search contracts, actual-choice telemetry, output fidelity controls and automatic-hook accounting. Its schema-overhead finding fed a source sweep of native deferral versus MCP-compressor; native clients remain the source-fit first owner, and host exposure must be measured. The next sweep must cover direct MCP responses, fetched HTML, structured tables/logs, large single records, repeated reads, schema-description overhead, post-compaction recovery and durable-history contamination. A release or source showing a better native routing surface reopens that surface review; a quality-passing native-arm comparison overturns a provisional owner. A grade, source review or artifact-token reduction alone cannot declare the whole stack non-overlapping or READY.
