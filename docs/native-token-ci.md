# Native token-tool fixtures in GitHub Actions

The [Linux workflow](../.github/workflows/native-token-e2e.yml) installs and invokes upstream tools against disposable public inputs: the original four below (RTK, QMD, Repomix, TOON), plus MarkItDown, ast-grep, ccusage, codebase-memory-mcp, Headroom and jCodeMunch, added 2026-09-26 and described in [the token-efficiency stack's hosted-CI section](token-efficiency-stack.md#hosted-ci-coverage-2026-09-26) rather than in the table below. This adds fresh CLI behavior checks to the existing repository-integrity and token-report tests. It does not start Codex/Claude, read account stores, call a provider, run an LLM or embedding model, or require a GPU. Two runtime details are part of the lane: MarkItDown's `magika` dependency bundles a file-type classifier (a 3,163,737-byte ONNX model in the magika 0.6.3 wheel) that MarkItDown runs on the CPU for every conversion, and Headroom's token counter downloads tiktoken's `o200k_base` vocabulary into the run's `TMPDIR` on first use. It runs for relevant pull requests/pushes and manual dispatch; publication of the workflow does not itself prove a hosted run passed.

Each fixture runs the pinned tool's own CLI or MCP commands (upstream native operations), and this repository's checks decide pass or fail on what they return. The receipt therefore labels itself `local_integration`: local integration evidence of upstream native operations, not an upstream test suite. The one upstream test is `rtk verify --require-all`, which runs the inline tests of RTK's built-in filters, compiled into its release binary. No other pinned tool documents an offline self-test command ([the run record](../evidence/artifacts/native-token-ci-extension-20260926/README.md) lists what was checked). Upstream test-suite qualification of a component belongs in its per-host receipts under `evidence/hosts/<host>/`, recorded with `scripts/host_receipts.py` and summarized in [the component evidence matrix](component-evidence-matrix.md); the receipts recorded so far for these tools run install and use commands, not upstream suites.

| QMD 2.8.3 | `npm install --global --prefix "$PREFIX" @tobilu/qmd@2.8.3` | Named BM25 collection, search/get with exact source body inside the pinned output framing, update and retrieval from fresh CLI processes, then owned collection removal |
| Repomix 1.18.1 | `npm install --global --prefix "$PREFIX" repomix@1.18.1` | Explicit two-file XML contains the complete original source and no extra file; separate compressed pack retains structure, without claiming complete implementation fidelity |
| TOON 4.1.1 | `npm install --global --prefix "$PREFIX" @toon-format/cli@4.1.1` | Encode/statistics, strict decode with equal JSON values/types, and a rejected truncated array |

The [harness](../scripts/native_token_ci.py) checks these versions against [the manifest](../manifests/stack.json). Pins and installer methods come from [native recipes](../recipes/README.md). Node 24 is supplied by SHA-pinned `actions/setup-node`; checkout and upload Actions are also SHA-pinned, checkout retains no credentials, and workflow permissions are `contents: read`. Package-manager caches are disabled across jobs. npm dependency ranges, and the PyPI dependencies of the `uv tool install` packages (MarkItDown, Headroom and jCodeMunch), can resolve differently in later fresh installs: there is no lockfile and no pinned dependency hash. The receipt retains installed top-level metadata (`npm list`, `uv tool list`) and does not claim a transitive lock. The uv archive is the only download checked against a hash pinned in the harness; the RTK and codebase-memory-mcp archives are checked against their publishers' `checksums.txt`.

The QMD BM25 lane sets the dependency's supported `NODE_LLAMA_CPP_SKIP_DOWNLOAD=true` during installation to skip node-llama-cpp's native build/download hook. Other necessary npm dependency scripts remain enabled. The runtime only uses lexical/document commands, never `query`, `embed`, `pull` or vector search. `QMD_FORCE_CPU=1` alone would not prevent model-enabled operations.

RTK uses `RTK_DB_PATH`, fresh XDG configuration and `RTK_TELEMETRY_DISABLED=1`. QMD has a named index plus explicit `INDEX_PATH`, `QMD_CONFIG_DIR` and `XDG_CACHE_HOME`. Repomix uses an explicit empty configuration and selected files. Child environments exclude inherited provider credentials, routing and tool-state overrides; native `HOME` is preserved. npm receives empty owned user/global config files, and `curl --disable` skips the default curl configuration. No hooks or global client defaults are installed.

The tools added on 2026-09-26 keep their state in the run's owned temporary directory through each tool's documented settings. codebase-memory-mcp gets `CBM_CACHE_DIR` and `CBM_RUNTIME_DIR` for its settings, indexes, logs and daemon rendezvous, instead of the account-wide `~/.cache/codebase-memory-mcp` and `/tmp/cbm-daemon-<uid>` ([configuration reference](https://github.com/DeusData/codebase-memory-mcp/blob/v0.11.0/docs/CONFIGURATION.md)). Headroom gets `HEADROOM_WORKSPACE_DIR` and `HEADROOM_CONFIG_DIR` with `HEADROOM_OFFLINE=1` and `DO_NOT_TRACK=1` ([paths](https://github.com/headroomlabs-ai/headroom/blob/v0.37.0/headroom/paths.py)). jCodeMunch gets `CODE_INDEX_PATH`, with `share_savings: false` in that directory's `config.jsonc`. MCPorter reads only an explicit `--config` file whose `imports: []` turns off its editor and client config imports, and it has its own `MCPORTER_DAEMON_DIR` ([config](https://github.com/openclaw/mcporter/blob/v0.14.1/docs/config.md), [daemon](https://github.com/openclaw/mcporter/blob/v0.14.1/docs/daemon.md)). uv installs into `UV_TOOL_DIR` and `UV_TOOL_BIN_DIR`, and ccusage reads a committed synthetic usage log through `CLAUDE_CONFIG_DIR`. jCodeMunch 1.108.319 still creates `~/.code-index`, and some of its savings and performance helpers ([token tracker](https://github.com/jgravelle/jcodemunch-mcp/blob/v1.108.319/src/jcodemunch_mcp/storage/token_tracker.py)) default to it, whatever `CODE_INDEX_PATH` says, so its MCP server alone runs with a `HOME` inside the run. These are settings, not an operating-system sandbox: the receipt's `state_observations` lists what each tool wrote under its redirected directories, and nothing checks other paths.

With `--install`, every measured tool runs from the absolute path of the copy just installed, including the Headroom and jCodeMunch MCP servers that MCPorter starts. `UV_TOOL_BIN_DIR` is not on `PATH`, so a bare server name would fail on a fresh runner or run an unverified copy already on a workstation's `PATH`. Only plumbing (Git, grep, curl, `sha256sum`, tar, npm and the Node runtime of npm-installed tools) comes from `PATH`. Headroom compresses a compact JSON array of 24 records, the input its SmartCrusher handles, and must report fewer tokens, a changed text and a SmartCrusher route, then return the original exactly from a new server process; a 49-token note below `compress()`'s 250-token minimum must come back unchanged. jCodeMunch's recovered source is compared with a frozen oracle (identity, bounds and complete text), never with the bounds its response reports. The [local runs of 2026-09-26](../evidence/artifacts/native-token-ci-extension-20260926/README.md) record failing controls for the absolute server paths, the RTK upstream tests (a trusted project filter with a failing inline test), the Headroom and jCodeMunch state checks, Headroom compression (disabled through `compress()`'s documented `optimize=False` passthrough), and the ccusage and MarkItDown checks. The codebase-memory-mcp state checks have no recorded failing control yet.

## Run a bounded check locally

From the checkout, with matching installed tools on PATH and a **new** result path outside Git:

```sh
python3 -m unittest tests.test_native_token_ci -v
python3 scripts/native_token_ci.py --output /absolute/private/new-native-ci-results
```

This reuses the native executables already on `PATH` and creates fresh fixture state. To exercise the clean upstream installation path too, add `--install`; downloads and npm installations use temporary owned prefixes. Each output directory is exclusive and is never silently replaced.

The script captures every started command's sanitized argv, stdout, stderr, exit, elapsed time and pre-sanitization byte hashes in `receipt.json`. It retains selected public artifacts, fixture/harness source hashes and the scoped environment settings. Expected nonzero Git, TOON and ast-grep results remain present and distinct from unexpected failures. A timeout terminates only that command's owned process group and preserves the failure. Temporary tools, fixture Git repository, QMD/RTK databases and caches are removed in the final cleanup path; retained evidence survives. Interrupted/incomplete execution cannot produce a passing receipt. Cancellation or runner loss may prevent cleanup/report completion, which is not a passing lifecycle result.

GitHub uploads only the sanitized result directory for 14 days, including a failed run's available receipt. It never uploads installation prefixes, home directories or authentication stores. Local paths are replaced with scope markers; raw hashes identify pre-sanitization output bytes. Full terminal streams are retained within this fixture scope, not native user conversations.

RTK's returned counters are local estimates. QMD has no savings counter; Repomix/TOON token reports describe representations. Neither this job nor a smaller fixture output proves reduced provider billing. Follow [the session handbook](token-session-handbook.md) for native adoption and [the lifecycle guide](../adoption/lifecycle.md) for stateful service/new-PC acceptance.
