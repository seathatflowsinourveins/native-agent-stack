# Foundation selection notes — September 21, 2026

[The comparison manifest](../catalogs/landscape/foundation.json) covers all 16
layers of the current [foundation catalog](../catalogs/foundation/manifest.json).
It reconciles existing pinned source reviews and retained native results from
base `fb04bf702ea67b14163405f0ebe132e393ebbd8a`. It makes no new installation,
model call, repository-performance trial or universal best-in-field claim.

Each layer states its requirement, retained choice, why alternatives do not
currently displace it, actual evidence limits, and the comparison that would
reopen the decision. `selected` means retained for the stated role, including
on-demand tools; it does not activate every tool in every task. `conditional`
and `unqualified` do not mean failed. No alternative is labeled an observed
failure without a retained failing operation.

The strongest direct comparison is the [QMD diagnostic](../evidence/artifacts/foundation-rd-20260921/qmd-comparison.json):
BM25 and hybrid had equal recall@3/5 on 12 queries, at reported average latency
of 5 ms and 10,328 ms. The incomplete corpus seal and single ordered run limit
this to a reason to keep the present default pending a representative repeated
comparison. Worktrunk's native old/new child-directory check supports its
specific upgrade. Most other choices combine native task acceptance with
requirement fit, rather than matched cross-repository performance trials.

Counterexamples stay visible: the earlier fixed-order provider comparison
reported Codex usage 11.26% lower and Claude 25.83% higher, with uncontrolled
cache/plugin conditions; TOON loses to compact JSON on the full catalog;
Context Hub's retained artifact grew by 85 tokens. The [community-practice
record](../catalogs/foundation/community-practice-20260920.json) has null measured
quality improvement and provider-cost change. None supports universal savings.

No retained evidence justifies changing an installed default in this
reconciliation. SDK/durable-worker frameworks, richer memory systems, alternate
RAG stores, broader deployment platforms and extra telemetry stacks remain
conditional or keep-but-compare where their distinct capabilities could answer
a future requirement. The [acceptance evidence policy](acceptance-evidence-policy.md)
continues to separate source review, native execution, synthetic fixtures and
measured improvement. A new PC must execute its selected adoption profile and
collect its own host evidence.

  runtime acceptance; their evidence levels remain distinct.
- `open_gates: []` is not universal lifecycle acceptance: the foundation decision
  array still contains partial and source-review scopes, and new-host,
  hard-crash, provider-cancellation and external-effect limits remain explicit.

comparison artifacts. Worker model/effort: inherited; provider usage unavailable.

repository membership and every local evidence reference. Those checks prove
artifact consistency, not new native execution or superiority.
