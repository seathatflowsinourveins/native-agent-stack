# Coverage audit: what the selection establishes

Checked September 19, 2026 against a fresh authenticated GitHub star listing, the published manifests, prior research records and a bounded new primary-source search.

The repository is a reviewed, evidence-backed selection for the chosen native coding workflow. The word "finalized" must not imply exhaustive evaluation of everything starred or a proven universal SOTA result. Successful upstream execution establishes that a path works; it does not establish that it outperforms competing approaches.

This bounded search demonstrates why a completeness claim would be premature. It is not a complete census of every repository beyond the starred list. No new runtime, model campaign or benchmark was installed or run for this audit.

## Remaining evidence and capability boundaries

- The core native context, memory and code-retrieval workflows have actual execution receipts. Optional live HUD, outer bridge invocation, native promptfoo and Linux Playwright execution retain narrower or unverified scope.
- QMD uses lexical document retrieval. Semantic document/archive recall and ai-memory LLM consolidation/backfill are disabled. Document/archive refresh is explicit; the selected code watcher requires its running services.
- Artifact token reductions are measured. Matched whole-task quality, provider-token savings and billing reductions are not established.
- The active vLLM pin remains 0.25 after the recorded 0.29 WSL GPU failure. Current release number and working deployment are separate facts.

The defensible conclusion is that the selected workflow has a working foundation with documented limits. A universal best-stack claim would additionally need explicit inclusion/exclusion decisions, task-relevant comparisons, and quality/usage measurements. Those are not supplied by the repository's offline integrity CI.
