## Keep discovery independent

Give each discovery worker the same functional requirements, platform/account
constraints, evidence criteria and output contract. Withhold incumbent names,
rankings, rejection reasons, stars and the other reviewer's conclusions until
each report is complete and its bytes are hashed. Require original upstream
sources, the strongest relevant challenger and the comparison that would change
each recommendation. Record failed source access and uncertainty explicitly.

This procedure reduces selection anchoring; it cannot establish zero bias.
Model training, chosen requirements, source availability and inherited client
instructions can influence discovery. Inspect what a worker actually receives.
An instruction to ignore an incumbent is weaker than withholding that identity.
A fresh context does not demonstrate filesystem or operating-system isolation.

The Codex discovery worker in this wave starts without inherited conversation
history and reads only the neutral requirements packet as local input. It also
receives ambient skill/tool names and project instructions naming the domain's
NautilusTrader destination. Its report therefore declares partial selection
blinding. It may research primary upstream sources and writes a separate report.
The requested boundary is not filesystem enforcement or a measured accuracy
improvement. The returned Claude discovery likewise used its native workflow with
project instructions that can name current domain selections. Both reports must
preserve this residual exposure. Its top-12-by-stars screen introduces additional
selection bias and is explicitly challenged in the report. Do not relabel either report fully blind or
restart useful live work merely to make the reviews look symmetrical.

## Exchange results through the native clients

Use the [native cooperation lanes](../recipes/claude-codex-cooperation-lanes.md)
and [portable Claude workflow practice](../recipes/claude-native-ultracode.md).
Identify the live owner's project and status before sending a bounded request.
An owned relay can use Claude's supported `ListAgents` and `SendMessage` tools;
an idle peer should not receive acknowledgement loops or repeated progress pings.
Queued delivery does not prove the recipient has read, completed or agreed with
the request. Record the actual return separately and preserve native accounts,
permissions, model settings and the user's running work.

Use one coordinator for integration. A reader may inspect a shared checkout;
every writing worker needs an owned branch/worktree. Keep source review,
implementation, independent verification and final integration separate. Load
only relevant skills and evidence into each role. The shared TypeSafe skill is
available for a task that needs qualified semantic judgments; installing a skill
or receiving a model judgment does not establish repository quality.

Claude's public [cross-session messaging documentation](https://code.claude.com/docs/en/cross-session-messaging)
describes message delivery and native identities. Its
[workflow documentation](https://code.claude.com/docs/en/workflows) describes the
workflow surface. Returned local evidence in this repository remains the source
for what actually ran; a documented capability is not a local execution receipt.

## Adjudicate findings after the reports are sealed

1. Preserve the exact review inputs, outputs, source pins, failed attempts and
   available requested/resolved model and usage fields. Unknown means unknown.
   Keep raw native conversations, sign-in state and host-specific paths private.
2. Compare each recommendation to the current layer, and the current layer back
   to the recommendation. Normalize repository aliases. A complementary parser,
   runtime, SDK, database or service is not automatically a competing replacement.
3. Check decision-changing claims against original upstream code/docs and retained
   executions. Upstream vendor benchmarks remain vendor evidence. Stars, release
   dates, repeated model votes and catalog inclusion do not certify a winner.
4. Record retain, adjust, trial, conditional or keep-but-compare with the strongest
   alternative's best case. An untested candidate has not failed. Preserve dated
   failures and distinguish an upstream defect from a local integration failure.
5. When quality or lifecycle decides the choice, freeze a representative workload
   and acceptance criteria before the comparison. Measure task correctness,
   omissions, abstention, end-to-end cost and required recovery. Use native
   upstream tests/examples where they fit; label local fixtures as local fixtures.
6. Regenerate the offline handbook and validate its links, identity joins and
   evidence inventory. Obtain independent patch review and retain the exact
   integrated revision and check results. A deterministic pass does not turn a
   source-based selection into runtime or cross-host acceptance.

## Apply the result on another PC

Start with the reviewed revision, [adoption manifest](../adoption/manifest.json)
and [grand handbook](grand-catalog-handbook.md). Establish the CPU/native-client
foundation first: local sign-in, scoped tools, one useful task, memory ownership
and continuation. Adopt the recorded Claude roles/workflows through supported
native configuration and repeat a bounded source/build/review task on that host.
The merged semantic evidence-reviewer example explicitly requests Opus/high;
its declaration passes local contract checks. Older provider receipts predate
that declaration and do not qualify a new native invocation of it.

Add a research application, container host, GPU service or durable worker runtime
only for its declared workload. Install each candidate in its own compatible
environment, preserve pins and test its useful behavior plus lifecycle. The
existing clean-prefix SDK check is evidence about this host; the new WSL system
must collect its own installation, integration and recovery results. Keep broker
paper qualification, live operation and paid hosting within their distinct scopes.

Future sessions should reopen only the affected layer when a demonstrated gap,
changed requirement, upstream breakage or matched challenger result appears.
Keep unresolved quality comparisons visible in the research queue; do not call
the evolving field permanently exhausted.
