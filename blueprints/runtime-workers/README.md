# Runtime workers by job

Before starting a runtime worker, adding a runtime or reviewing a runtime update, read the matching row in [runtime-jobs.json](../../catalogs/foundation/runtime-jobs.json). This is the canonical rules entrypoint for coding, research gathering, review, GitHub agents, scheduling, evaluation, multi-worker orchestration and trading R&D. The [qualification decision](../../docs/decisions/2026-10-03-runtime-job-qualification.md) records the current evidence and open comparisons.

## Start a worker

1. Match the task to its job row. Use its measured `default` only when the decision binds frozen results and both families' final-head reads. While that field is unset, use the row's `selection_in_use` from the Claude-owned manifest: OpenHands1.50.1 for coding; GPT Researcher3.7.0 plus DeerFlow2.1.0 for gathering; Dagu2.18.1 for scheduling; Inspect0.3.273 for model/task evaluation and Harbor0.23.0 for containerized agent evaluation. The native clients retain review, worker orchestration and trading R&D under their existing lane rules. Hosted GitHub actions remain per-repository choices. Pending measurement adds no approval step and does not change an incumbent.
2. Use the selected upstream's native executable, SDK, extension format and install/test command at the exact recorded source. Give a writer an owned worktree and bounded paths; one coordinator integrates. Load only the job's needed skills/tools. The [skills trial](skills/README.md) separates inventory from actual activation and pruning.
3. Select OmniRoute's provisional `cx/gpt-6.1-sol-ultra` alias; use `cx/gpt-6-astra-max` for consequential judgment. Bind the per-runtime mapping before qualification: native Codex Ultra orchestration, another runtime's supported effort field, effective inference effort and installed gateway composition are separate observations. The gateway's logical Ultra translates to wire Max, while Codex chooses its non-Ultra inference effort from model metadata. Preserve each runtime's supported native effort setting. Require owner-observed delivered reasoning, parallel-tool fields and correlation/counters before freeze; a requested alias or HTTP200 does not qualify the route. The destination canary is21128; the allocated workstation readiness endpoint is20128, with distinct source composition. Keep native sign-ins native; authentication stores stay with their upstream clients.
4. Retain the useful result, terminal outcome, actual tool effects, failures and native usage. Every PR read names its head. Distinguish source review, unchanged upstream tests, integration checks, synthetic controls and actual provider/host execution under the [acceptance policy](../../docs/acceptance-evidence-policy.md).

For Codex0.160, record the effective multi-agent version and model-message/config hint as part of native Ultra qualification. The pinned [feature registry](https://github.com/openai/codex/blob/a956835d020762cb2b570053af06f643a11c0ecc/codex-rs/features/src/lib.rs#L1337) makes `multi_agent_v2` stable but default-off; its [mode resolver](https://github.com/openai/codex/blob/a956835d020762cb2b570053af06f643a11c0ecc/codex-rs/core/src/session/multi_agents.rs#L77) selects proactive Ultra behavior only on V2 and respects configured/catalog messages. A requested effort alone does not bind that behavior. Codex Action's [protected argument contract](https://github.com/openai/codex-action/blob/86365089eb2b84e0a8fb0717b304f8bdcb13b20e/src/runCodexExec.ts#L609) restricts V2 flags/feature overrides; qualify a supported trusted configuration without changing the action's safety strategy. This is a pinned-source condition, not an observation of the active client's settings.

## Measure gateway token features

Use the upstream compression/cache/combo implementation at the recorded gateway pin. Freeze a prompt-compression control, exact feature settings, task/source/extension hashes, runtime/model/effort, quality graders, repetition order and cache boundaries before execution. Obtain the Claude read and exclusive throwaway GPT-pool window through the existing architecture handoff, coordinated with session0c and client-token measurements.

Measure one gateway condition per artifact; keep client context compression outside that condition. Enable a feature only when its frozen quality rule passes and native counters show a benefit. Separate input/output totals, cached/reasoning subsets, compression estimates, cache-hit counters and billed cost. Retain every failed attempt and keep absent counters unknown. Headerless requests and opt-in compression are distinct conditions; an advertised feature establishes no saving. Gateway effort-observation columns may be null even when an effort was sent.

The [pinned cache controls](../../evidence/artifacts/runtime-jobs-source-intake-20261003/gateway-cache-controls.json) support `X-OmniRoute-No-Cache: true` or `Cache-Control: no-cache` for semantic-response-cache read/write bypass. Use that bypass and a unique correlation identifier in every arm and independent attempt, including compression-only controls. This does not clear upstream prompt caching. `x-omniroute-compression: off` leaves independent reactive context-fit safety available; observe and retain any intervention. Rebind these source controls to the actual canary composition before freeze. Use one authoritative complete usage aggregate per arm; compare uncached input plus output only when cache subsets are complete, and retain gross input/output separately. Capture only allowlisted gateway metadata. Cache-hit usage belongs to the retained response, and gateway savings/cost headers are estimates rather than new provider consumption or returned billing.

## Add or replace a default

Gather the live job landscape through the installed GPT research runtime and web search; re-read every claim at a pinned primary source. Start the extension intake at [org-extensions.md](org-extensions.md), then bind the selected org skills, agents, MCP servers and plugins with pins, native loader contracts and useful activation checks. Reuse existing skill records; distinguish their selected pin from a newer runtime/plugin pin. Record alternatives and concrete fit gaps.

Preregister frozen tasks using the standing maintained upstream evaluators: Harbor for containerized agent tasks and Inspect for model/task grading. The user's eligible evaluator landscape also includes promptfoo; it remains an unadopted candidate, with a consensus amendment required before changing the evaluator of record. Keep unchanged upstream graders separate from locally authored rubrics run by an upstream evaluator. Preserve native client orchestration when an API effort enum differs. Obtain an Astra/max read for consequential architecture and a Claude read before freeze. Run only in the agreed window, post sanitized native outcomes and independent observations, then apply the frozen rule. Retain the standing selection unless a challenger clears its preregistered gain; record a native-baseline win for native-owned jobs. This second-gatherer study cannot replace fixed GPT Researcher.

Update the job row, dated decision and catalog evidence together. Send manifest/install/client changes as a consensus proposal to the Claude architecture owner through PR608 or a `CODEX-*.md` note. A final default requires both families' reads at its merged head. Trading R&D additionally follows [its lane rules](../us-equities/AGENTS.md) and the [paper policy](../../docs/paper-lane-policy.md); inspected holdouts and existing trading freezes retain their scope.
