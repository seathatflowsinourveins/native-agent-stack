One technique is **prompt caching** in Anthropic's Claude API. Claude Code uses it on every turn of a long session. The API stores the processed form of a prompt prefix that doesn't change, such as the system prompt, tool definitions and earlier conversation turns, so later requests with the same prefix read it from cache instead of processing it again. It doesn't shrink the context window: it cuts the cost and time of the repeated part, which in an agent loop is most of the input. Anthropic's pricing puts cache reads at 10% of the base input-token price, a 90% discount. The tradeoff is that a cache write costs 1.25× base input for the default 5-minute lifetime, so it only pays off if the prefix is reused before the cache expires. These figures are from my own knowledge; I didn't check them against current Anthropic docs, as the one-tool limit ruled that out.
