One technique is **prompt caching** in the Anthropic Messages API, which Claude Code uses across long agent sessions. You mark a stable prompt prefix, such as the system prompt, tool definitions and earlier conversation turns, with `cache_control` breakpoints. Later requests that start with the same prefix read it from the cache instead of processing it again at full price. The context window stays the same size, but most of the input tokens a coding agent re-sends on each tool-call turn become cheap cache reads. By Anthropic's published pricing, cache reads cost 10% of the base input-token price (a 90% discount), and Anthropic's launch announcement claimed latency drops of up to 85% for long prompts. The tradeoff is that writing to the cache costs 25% more than normal input for the default 5-minute lifetime, so caching only pays off when the prefix is reused before it expires.
