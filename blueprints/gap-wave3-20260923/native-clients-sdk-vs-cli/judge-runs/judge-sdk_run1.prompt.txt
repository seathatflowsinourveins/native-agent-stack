The technique is **prompt caching**, specifically Anthropic's prompt caching for the Claude API, which Claude Code uses. An agent resends the same long prefix on every tool-call turn: system prompt, tool definitions, and earlier conversation. Caching lets the API store that prefix at marked `cache_control` breakpoints and reuse it on later requests, so the unchanged part is not billed or processed as fresh input. Anthropic's published pricing bills a cache read at 10% of the base input-token price, about a 90% saving on the reused prefix. The tradeoff is on writes: storing the prefix costs 1.25× the base input price with the default 5-minute lifetime, or 2× with the 1-hour option. Caching also only helps when the prefix stays byte-for-byte identical and is reused before it expires.

These figures come from my knowledge of Anthropic's documentation, not from a source I checked in this session. The only tool I ran was the timestamp command.
