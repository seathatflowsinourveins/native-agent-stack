The technique is **prompt caching**, a feature of Anthropic's Claude API that Claude Code relies on during long agentic sessions. The system prompt, tool definitions and earlier conversation turns stay the same from one tool call to the next. Once written to cache, that shared prefix is read back on later requests instead of being processed again, so each turn fully processes only the new tokens after the last cache breakpoint. According to Anthropic's pricing documentation, cache reads cost 10% of the base input-token price, a 90% discount. The tradeoff is that cache writes cost 1.25× the base price with the default 5-minute TTL, so caching only pays off when a prefix is reused.
