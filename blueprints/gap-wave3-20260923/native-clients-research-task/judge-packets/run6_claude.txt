One technique is **prompt caching** in the Anthropic Messages API, which Claude Code uses automatically for its system prompt, tool definitions and conversation history. You mark a stable prefix (tools, system prompt, earlier turns) with a `cache_control` breakpoint, and later requests reuse the cached prefix instead of reprocessing it. This doesn't cut how many tokens you send, but it makes the repeated tokens much cheaper and faster, and a long agent session repeats almost everything on every tool call. Anthropic's documentation prices cache reads at 10% of the base input-token rate, which it describes as up to a 90% cost reduction and up to an 85% latency reduction for long prompts. The tradeoff is that cache writes cost 1.25× the base rate with the default 5-minute lifetime, or 2× with the 1-hour lifetime, so caching loses money on a prefix that is rarely reused before it expires.

These figures come from memory of Anthropic's docs; I didn't check them against the current pricing page because only Bash was allowed.
