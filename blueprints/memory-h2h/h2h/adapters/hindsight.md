# Hindsight adapter — v0.10.2

Targets [`vectorize-io/hindsight` v0.10.2](https://github.com/vectorize-io/hindsight/releases/tag/v0.10.2), commit `5fc4ce20917b916240cef27c212c387a177f115b`. The adapter uses the published self-hosted HTTP API, through `httpx`; it does not depend on the Python Hindsight client. No imports contact a server. Every adapter instance owns its process, bank mapping and provenance mapping.

Research checked executable/package availability first: `hindsight-api` and `hindsight_api` were not installed on this builder host. The tagged release notes were then inspected through `gh api`, followed by tagged source, OpenAPI and documentation. No memory system was installed, started, stopped or queried during the source build. Docker executable help/version checks do not establish running-system acceptance.

## Install and private launch

The upstream pip installation command is quoted verbatim from [`hindsight-api/README.md`, lines 7–11](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-api/README.md#L7-L11):

```sh
pip install hindsight-api
```

Its pinned form is `pip install hindsight-api==0.10.2`; the version insertion comes from [`hindsight-api/pyproject.toml`, lines 5–14](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-api/pyproject.toml#L5-L14), which declares version `0.10.2` and `hindsight-api-slim[all]==0.10.2`. This is a manifest-derived pin, not a verbatim versioned command in the README.

The adapter selects the full **API-only Docker image**, preserving the bundled default reranker and, when `embed=None`, local embedder. Upstream's documented Docker installation/start command includes:

```sh
docker run -it --pull always --name hindsight --restart unless-stopped --shm-size=1g -p 8888:8888 -p 9999:9999 \
  -e HINDSIGHT_API_LLM_API_KEY=$OPENAI_API_KEY \
  -v hindsight-data:/home/hindsight/.pg0 \
  ghcr.io/vectorize-io/hindsight:latest
```

Quoted from [installation.md, lines 75–84](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-docs/docs/developer/installation.md#L75-L84); it is reference text, not a command executed by the builder. Our image pin is `ghcr.io/vectorize-io/hindsight-api:0.10.2`: the [release workflow, lines 386–390](https://github.com/vectorize-io/hindsight/blob/v0.10.2/.github/workflows/release.yml#L386-L390), selects `target: api-only` / `image_name: hindsight-api`; [lines 443–456](https://github.com/vectorize-io/hindsight/blob/v0.10.2/.github/workflows/release.yml#L443-L456) remove the leading `v` and publish `type=semver,pattern={{version}}`. Docker's normal `run` behavior pulls a missing image. The coordinator can acquire this exact image before running the harness.

`start` creates a fresh `workdir/hindsight-<uuid>/pg0` and mounts it at `/home/hindsight/.pg0`. This is the upstream supported bind-mount alternative: [installation.md, lines 89–104](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-docs/docs/developer/installation.md#L89-L104), says the directory **“must be owned by UID 1000”** and **“Do not run the image under a different UID with --user.”** The adapter checks that ownership and fails clearly if it cannot use this route. It does not change host ownership, repurpose `HOME`, or substitute a shared named volume.

The image's defaults are quoted in [`docker/standalone/Dockerfile`, lines 235–248](https://github.com/vectorize-io/hindsight/blob/v0.10.2/docker/standalone/Dockerfile#L235-L248): `HINDSIGHT_ENABLE_API=true`, `HINDSIGHT_ENABLE_CP=false`, and `CMD ["/app/start-all.sh"]`. That script runs **`hindsight-api &`** in `/app/api` ([start-all.sh, lines 346–354](https://github.com/vectorize-io/hindsight/blob/v0.10.2/docker/standalone/start-all.sh#L346-L354)). A small adapter credential bootstrap execs that exact upstream startup script, overriding only binding and supplied model routes. This transport glue is described below; it is not a Hindsight credential-stdin API.

The generated launch is `docker run --rm --name <owned-name> --network host --interactive --entrypoint /app/api/.venv/bin/python --env <NON_SECRET_NAME> ... --volume <private-pg0>:/home/hindsight/.pg0 ghcr.io/vectorize-io/hindsight-api:0.10.2 -c <credential-bootstrap>`. Docker host networking is an official Docker route; a Hindsight-specific host-network example was not found in the pinned installation page, Dockerfile or start script. This adapter requires Linux and a **local Docker daemon**. Host networking lets unchanged `127.0.0.1` model base URLs reach the host endpoints. The caller must allocate an unused `H2H_PORT`. Before starting Docker or making any HTTP request, the adapter checks the loopback bind, following [Hindsight main.py, lines 139–158](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-api-slim/hindsight_api/main.py#L139-L158). Like that upstream preflight, it releases the probe socket before launch; the coordinator must keep the assigned port exclusive until startup completes. No fixed host database port is set: [pg0.py, lines 24–32 and 53–64](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-api-slim/hindsight_api/pg0.py#L24-L64), says `None means pg0 will auto-assign`.

Docker receives only named **non-secret** configuration variables through `--env NAME`. API keys are read from the supplied `ModelRoute.api_key_env` in memory and serialized to the owned subprocess stdin as a small JSON map of the two documented API-key environment aliases (only the LLM alias when `embed=None`). The inline Python bootstrap executes `os.environ.update(json.load(sys.stdin))` and then `os.execv('/app/start-all.sh', ['/app/start-all.sh'])`. Closing stdin completes the JSON input. The key values occur neither in argv nor in Docker's configured environment; no env file, credential file, script file or key is written by the adapter. Startup stdout/stderr are discarded; stop output is captured only in memory to classify cleanup. Only pg0 data is bind-mounted, so a host `.env` is not loaded into the image. This matters because [Hindsight's config loader, lines 26–52](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-api-slim/hindsight_api/config.py#L26-L52), explicitly uses `load_dotenv(..., override=True)` at standalone startup.

The credential bootstrap is local transport glue, while Hindsight still receives its documented environment interface. [CPython v3.11.15 `Doc/library/os.rst`, lines 196–198](https://github.com/python/cpython/blob/v3.11.15/Doc/library/os.rst#L196-L198) documents environment mutation, and [lines 3757–3762](https://github.com/python/cpython/blob/v3.11.15/Doc/library/os.rst#L3757-L3762) say `execv` inherits that environment. [CPython JSON source, lines 274–293](https://github.com/python/cpython/blob/v3.11.15/Lib/json/__init__.py#L274-L293) reads the supplied stream to EOF. Docker's stdout/stderr logging path excludes stdin ([Moby commit `c8e265787b0a89d161f34c3920f73f136974744b`, container.go line 715](https://github.com/moby/moby/blob/c8e265787b0a89d161f34c3920f73f136974744b/daemon/container/container.go#L715)). This is pinned source evidence, not a running host-daemon inspection.

Default consolidation remains enabled, as [configuration.mdx, lines 2257–2258](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-docs/docs/developer/configuration.mdx#L2257-L2258) specifies both observation and auto-consolidation defaults as `true`. [operations.mdx, lines 67–77](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-docs/docs/developer/api/operations.mdx#L67-L77) states it is triggered after retains and bank-deduped. After all synchronous retains, ingestion waits until the bank has no pending/processing work for two polls; failed/cancelled work and timeouts are errors, not successful ingestion. Server-native retries run unchanged. The ingestion timer includes this wait.

Recall uses **only** the original query and optional question timestamp. It does not set `types`, budgets, inclusion options, tag filters, score thresholds or query gates. Upstream is token-oriented ([recall.mdx, lines 110–115](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-docs/docs/developer/api/recall.mdx#L110-L115)); `k` is not a RecallRequest field. The adapter applies the harness's `k` as a client-side limit over the API's existing ranked results. `k=0` returns an empty list without recall.

The common answerer receives each complete returned fact as JSON, retaining `text`, event/mention dates, type, metadata and canonical entity names, plus the returned entity states associated with that fact. These are recall data, not answers. [recall.mdx, lines 450–517 and 533–535](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-docs/docs/developer/api/recall.mdx#L450-L517) documents the result fields, relevance order and entity states. `Retrieved.score` uses `scores.final`, which upstream describes as a relative ranking signal, not a calibrated probability ([lines 510–513](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-docs/docs/developer/api/recall.mdx#L510-L513)). `session_ids` comes from returned `metadata.session_id`, or returned `document_id` mapped to the original session. Observations without reported document provenance yield `()`; source-fact expansion is disabled by default and is not enabled just for scoring.

`reset(namespace)` deletes that namespace's previous whole bank, then creates an empty default bank with a fresh ID. Recall and ingestion always address exactly the mapped bank; other namespaces are separate banks. Rotating the bank identity prevents in-flight work targeting a previous bank from repopulating its replacement. A fresh private PostgreSQL directory per `start` also prevents abandoned queues from previous runs being executed against a new benchmark.

## LLM work, disk state and limits

`needs_llm=True`: retain extracts semantic facts using the LLM, and default consolidation synthesizes observations. [Operations documentation, lines 49–51 and 67–77](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-docs/docs/developer/api/operations.mdx#L49-L77) names that pipeline. Default recall uses embeddings, keyword/graph/temporal search and a local cross-encoder; its default temporal analyzer is `DateparserQueryAnalyzer` ([temporal_extraction.py, lines 64–76](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-api-slim/hindsight_api/engine/search/temporal_extraction.py#L64-L76)). The adapter does not call reflect or an additional answer model.

Upstream's cited retain response reports extraction **token usage**, not a per-session LLM call count ([http.py, lines 1276–1308](https://github.com/vectorize-io/hindsight/blob/v0.10.2/hindsight-api-slim/hindsight_api/api/http.py#L1276-L1308)). A fixed calls-per-session estimate is not documented in these references: chunking, consolidation and native retries affect it. `IngestStats.llm_calls` stays `None`; it is not set to the number of HTTP requests.
