## Context and runtime efficiency

Use the smallest sufficient evidence packet, then open its source when needed.
The document recipe returns at most three records of240 characters with document,
page, source hash and bounds; missing evidence stays empty. Native project locks
and generated API contracts reduce repeated environment and schema investigation.
The publication validator evaluates Git publication paths rather than installed
build trees, while retaining tracked and explicitly hash-listed files. Full native
logs, failed attempts and artifact hashes remain available outside routine context.

These are architectural constraints and observed artifact boundaries, not a
measurement of complete provider usage. Native model quality, caching, compaction
and explicit scoped memory remain intact. No model call is needed to replay the
deterministic artifact checks. Do not repeat accepted native work solely to refresh
a timestamp or load the entire catalog into every worker.

## Acceptance sequence

Read the selected recipe, its exact source pins, compatibility and license notes.
Use its isolated prefix/project and upstream commands. Preserve failed attempts;
verify the declared task, negative cases and cleanup. Record the actual host before
promoting a local tool or marking another profile ready. Keep rollback paths and
native account stores local.

The catalog is a selection aid. Stars and awesome lists establish discovery, not
installation permission, compatibility or successful execution. Shared services,
accounts, global configuration and publication have one coordinator owner.
