# Independent adversarial reviews of the window census before this head was pushed (2026-10-06 UTC)

Method: two read-only testers (the project's `stack-verifier` agent type, Opus at maximum effort, their prompts naming the census text, the controls' fixture builders, the contract, the findings already fixed and the attack families; each wrote only under its own scratch directory, never touched the live store except the three live-trial arms' rows for one read-only comparison, and never contacted a gateway).
Evidence class `local_integration`: synthetic fixtures built with the controls' builders; the only real rows read are the live trial's. Their scripts stay private (a scratch directory); what is kept here is what each found, what fixed it and the regression result.

## Review 1: the census at sha256 385e891a (the head's census before the journal check): about 150 targeted cases and 2,000 random mutations of one arm file

Result: 11 findings (2 P1, 7 P2, 2 P3). Every one needs an input that the real producers (the gateway, the frozen scripts, the wrapper, guard 5) never write; every one is fixed so that the census fails closed.

| id | severity | what was found | the fix | controls |
| --- | --- | --- | --- | --- |
| F1 | P1 | a stamp with non-ASCII digits (for example an Arabic-Indic digit) passed the format check (`\d` and `strptime` accept it) and sorts outside every string bound: a foreign call row, an orphan usage row or the stand-in usage row of a substitution was never read, so a substituted request PASSed with `scope=canary` | ASCII digits only (`[0-9]`, `isascii()`); a usage stamp that cannot be shifted is a problem of its own | F1a, F1b, F1c, F1d |
| F2 | P1 | the `min_rows` a native RESULT line prints was trusted (a turn that printed `min_rows=0` with both rows dropped PASSed), and the canary gate checked only the arms' kinds and request counts (eight one-row turns in place of the tool-call set PASSed) | `min_rows` is derived from the shape (native script 2.1's `SHAPES`) and a printed value that differs is a problem; each canary arm must hold exactly the modes or shapes of the frozen command | F2a, F2b, F2c |
| F3 | P2 | a wrapper output cut off after the journal line hid a restart in the last arm: only the first identity line was compared and neither RUN-STATUS nor `# finished` was required | every identity line is compared with the receipt; the canary gate needs two identity lines, one RUN-STATUS with status 0, one wrapper header and one `# finished` per arm | F3a, F3b |

Accepted as benign by the reviewer and by us: one corrupted correlation id when the request's response id is intact (the scripts' own predicate is `correlation_id = ? or response_id = ?`, so the row is found through the other id).

Regression of the reviewer's whole corpus (147 targeted cases) against the census of this head: no false PASS except that one accepted case; its 2,000 random mutations (seeds 14 and 15) were rerun as 1,500 (seed 14) and 800 (seed 15) mutations of the canary world: every one exit 2, none a crash.

## Review 2: the journal check, the census at sha256 55e993f7 (the census as it stood with the journal check: about 90 cases in five attack families, run read-only against the controls' journal shim and four times against the real journal)

Result: 9 findings (1 P1, 5 P2, 3 P3). Three were reproduced as false PASSes in the canary's scope (F-1, F-2 and the four-arm variant of F-3); every one is fixed so that the census fails closed or says what it cannot see. Attack families and what each found: journal output variations (39 runs: one reachable false-PASS class, a null message, plus 17 fail-open encodings that this journalctl and gateway do not produce), exit status and streams (12 runs: no false PASS from an exit code; a stderr warning with exit 0 and one line fewer was not detectable), pairing (25 runs: 6 false PASSes, 3 chain and 3 leading-edge), interplay (7 runs: a forged result line in the receipt and one crash), the real journal (4 reads: 0 false PASSes; the line format, the offsets of 12-25 ms between the gateway's time and journald's, the explicit UTC suffix of the query and the live trial's 6 lines against 3 rows, and 3 against 2 on arm A alone, were all confirmed). No result line was ever a PASS beside a PROBLEM line, and the last `CENSUS-RESULT` line always matched the exit status.

| id | severity | what was found | the fix | controls |
| --- | --- | --- | --- | --- |
| F-1 | P1 | a foreign request that arrived just before the window's start could stand in for an own request (the R3 world): the store side reads call and usage rows from 3 s before the window, a substitute usage row may lie up to 3 s before the own row with a latency within 0.1 s of the own duration, so the substitute request may have arrived 3.1 s before the first own arrival, and the journal side counted lines only from the window's start; on this host the first own arrival line of the live trial was 0.096 s after the window's start | arrival lines are counted from 4 s before the window's start (the 3 s candidate pad and 1 s margin) to the window's end, and the journal is read from 6 s before | J12a (a line 2.5 s before: INCONCLUSIVE), J12b (1.1 s before), J12c (the range's own boundary: a line 4.5 s before is not counted) |
| F-2 | P2 | an arrival line longer than 4096 bytes reaches the census as `MESSAGE: null` (journalctl writes such a field as null unless it is given `--all`) and was skipped silently, so a request of a client with a long `model` or `reasoning_effort` (the gateway logs the label before it checks the authorization; the label appears twice in the message, so about 2 KB suffice; whether such a request also writes its normal rows was not verified) left no line the census could count; 17 further encodings (a byte array with a value outside 0-255, a number, an object or an array as message, a message that starts with `{` and does not parse, a negative or boolean `__REALTIME_TIMESTAMP`) were also skipped | `--all` is passed, and an entry whose message is null, of the wrong type, undecodable, starts with `{` but does not parse, carries the arrival marker without being counted, or whose timestamp is not ASCII digits within 2000-2100 makes the window INCONCLUSIVE | J13a-J13h (each form), J13i (a 5,000-byte label served as a string: counted), J14b (the argument vector the shim saw holds `--all` and an explicit UTC suffix) |
| F-3 | P2 | the limit that control J10 shows is wider than documented: the pairing compared time only, so a lost own line balanced by a foreign line chains through a neighbouring own row (a foreign line 4.4-5.0 s from the lost one, within 3 s of the next own request's line, PASSed); in J10 itself the foreign line was of another path | each own call row pairs only with an inbound line of the same path (the label's path equals the row's `path`), and the protocol states the remaining chain width: 3 s per link between neighbouring own requests | J16 (the J10 world with a line of another path: INCONCLUSIVE), J15 (the chain width, expected PASS and documented as a limit) |
| F-4 | P2 | a client could write a forged `CENSUS-RESULT PASS` line into the receipt through the label of an arrival line (a newline, a carriage return or U+2028 in `model` or `reasoning_effort`, before the authorization check) | control and line-separator characters of labels are escaped in every receipt line (closed before this round's last head, by review 1's F11 fix, which escapes control characters of every input; this review read the census before that fix) | J20 (passes on the census before this round's last head too: no difference in the negative controls) |
| F-5 | P2 | an escaped lone surrogate in a label crashed the census with exit 1 and no receipt when labels were printed (an INCONCLUSIVE window) | the same escaping, and the receipt is written as bytes with backslash escapes inside the guarded block (review 1's F6 fix; closed before this round's last head) | J20 |
| F-6 | P2 | documentation: the docstring and the receipt's NOT-EXCLUDED line left out the J10 limit, and statements such as "the journal shows no other inbound request" and "a foreign request leaves a line even when its call row was never written" were false for J10, F-3, F-1 and F-2 | the limits are stated where the claims are made (docstring, receipt, protocol): the width of the pairing, the foreign request the gateway did not log, the unlogged persistence failures | (text) |
| F-7 | P3 | the pairing counts in the receipt could be wrong (rows without a line were counted per row, not from a matching), and the lines of such components were not listed | the rows and lines left over after a maximum matching are counted and the lines are listed | J17 (three rows and three lines, one row and one line left), X3 (the matching functions against a brute force and scipy) |
| F-8 | P3 | some exceptions skipped every check after the journal block: a byte that is not valid UTF-8 on journalctl's stdout (UnicodeDecodeError) and an own row whose duration overflows the arrival (1e15 ms) | stdout is decoded with replacement and the line is then parsed as usual (a line that does not parse is counted as unreadable); an arrival that overflows is a problem of its own ("is longer than a week") and the rest is measured | J13j (a 0xFF byte in an arrival line), J18 (1e15 ms) |
| F-9 | P3 | the receipt did not record the journal query, the binary, its version or its stderr, and the QUERY line printed placeholders (and a different pad than the argument vector's); a stderr warning such as `File ... is truncated, ignoring file.` was thrown away | the receipt prints the exact argument vector, the binary, its version, the stderr and the number of entries read, and a stderr that reports skipped data (words such as truncated, corrupt, ignoring, failed, error) makes the window INCONCLUSIVE | J14 (the command, binary and version in the receipt), J19a (the truncated-file warning: INCONCLUSIVE), J19b (a harmless hint is recorded: PASS) |

Regression of the whole of review 1's corpus against the census with these fixes: no false PASS except the one accepted case; the 1,500 and 800 random mutations (seeds 14 and 15): every one exit 2, none a crash; the property test (600 worlds, seed 757, with the journal faults): 318 of 318 faulty worlds INCONCLUSIVE and 282 of 282 clean worlds PASS; the real rows (the baseline arms, the live trial) give the same answers as before the fixes (43 inbound requests against 26 own call rows; arm A alone 3 against 2; the three arms 6 against 3). The controls of this review are written against the reviewer's reproductions; the negative controls (`checks/census-negative-controls.txt`, the table is exit statuses) show which of them the census before these fixes (`superseded/window-census-r16.py.txt`) passed where INCONCLUSIVE is right: J12a and J12b (F-1), J13a-J13h (F-2), J16 (F-3) and J19a (F-9); the others (J12c, J13i, J13j, J14, J15, J17, J18, J19b, J20) give the same exit status there, and J13j, J14, J17 and J18 differ in the receipt's text only, which the table does not show (the list of scenarios not as expected does).
