# Why build script version 3 failed twice at upstream's check:pack-boot, the host behaviour behind it, a one-minute reproduction on the installed candidate prefix, and the fix in version 4 (2026-10-06 UTC; nothing deployed, no credential involved)
# 1. check:pack-boot (scripts/check/check-pack-boot.mjs of the composition) picks PORT = 23000 + (its own pid % 4000), starts the installed CLI and polls http://127.0.0.1:PORT/api/monitoring/health from its first second (a fetch every 2 s).
# 2. The installed CLI's own port preflight (bin/cli/commands/serve.mjs resolveServeBusyPids -> bin/cli/utils/pid.mjs findListeningPids: `lsof -ti :PORT`) lists EVERY process with a socket on the port, clients included (the known client-socket trap of the 2026-09-30 note, omniroute-sol-max-20260930).
# 3. On this host a connect to a closed loopback port that nothing in the network namespace has bound before HANGS (undici UND_ERR_CONNECT_TIMEOUT after 10.5 s) instead of failing at once with ECONNREFUSED; after one bind and close of the port it is refused at once (section B). The cause is not established (a WSL networking behaviour is suspected).
#    So the harness's own poll sits in SYN_SENT with remote port PORT when the CLI's preflight runs; the CLI refuses with "Port PORT is already in use by PID <the harness>" and exits 1. Both failed runs name the harness's own pid: 23149 = 23000 + 120149 % 4000 and 26495 = 23000 + 263495 % 4000.
# 4. Version 1's real run (the recorded tarball's build) passed with upstream's defaults (how its port answered a connect at that time was not recorded; an immediate refusal would explain it). The fix in version 4 is not a retry: check:pack-boot runs with the reviewed lsof shim v2 first on PATH (sha256 b6ae9002..., the committed copy in omniroute-sol-max-20260930), which answers `lsof -ti :PORT` with exit 2 and no output,
#    so upstream's own bind-probe fallback (#14518) decides, and a real second listener is still refused; it is the PATH the deployed prefix runs with. Mode B below and the rerun of the gate in the failed run's tree (section D) show it passing; the full version-4 run is checks/build-v4-results.txt.
