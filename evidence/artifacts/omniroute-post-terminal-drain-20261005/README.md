# Why a client that closes right after the terminal event left no call_logs and no usage_history row, and the drain patch, 2026-10-05/06

Evidence for the update of 2026-10-05 (evening) in [`docs/decisions/2026-10-05-omniroute-gateway-composition.md`](../../../docs/decisions/2026-10-05-omniroute-gateway-composition.md). The patch is a **candidate**: it is tested in scratch trees built from public refs, built and installed
in a private prefix, and runs nowhere; the canary on 20128 is pending and its acceptance protocol is frozen here before the switch. Host paths are written `$HOME`; the metadata-only reads of the gateway store name no credential, connection or body.
Superseded and failed attempts are kept in [`superseded/`](superseded/README.md). Every `.txt` under `scripts/` is the script as it ran (a `.txt` suffix appended), except `smoke-control.sh.txt`, whose default path to the smoke script is replaced by a required variable (`SMOKE_SCRIPT`); controls named below show the check failing with its condition absent.

Rerun the validation: `DRAIN_DIR=<directory holding drain-after-terminal.patch and superseded-first-version.patch> EV=<evidence/artifacts/omniroute-wire-effort-20261005 of this repository> EXPECT_TREE=b7c6869001ce8bdd23e2e2352f48ce3058bc13d2 scripts/drain-prototype.sh.txt`
needs a bare mirror of OmniRoute (v3.8.51 and PR 15167's head) at the path the script names (`MIRROR`). It stops with exit 3 when a setup step fails, a tree id differs or an expectation is violated, and with exit 2 before creating anything when an input or the mirror is missing; it creates its own scratch directory and deletes only its own temporary copy of the extracted test file. The handler check and the build script take the same `DRAIN_DIR`, `EV` and `EXPECT_TREE`.

Limits: the host mirror lacks one object that an unrelated upstream test needs (above); the live acceptance and the 2604 install are not done; the unit tests use the Responses format on the bare stream, the handler check adds Chat Completions with a stubbed upstream, and Anthropic-format clients are covered by code reading only; the retained build is version 1's and a rebuild of the same tree is not byte-identical (the recorded sha256 identifies the artifact), and the runtime dependency graph is not pinned by the tarball.
