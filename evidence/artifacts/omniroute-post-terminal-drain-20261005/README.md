# Why a client that closes right after the terminal event left no call_logs and no usage_history row, and the drain patch, 2026-10-05/06

Evidence for the update of 2026-10-05 (evening) in [`docs/decisions/2026-10-05-omniroute-gateway-composition.md`](../../../docs/decisions/2026-10-05-omniroute-gateway-composition.md). The patch is a **candidate**: it is tested in scratch trees built from public refs, built and installed
in a private prefix, and runs nowhere; the canary on 20128 is held by the command center, and its acceptance protocol (`checks/live-acceptance-protocol.md`, version 2) is frozen by the commit that adds it. Host paths are written `$HOME`; the metadata-only reads of the gateway store name no credential, connection or body.
Superseded and failed attempts are kept in [`superseded/`](superseded/README.md). Every `.txt` under `scripts/` is the script as it ran (a `.txt` suffix appended), except `scripts/smoke-control.sh.txt`, whose default path to the smoke script is replaced by a required variable (`SMOKE_SCRIPT`);
controls named below show the check failing with its condition absent. UUID-shaped strings (the gateway's correlation ids) in committed outputs are shortened to 8 hex digits, each such file saying so and carrying the sha256 of its unshortened text; the unshortened texts are kept privately and listed in `checks/logs/MANIFEST.txt`.

needs a bare mirror of OmniRoute (v3.8.51 and PR 15167's head) at the path the script names (`MIRROR`). It stops with exit 3 when a setup step fails, a tree id differs or an expectation is violated, and with exit 2 before creating anything when an input or the mirror is missing; it creates its own scratch directory and deletes only its own temporary copy of the extracted test file. The handler check, the session-tag check (which needs `handler-e2e-session-tag.test.ts` in `DRAIN_DIR`) and the build script take the same `DRAIN_DIR`, `EV` and `EXPECT_TREE`; the build script also needs the committed lsof shim (found next to `EV`, or `SHIM_SOURCE`) and, on this host, cannot pass `check:pack-boot` without it (`checks/preflight-race-reproduction.txt`).
Rerun the offline controls: `python3 scripts/acceptance-controls/run-controls.py --work <scratch dir> --schema <the live store's table definitions, dumped without data> --repo <this repository> [--only R1,N1,G,W,...]` (the scripts it exercises sit in the paths named in its header). The scenarios that demonstrate version 1's defects (`N2a`, `N2b`, `N5b`, `N6`, `N1v1`) need version 1's quiet check to see a quiet host: when a worker of another lane (`omniroute-codex-sdk/worker.py` or `codex exec`) runs on the host they come out INCONCLUSIVE, so put a directory holding `scripts/acceptance-controls/pgrep-shim.sh.txt` as an executable named `pgrep` first on `PATH` for them (the final run did, for part B2 and part D, because a worker of another lane was running; the first run of part B shows the four disturbed results).

Limits: the host mirror lacks one object that an unrelated upstream test needs (above); the live acceptance of the drain build and the 2604 install are not done; the unit tests use the Responses format on the bare stream, the handler check adds Chat Completions with a stubbed upstream, and Anthropic-format clients are covered by code reading only;
the retained build is version 1's and a rebuild of the same tree is not byte-identical (the recorded sha256 identifies the artifact), and the runtime dependency graph is not pinned by the tarball; the offline controls are synthetic, and the guard cannot see a request that is silent on the wire or an interactive client between requests (the protocol's announcements and holds cover those).
