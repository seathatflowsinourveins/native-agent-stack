# Login shell contract acceptance scripts (2026-09-29)

The probes behind the "Update 2026-09-29" section of [the terminal decision](../../../docs/decisions/2026-09-28-terminal-experience.md)
and its [receipt](../../receipts/login-shell-contract-20260929.json). They are read-only or write only to the system temporary
directory; none of them edits a settings file and none writes into this folder. `scrub_placeholder_probe.py` removes its throwaway homes
and their private temporary directories (it points `TMPDIR` and `CLAUDE_CODE_TMPDIR` there, so the client's per-directory state, file-watch
probe folder and sandbox socket go with them) and the client's shared `/tmp/inline-comments-buffer.jsonl` when it was absent before the run and appeared, empty, during it (the script cannot tell its own arms from a concurrent session); it records
the real home's placeholder names and the top level of the real `/tmp` and `/tmp/claude-<uid>` before and after, so the isolation is measured for that run as far as those comparisons go: the named files of the real home by lstat (mode, size, mtime, inode) and the top-level names of the real `/tmp` and `/tmp/claude-<uid>`; writes inside entries that already existed are not measured (a concurrent session can add entries to the window; the private directory's contents are the positive observation). Run them with
`python3 -B` so no `__pycache__` appears here. Each was run on the workstation the receipt names.

| Script | What it measures | How it was run |
| --- | --- | --- |
| `scrub_placeholder_probe.py` | What `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` leaves behind on Linux with bubblewrap: three arms in throwaway homes (no variable; the variable with a stock Ubuntu-shaped home that has only `~/.profile`; the variable with a real `~/.bash_profile` that hands off to `~/.profile`). Runs the installed native binary under `env -i` with a dummy non-credential API value; the run stops at the API-key check after the files are written, so no model call is made. Each arm points `TMPDIR` and `CLAUDE_CODE_TMPDIR` at a short private directory (scratch is created directly under `/tmp` with a short name and an arm whose socket path would exceed the client's 103-byte cap is refused, and `XDG_RUNTIME_DIR` is never set), because the client falls back to a fixed `/tmp/cc-socks-<uid>` directory when `<dir>/cc-socks/<pid>.sock` is longer than that. In the stock-home arm it also runs the installed `claude doctor` twice, with the sandbox off and with it enabled plus a planted stale mask file (the positive control), and records whether each run's warnings name the planted file and the scrub-created file (the planted file only shows the warning is live: the documented warning covers 0-byte read-only placeholders, and the scrub-created file is writable, so its mode is recorded too). Prints counts, generic dotfile names and booleans, and whether each login `PATH` still holds `~/.local/bin`. The 19 names of the real home are compared by `lstat` before and after, from ONE final snapshot; a name whose state could not be observed (an unsearchable parent directory) is listed in `real_home_names_unmeasured` and makes `real_home_placeholder_names_unchanged` null, never true. The client also touches one absolute path outside any home, `/tmp/inline-comments-buffer.jsonl`, which it hard-codes; the script removes it only if it was absent before and appeared, empty, during the run, and reports both facts | `python3 -B scrub_placeholder_probe.py` (needs `claude` and `bwrap`) |
| `startup_placeholder_names.py` | Which paths the installed client's scrub-mode startup code creates: reads the native binary, finds the loop that opens a fixed list in append mode with parent directories created, and prints the home-relative and working-directory-relative names, the one absolute path, the open mode and whether `.bash_profile`, `.profile` and `.bash_login` are on the list. Read-only; prints names and booleans | `python3 -B startup_placeholder_names.py` (needs the native `claude`) |
| `socket_path_fallback_probe.py` | Where the client's messaging-socket directory (`cc-socks`) goes when its private temp directory is short (17 bytes) and when its socket path exceeds the client's own 103-byte cap (a 99-byte private path gives a 121-byte socket path): two runs of the same scrub start, the top-level names that appeared in the real `/tmp`, where the directory landed, whether a fallback directory already existed (then the run is not conclusive) and the shared `inline-comments-buffer.jsonl` (present before, appeared, removed). A fallback directory that appeared is removed only when it is an empty directory owned by this user. Prints counts and booleans | `python3 -B socket_path_fallback_probe.py` (needs the native `claude`) |
| `login_shell_check_controls.py` | The doctor's login-shell check (function copied from the practice repository, which has no remote) against eleven temporary homes: `~/.profile` only, an empty `~/.bash_profile` (the incident), a real hand-off `~/.bash_profile`, an empty `~/.bash_login`, no startup files, a healthy `~/.bash_profile` beside an empty `~/.bash_login` that bash never reads (must pass), a non-empty `~/.bash_profile` that exits 0 before the probe (must fail: no answer for any name), one that exits 1, a shell function named `claude` with no executable (must fail: `type -P` finds files only), a startup file that hashes `claude` to a path that does not exist with `hash -p`, and a mode-0644 `claude` on PATH (both must fail: `type -P` prints the stale or non-executable path, `exec` fails with 127 or 126, so a name counts only when the resolved path is an executable regular file). The probe prints FOUND or MISSING for every name and a final DONE; a run without them fails (the lines are ordinary stdout: they guard against accidental early exits, not against a startup file that replays the command string). The earlier check is kept in the file (`previous_check`) so the run shows it was wrong on three of the cases. With `--real-host` it also checks the running user's home, read-only | `python3 -B login_shell_check_controls.py --real-host` |
| `login_path_digest.py` | The number of entries and a SHA-256 prefix of the PATH a login shell ends up with, started the way the doctor check starts one (`env -i`, the distro default PATH, `/bin/bash -lc`). Run before and after a change to the login startup files: an unchanged digest shows the change altered nothing. The PATH is read between two nonce-marked lines, so a startup file's ordinary output cannot pass for it (a startup file that deliberately replays the command string (`$BASH_EXECUTION_STRING`) can, so shell stdout is not authenticated) and a newline inside a component stays part of the payload; a login shell that failed or ended before the record is a measurement error (exit 1, no digest); `--selftest` shows that on four temporary homes and adds startup files that log a `PATH=` line, print a plain line and print a non-UTF-8 byte, two different PATHs and a newline inside a component (ten checks) | `python3 -B login_path_digest.py [--selftest]` |
| `agents_json_probe.py` | What `claude agents --json` prints on this host: rows, kinds, statuses and field names, and whether `--cwd` and `--all` change it. Read-only, no session started; a live snapshot | `python3 -B agents_json_probe.py` |
| `landscape_refresh.py` | The dated upstream refresh: Windows Terminal releases and the two toast signals, the newest Claude Code and Codex releases, how many lines of Codex's notification, palette and config sources changed between the installed tag and the newest stable tag, the candidate notifiers' heads against the recorded pins, and the public Claude Code reports about the placeholder files. Reads only; never files or comments. The Codex comparison covers the Notifications, NotificationMethod and NotificationCondition enums, the TuiNotificationSettings struct, the two Display impls, Notifications' Default impl and the `terminal_title` field, each with its attributes (which may span lines) and doc comments, and answers null when a part is missing; `--selftest` needs no network | `python3 -B landscape_refresh.py [--selftest]` (needs `gh` signed in) |

Not retained: the incident host's paths and session identifiers, and the peer probe's scratch directory. The counts, names of
generic dotfiles and booleans are in the receipt.
