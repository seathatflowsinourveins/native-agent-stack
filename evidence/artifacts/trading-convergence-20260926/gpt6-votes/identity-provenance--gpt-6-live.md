The proposal needs changes. Its narrow DVC restore recommendation is defensible, but several rejection reasons contradict upstream documentation. This was a source and receipt review; I did not rerun acceptance trials.

1. **Iceberg does not inherently rewrite source Parquet files.** The pinned PyIceberg **0.12.0** documents `add_files`, which registers existing Parquet files without rewriting them. The comparison exercised `append`, so its result cannot establish structural impossibility. PyIceberg also supports a local SQLite catalog, although upstream limits that option to development use. Reevaluate byte preservation using `add_files`, with explicit retention and sidecar-file handling. Sources: [pinned API documentation](https://raw.githubusercontent.com/apache/iceberg-python/pyiceberg-0.12.0/mkdocs/docs/api.md), [catalog configuration](https://py.iceberg.apache.org/configuration/#sql-catalog).

2. **ArcticDB’s blanket rejection exceeds the experiment.** Its pinned API supports concurrent staged writes followed by one finalizer. The harness instead used concurrent `append` calls to one symbol, while DVC’s writers used separate directories. The receipt explicitly acknowledges that the supported ArcticDB path was untested. Its BSL restriction concerns a defined commercial third-party database service; the proposal has not shown that restriction disqualifies this personal research system. Reclassify ArcticDB as conditional and retain the unsafe-append finding. Sources: [v6.26.0 implementation](https://raw.githubusercontent.com/man-group/ArcticDB/v6.26.0/python/arcticdb/version_store/library.py), [license](https://raw.githubusercontent.com/man-group/ArcticDB/v6.26.0/LICENSE.txt), [comparison harness](blueprints/gap-wave2-20260923/us-equities__identity-provenance/store_arms.py:331).

3. **The OpenPM rejection contains two factual errors.** The paper explicitly links an available [code repository](https://github.com/aslcai/OpenPM-Bench) and [dataset](https://huggingface.co/datasets/aslcai/OpenPM-Bench). It describes IEX TOPS, SEC filings, FRED/ALFRED, GDELT and Finnhub inputs—not merely synthetic five-minute data. Its availability gates and provenance artifacts merit source review. Its narrow S&P 500 window and optimistic execution assumptions still prevent treating it as a qualified historical-data solution. Source: [paper, including Appendix A](https://arxiv.org/html/2608.09988v1).

4. **DVC earns the bounded restore claim, not demonstrated overall superiority.** Upstream documents restoration from its cache, consistent with the retained fixture. However, the comparison receipt explicitly says it did **not** execute the layer’s verdict-overturn protocol or `validate_source` rejection checks. Its storage comparison also excludes DVC’s 28,963-byte Git directory: ArcticDB/DVC is approximately **20.72×** using the quoted 10,887 bytes, or **5.66×** including that directory—not 18×. Neither tiny-fixture ratio establishes scaling. Also fix the JSON’s contradictory `iceberg-source-review-only: supported` check: the same proposal cites executed PyIceberg results. Sources: [DVC checkout](https://doc.dvc.org/command-reference/checkout), [comparison receipt and limitations](evidence/artifacts/gap-wave2-20260923/us-equities__identity-provenance/4-four-store-comparison.json:985).

5. **OpenLineage/MLflow additions are supportable only at the demonstrated integration scope.** FileTransport persistence is real, and MLflow’s pinned validation code confirms the 36-character digest limit. But the receipt validates the OpenLineage **core envelope**, not the unpublished custom facet schemas; its original all-events consistency criterion was amended after failure. Preserve those qualifications. Describe tamper detection as behavior of the project’s verifier, rather than an intrinsic guarantee of FileTransport. Sources: [OpenLineage configuration](https://openlineage.io/docs/client/python/configuration/), [custom facets](https://openlineage.io/docs/spec/facets/custom-facets/), [MLflow validation](https://raw.githubusercontent.com/mlflow/mlflow/v3.16.1/mlflow/utils/validation.py), [receipt limitations](evidence/artifacts/gap-wave2-20260923/us-equities__identity-provenance/5-openlineage-mlflow-bindings.json:390).

6. **Delta’s retention defaults are configurable, not a decisive capability limit.** Thirty-day log retention and seven-day deleted-file retention are defaults; `VACUUM` is not automatically triggered. Avoiding Spark is a reasonable implementation choice, but delta-rs supports the existing DuckDB/Polars path and deserves an explicit comparison disposition. Sources: [Delta retention documentation](https://docs.delta.io/delta-utility/), [delta-rs documentation](https://delta-io.github.io/delta-rs/latest/).

7. **Marquez and PermID need more precise rejection statuses.** Marquez’s old release is a legitimate maintenance concern, but its upstream documentation establishes dataset/job/run aggregation, lineage graphs and query APIs beyond local event-file persistence. “Refuted” is too strong without testing the required capability. Likewise, OpenPermID 0.5’s 2021 release establishes a stale **wrapper**, not an unmaintained underlying service. Historical collision coverage remains unverified. Sources: [Marquez release](https://github.com/MarquezProject/marquez/releases/tag/0.50.0), [Marquez README](https://raw.githubusercontent.com/MarquezProject/marquez/main/README.md), [OpenPermID PyPI](https://pypi.org/project/OpenPermID/), [official REST API guide](https://developers.lseg.com/content/dam/devportal/api-families/open-permid/permid-entity-search/documentation/permid-apis-user-guide-aug-2021.pdf).

8. **The proposal misses two strong comparison candidates.** **lakeFS**, already mentioned elsewhere in the repository, directly addresses versioned object snapshots, branching and rollback; evaluate its current source-available terms and operational cost. **DuckLake** fits DuckDB/Parquet and supports transactional registration of existing files without copying, plus time travel. Its maintenance operations can delete registered files, so retention needs qualification. Neither supplies missing historical identities. Sources: [lakeFS README](https://raw.githubusercontent.com/treeverse/lakeFS/master/README.md), [DuckLake file registration](https://ducklake.select/docs/stable/duckdb/metadata/adding_files), [DuckLake time travel](https://ducklake.select/docs/stable/duckdb/usage/time_travel).

9. **Replace stars-and-age rejection reasons with actual code findings.** I opened both small projects’ implementations. `backtest-bias.check_identity` uses advisory price-pattern heuristics and explicitly requires checking corporate-action records; it cannot establish permanent identity. `pit-adjuster` requires an external corporate-action archive, uses A-share defaults, and its core filters by ex-date while carrying `available_at` without comparing it. These are substantive limits requiring qualification; low popularity and unread code are not technical refutations. Sources: [backtest-bias implementation](https://raw.githubusercontent.com/Finance-broski/backtest-bias/main/backtest_bias/core.py), [pit-adjuster implementation](https://raw.githubusercontent.com/holdout-labs/pit-adjuster/main/src/pit_adjuster/chain.py).

10. **Several scope decisions survive review.** SocratiCode is code intelligence and should leave this layer. OpenFIGI’s documented interface does not provide the dated equity-identity windows required here; its `includeUnlistedEquities` option also makes “current-state only” an unnecessarily broad characterization. GX’s supported-source list omits DuckDB/Polars. Delta Sharing and Shingou remain poor fits for the stated historical-security-data obligation. None of these conclusions proves that every free alternative has been exhausted. Sources: [SocratiCode](https://raw.githubusercontent.com/giancarloerra/socraticode/main/README.md), [OpenFIGI API](https://www.openfigi.com/api/documentation), [GX compatibility](https://docs.greatexpectations.io/docs/help/compatibility_reference/), [Delta Sharing protocol](https://raw.githubusercontent.com/delta-io/delta-sharing/main/PROTOCOL.md), [Shingou’s stated boundaries](https://raw.githubusercontent.com/shingou-io/shingou-signal-log/main/README.md).

VERDICT: needs_changes
