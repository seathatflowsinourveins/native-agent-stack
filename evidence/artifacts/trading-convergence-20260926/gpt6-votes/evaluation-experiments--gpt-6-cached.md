The current tools can remain within their tested scopes, but several exclusions are factually wrong. I treated truncated checks as undelivered and independently inspected upstream sources and retained artifacts.

1. **FinSearchComp is runnable software, not paper-only.** Its repository provides installation instructions, inference and evaluation scripts, and complete and AkShare-compatible datasets. Reclassify it as an unqualified financial-agent benchmark candidate; publication age does not establish irrelevance. [Upstream repository](https://github.com/randomtutu/FinSearchComp).

2. **FinMCP-Bench also publishes code and data.** Alibaba’s DianJin-TIR includes inference runners and `eval/evaluation.py`; the authors publish the benchmark on Hugging Face. The actual constraints include its CC-BY-NC-SA-4.0 dataset license and Qieman tool dependencies. “No software here to install or pin” is false. [Evaluation implementation](https://github.com/aliyun/qwen-dianjin/tree/master/DianJin-TIR), [dataset and license](https://huggingface.co/datasets/DianJin/FinMCP-Bench).

3. **The other two paper-only exclusions are also unsupported.** Backtrader-Bench releases question datasets, generation pipelines and evaluation runners. Temporal Leakage releases analysis code, data, configurations and results. These remain candidates requiring qualification, but they are not merely methodology papers. Also, replace “clears five models” with bounded null findings: the Temporal Leakage paper explicitly distinguishes a null result from certification of no leakage. [Backtrader-Bench](https://github.com/rzhao999/Backtrader-Bench), [Temporal Leakage repository](https://github.com/ZeyuZhang1901/Temporal-Leakage-Backtesting), [paper](https://arxiv.org/html/2608.02985v1).

4. **The MTEB dismissal confuses the locally executed task with upstream capability.** The retained run exercised STSBenchmark; MTEB also evaluates retrieval. A particularly relevant omission is **FinMTEB**, whose financial retrieval tasks include FinanceBench, FiQA, Apple 10-K and FinQA. ARB’s Linux reproduction supports its code-retrieval scope; it does not settle the financial-document gap. [MTEB task overview](https://docs.mteb.org/overview/), [FinMTEB](https://github.com/yixuantt/FinMTEB), [financial task definitions](https://github.com/yixuantt/FinMTEB/blob/main/eval_instruction.py).

5. **Inspect’s measured advantage is narrower than the Promptfoo rejection.** I confirmed the retained 8-case comparison and the 30-case prediction agreement. The first establishes configuration-specific source-byte and retry-log advantages; the second uses one shared custom scorer and one startup-inclusive timing observation. These support retaining Inspect for those properties. They do not evaluate Promptfoo’s documented Claude Agent SDK and skill-use assertions. Preserve that distinction when declaring the challenger closed. [Promptfoo’s native agent/skill evaluation](https://www.promptfoo.dev/docs/providers/claude-agent-sdk/).

6. **Phoenix is mischaracterized.** Its upstream capabilities include versioned datasets, experiments, evaluators and prompt management—not merely trace inspection. Its Elastic license restricts providing substantial functionality to third parties as a hosted service; describing that as an internal self-hosting restriction is misleading. Conditional status remains defensible, but these rejection grounds need correction. [Datasets and experiments](https://arize.com/docs/phoenix/datasets-and-experiments/overview-datasets), [license](https://github.com/Arize-ai/phoenix/blob/main/LICENSE).

7. **TraderHarness’s license warning contradicts the packet’s own verification.** The delivered check says LICENSE, README and PyPI agree on Apache-2.0 and resolves `NOASSERTION` as a detector miss. The rejection nevertheless repeats “a real mismatch.” Remove that warning unless a specific conflicting grant is identified. Its China A-share scope remains a separate applicability concern. [License notice](https://github.com/HephaestLab/TraderHarness/blob/main/LICENSE), [upstream scope](https://github.com/HephaestLab/TraderHarness/blob/main/README_en.md).

8. **Apply the evaluation scope consistently.** River’s weak classifier accuracy does not refute its delayed-validation machinery; the retained causality control supports that machinery. Likewise, falsification-ledger supplies preregistration and evidence adjudication, while Lacuna supplies validation reports. These overlap the layer’s stated progressive-evaluation and validation-reporting scope. Limited maturity can justify deferral; stars, synchronized pushes and lack of broker isolation do not establish functional inferiority. [River implementation](https://github.com/online-ml/river/blob/main/river/evaluate/progressive_validation.py), [falsification-ledger](https://github.com/holdout-labs/falsification-ledger), [Lacuna](https://github.com/eyenoticeall/Lacuna).

9. **Additional relevant capabilities are omitted from this packet.** DeepEval provides explicit MCP-use and task-completion metrics; Ragas provides answer-correctness and tool-use evaluation. Both appear elsewhere in the repository, so they are not global discovery blind spots. Review them against the remaining semantic and MCP-evaluation gaps, rather than recycling the previously rejected argument about pytest versus YAML. Their availability warrants consideration, not automatic adoption. [DeepEval MCP evaluation](https://deepeval.com/docs/metrics-mcp-use), [Ragas metrics](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/answer_correctness/).

10. **Retain qualified winners without claiming universal superiority.** MLflow’s tracking receipt supports retention, and upstream confirms tracing and evaluation capabilities; that refutes the specific claim that MLflow lacks them, not Opik as a whole. Inspect’s tested 0.3.268 and published 0.3.269 should remain distinct acceptance states. Updating stale catalog text is justified, but the candidate corrections above make this more than housekeeping. [MLflow capabilities](https://github.com/mlflow/mlflow), [Opik capabilities](https://github.com/comet-ml/opik), [Inspect release history](https://pypi.org/project/inspect-ai/#history).
