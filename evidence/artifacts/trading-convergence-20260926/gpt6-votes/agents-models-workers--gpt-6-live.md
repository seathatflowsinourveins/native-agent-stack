1. **The winner/challenger standard is inconsistent.** Operational receipts justify retaining ai-memory and SocratiCode provisionally; they do not establish comparative superiority. Missing local comparisons cannot simultaneously justify their `earns_it` labels, reject memory challengers, and admit Claude Agent SDK without a task-level comparison. The repository itself explicitly distinguishes operational fit from retrieval superiority and says source-only candidates have not failed. [Recorded selection criteria](https://raw.githubusercontent.com/seathatflowsinourveins/native-agent-stack/19092db0/catalogs/landscape/us-equities.json).

2. **“Only catalog fields need refreshing” is false for ai-memory.** I checked the proposal’s cited revision, `19092db0`: it does record version 2.4.1, but its freshness note also says **seven changed Codex hook commands await `/hooks` re-trust**. Preserve that unresolved client-integration gate rather than describing the remaining work as documentation only. The upstream 2.4.1 release itself checks out. [Manifest](https://github.com/seathatflowsinourveins/native-agent-stack/blob/19092db0/manifests/stack.json), [upstream release](https://github.com/akitaonrails/ai-memory/releases/tag/v2.4.1).

3. **The OpenAI Agents SDK rejection overstates its authentication requirement.** It does not inherit Codex subscription entitlement, but trialing the SDK does **not inherently require a paid OpenAI API account**: official documentation supports non-OpenAI providers and disabling or replacing OpenAI tracing. A same-OpenAI-model comparison would require appropriate entitlement; that is a narrower constraint. Claude Agent SDK also documents API authentication and restrictions on offering subscription login through third-party products, so apply authentication criteria consistently. [OpenAI provider documentation](https://openai.github.io/openai-agents-python/models/), [Anthropic SDK documentation](https://code.claude.com/docs/en/agent-sdk/overview).

4. **Claude’s claimed freshness advantage compares different things.** An uninstalled candidate’s latest release is compared with Codex’s deliberately pinned installation. Codex 0.157.1 was released September 26; Claude SDK 0.2.160 was released September 25. Those dates establish neither superior maintenance nor task performance. Claude remains a plausible comparator, with a concrete hypothesis available: its changelog documents a fix for follow-up turns failing after background subagents. Use that behavior to motivate a trial. [Codex release](https://github.com/openai/codex/releases/tag/rust-v0.157.1), [Claude changelog](https://raw.githubusercontent.com/anthropics/claude-agent-sdk-python/v0.2.160/CHANGELOG.md).

5. **The proposed trial needs a corrected baseline and accounting contract.** The cited worker receipt already includes September 23 requalification with matching SDK/CLI 0.155.1 and successful scoped extraction. Those successes changed scope/permissions, so they do not establish equivalent read-only acceptance—but the September 19 failures are not the complete baseline either. The current wrapper also accepts `--turn-deadline-seconds`, not the cited `--deadline-seconds`. Freeze current models, prompts, tool roots, permissions and cache conditions across arms. Define usage aggregation explicitly: Claude documents different scopes for turn usage, subagents and resumed cumulative totals; “same receipt schema” alone does not make counts comparable. [Worker receipt](https://github.com/seathatflowsinourveins/native-agent-stack/blob/19092db0/blueprints/us-equities/workers/receipt.json), [wrapper](https://github.com/seathatflowsinourveins/native-agent-stack/blob/19092db0/blueprints/us-equities/workers/native_worker.py), [Claude usage semantics](https://code.claude.com/docs/en/agent-sdk/cost-tracking).

6. **Hindsight and Graphiti deserve explicit trial/deferred dispositions.** Hindsight’s paper reports 83.6% LongMemEval accuracy against 39.0% for its same-backbone full-context baseline. That is relevant comparative evidence, although it does not compare against ai-memory or establish financial-source fidelity. Graphiti documents bi-temporal history, fact invalidation, MCP integration and an embedded FalkorDB option—directly relevant to dated-source retrieval and deployment cost. Neither deserves adoption from these sources alone; neither has failed merely because this repository has not tested it. [Hindsight paper](https://arxiv.org/html/2512.12818v1), [Graphiti source documentation](https://raw.githubusercontent.com/getzep/graphiti/main/README.md).

7. **The conceptual-code-search sweep misses strong comparators.** **Claude Context** documents hybrid BM25/vector search, incremental indexing, Ollama embeddings and local Milvus. **codebase-memory-mcp** documents bundled semantic embeddings, SQLite BM25 and structural graph retrieval without a separate embedding service; it is already named in the repository’s alternatives. These warrant source review against SocratiCode’s specific requirements. Their advertised performance remains unverified here. [Claude Context](https://github.com/zilliztech/claude-context), [codebase-memory-mcp](https://github.com/DeusData/codebase-memory-mcp).

8. **Other material omissions span memory and workers.** **mcp-memory-service** offers local SQLite storage, scoped retrieval and Codex/Claude MCP integration. **OpenHands Software Agent SDK** offers programmable agents with local or isolated workspaces. **Pydantic AI Harness** documents bounded agent-call budgets and durable-execution integrations. These are candidates for scoped evaluation, with native authentication compatibility still to establish—not automatic replacements. [Memory service](https://github.com/doobidoo/mcp-memory-service), [OpenHands SDK](https://github.com/OpenHands/software-agent-sdk), [Pydantic AI Harness](https://github.com/pydantic/pydantic-ai-harness).

9. **Tighten the papers’ evidence descriptions.** Searching this repository cannot establish that public code is unavailable. Also, InKH explicitly reports only synthetic experiments; its public-data replay is specified but unexecuted. KTD-Fin principally addresses historical memorization through masking, rather than demonstrating a superior retrieval component. Keeping both as method references is reasonable, with those limits stated. [InKH](https://arxiv.org/html/2606.01886v1), [KTD-Fin](https://arxiv.org/html/2605.28359v1).
