1. **The trial plans reuse an already-inspected evaluation segment.** The referenced study explicitly says January–March 2021 cannot serve as a fresh holdout. Its outputs are raw-price labels, not portfolio returns or Sharpe. It also already uses a six-session exclusion; the library’s zero default does not describe that experiment. Reuse these inputs for regression checks, but preregister a separate evaluation before promoting LightGBM or an optimizer for predictive advantage. [Recorded experiment](https://github.com/seathatflowsinourveins/native-agent-stack/blob/main/blueprints/us-equities/research-evaluation/README.md).

2. **The EdgarTools failure is overstated.** Issue #1337 concerns `_extract_13f_section()` in the **MCP reader**: it incorrectly evaluates and iterates an existing `ThirteenF.holdings` DataFrame. It does not establish that native holdings acquisition fails or that every 13F-derived signal is affected. Version 5.59.1 fixes that reader and returns only the top 30 aggregated securities. Retaining EdgarTools is reasonable, but the upgrade rationale and acceptance check must name the affected interface. [Issue #1337](https://github.com/dgunning/edgartools/issues/1337), [release notes](https://github.com/dgunning/edgartools/releases/tag/v5.59.1).

3. **Qlib’s rejection applies a different standard from RD-Agent’s admission.** Qlib already implements daily IC/RankIC and a publication-date-aware PIT database for quarterly/annual fundamentals. Neither capability supplies a licensed historical US universe, but RD-Agent does not supply one either—and its financial research implementation uses Qlib. Keep the dataset gate separate from evaluating these research capabilities; “off-requirement” is inadequately supported. [IC implementation](https://raw.githubusercontent.com/microsoft/qlib/main/qlib/contrib/eva/alpha.py), [PIT documentation](https://qlib.readthedocs.io/en/latest/advanced/PIT.html), [RD-Agent implementation](https://raw.githubusercontent.com/microsoft/RD-Agent/v1.0.0/rdagent/scenarios/qlib/experiment/factor_experiment.py).

4. **Kronos is rejected partly through incumbency.** Its paper actually compares against Chronos and TimesFM, and its repository distributes pretrained financial OHLCV models through Hugging Face. Existing catalog entries do not demonstrate equivalent capability. The verified April 13, 2026 push also falls within the proposal’s twelve-month maintenance window; missing GitHub Release objects do not establish abandonment. Retain it as a conditional comparator, subject to pretraining-contamination checks and an independent US-market evaluation. [Paper](https://arxiv.org/html/2508.02739v1), [model distribution](https://github.com/shiyu-coder/Kronos), [repository metadata](https://api.github.com/repos/shiyu-coder/Kronos).

5. **AlphaInspect is a missed direct challenger to alphalens-reloaded.** It provides factor IC, quantile-return analysis and turnover reporting. PyPI records version 0.5.9 on October 23, 2025—newer than the cited June 2025 alphalens-reloaded distribution. This warrants comparison, not automatic adoption: its externally supplied forward returns and return-aggregation conventions need reconciliation with the frozen contract. [PyPI](https://pypi.org/project/alphainspect/), [report implementation](https://raw.githubusercontent.com/wukan1986/AlphaInspect/main/alphainspect/reports.py).

6. **The LightGBM shortlist misses XGBoost and CatBoost.** Qlib itself provides both as financial prediction baselines. In its published CSI300/Alpha158 results, XGBoost has higher IC and RankIC than LightGBM, although lower annualized return. Those results do not transfer automatically to this project, but they directly undermine selecting the comparator set through LightGBM’s dependency status. Include these contenders or give an explicit exclusion rationale. [Qlib benchmark results](https://github.com/microsoft/qlib/blob/main/examples/benchmarks/README.md).

7. **The skfolio update is justified, but its proposed verification is insufficient.** I confirmed the intervening releases and substantive VaR/EVaR fixes. Reproducing minimum-variance/HRP weights and Sharpe does not exercise those corrected risk calculations. Retain skfolio for demonstrated capabilities, qualify the exact new pin with the relevant unchanged upstream regressions, and avoid treating reproduction as comparative superiority. [Releases](https://github.com/skfolio/skfolio/releases), [VaR regression changes](https://github.com/skfolio/skfolio/pull/343/files), [EVaR regression changes](https://github.com/skfolio/skfolio/pull/359/files).

8. **PyPortfolioOpt and tsfresh receive inconsistent rejection standards.** PyPortfolioOpt’s optimizers can be evaluated using the same externally supplied chronological splits; lacking a bundled splitter does not disqualify the optimization role. Likewise, tsfresh documents rolling feature extraction—the named gap—so “we have not source-reviewed it” supports deferral, not substantive rejection, particularly when metadata-only challengers are admitted elsewhere. [PyPortfolioOpt](https://github.com/PyPortfolio/PyPortfolioOpt), [tsfresh forecasting documentation](https://tsfresh.readthedocs.io/en/stable/text/forecasting.html).

9. **FactorMiner’s negative search conclusion needs qualification.** I found an installable, MIT-licensed implementation at `minihellboy/factorminer`, with CLI, evaluation and research-memory functionality. I did **not** establish that it is the paper authors’ official implementation. Its documentation also discloses missing exact paper datasets and proxy baselines. Record it separately as an unqualified implementation candidate; replace the absolute “no installable code repository exists” claim. [Repository](https://github.com/minihellboy/factorminer), [reproduction limitations](https://raw.githubusercontent.com/minihellboy/factorminer/main/docs/reproducibility.md).
