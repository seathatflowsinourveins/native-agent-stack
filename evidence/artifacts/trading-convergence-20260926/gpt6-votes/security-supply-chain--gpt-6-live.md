The proposal needs revision. Its release pins check out, but several conclusions overlook later evidence. I independently opened upstream sources and matched 71 retained-output hashes. The supplied JSON is truncated mid-verification; this review covers the delivered content.

1. **The baseline is materially outdated.** September 23 receipts already record the 36-package SDK Grype scan, Syft/Grype signature verification, an OpenBao trial, a Grype/Trivy/OSV/pip-audit comparison, and expanded Gitleaks history coverage. Therefore, “never Grype-scanned,” “none has run,” and “no measured comparison” are incorrect for this checkout. Reconcile those historical, scoped results before proposing duplicate trials. Their limitations remain significant. [Retained receipts and results](https://github.com/seathatflowsinourveins/native-agent-stack/blob/720e294b5c10211d8f75a939bc478af734279d74/evidence/artifacts/gap-wave2-20260923/us-equities__security-supply-chain/README.md).

2. **The broker-authority discussion misses an observed enforcement gap.** Retained canary tests show broker-named environment variables reaching the SDK child and sandbox shells under the tested launch conditions. These were synthetic probes; they establish neither live credential contents nor successful broker access. Nevertheless, absent broker tools do not establish the claimed boundary. This evidence should drive the next authorization/environment-denial check. [Worker-boundary receipt](https://github.com/seathatflowsinourveins/native-agent-stack/blob/720e294b5c10211d8f75a939bc478af734279d74/evidence/artifacts/gap-wave2-20260923/us-equities__security-supply-chain/8-research-worker-broker-authority.json).

3. **Grype is incorrectly described as a required PR check.** The cited automation catalog explicitly sets both `required_check` and `target_required_check` to false for `sbom-vuln`, explaining its path filtering. The checked-in ruleset omits it. Retaining Syft/Grype for demonstrated tasks is defensible; this enforcement claim is not. Also, the current OSV inventory contains **43**, rather than 37, entries. [Automation catalog](https://github.com/seathatflowsinourveins/native-agent-stack/blob/720e294b5c10211d8f75a939bc478af734279d74/catalogs/foundation/automation.json), [ruleset](https://github.com/seathatflowsinourveins/native-agent-stack/blob/720e294b5c10211d8f75a939bc478af734279d74/.github/main-ruleset.json), [OSV inventory](https://github.com/seathatflowsinourveins/native-agent-stack/blob/720e294b5c10211d8f75a939bc478af734279d74/.github/osv-scanner-lockfiles.json).

4. **TruffleHog merits comparison, but its proposed acceptance criterion is ineffective.** Active verification establishes something about detected credentials; it cannot certify that no secrets exist. Matching zero true positives on a clean sample demonstrates little, and a revoked placeholder tests only a negative case. Use labeled detection fixtures, exact commit boundaries, and separately identified synthetic verification/error controls. Preserve the distinction between `unverified` and `unknown`. Also, `--no-verification` alone does not establish zero outbound traffic—the CLI separately provides `--no-update`. [Pinned TruffleHog documentation](https://github.com/trufflesecurity/trufflehog/blob/v3.97.9/README.md).

5. **The Trivy rationale confuses scan scope with tool capability.** Syft supports OS and multiple language ecosystems; Grype supports OS packages and languages including Rust. Their earlier Python-only inputs are not structural exclusions. Scanning the same venv with Trivy cannot establish coverage of host packages outside it. The existing comparison already found matching inventories across 21 packages; its zero-finding agreement does not establish superior recall. [Syft](https://github.com/anchore/syft/blob/v1.52.0/README.md), [Grype](https://github.com/anchore/grype), [comparison receipt](https://github.com/seathatflowsinourveins/native-agent-stack/blob/720e294b5c10211d8f75a939bc478af734279d74/evidence/artifacts/gap-wave2-20260923/us-equities__security-supply-chain/7-scanner-comparison.json).

6. **Scorecard cannot close the scanner-comparison gap.** Its scores assess security-practice heuristics, not vulnerability-detection accuracy, SBOM completeness, or secret-scanning recall. Add it as upstream-project risk evidence if useful, but keep that measurement separate from scanner performance. [Scorecard’s stated methodology](https://github.com/ossf/scorecard/blob/v5.5.0/README.md).

7. **The Cosign trial assumes the wrong artifact format.** Both pinned Anchore installers verify signed **checksum files** using certificates and signatures, then bind archives through their hashes. They specify an exact release-workflow identity. The proposed per-artifact `.sigstore.json` command and broad repository-prefix regex should be replaced with the actual publisher procedure—or the existing receipt reused. Signature authentication also does not, by itself, establish build provenance. [Syft installer](https://github.com/anchore/syft/blob/v1.52.0/install.sh), [Grype installer](https://github.com/anchore/grype/blob/v0.119.0/install.sh).

8. **OpenBao’s proposed KV “lease” test conflates different controls.** OpenBao explicitly states that arbitrary KV secrets do **not** receive leases. Revoking a token can prevent subsequent retrieval; it does not invalidate an already retrieved broker credential at its provider. Separate KV access/versioning tests from provider-backed issuance, rotation, and revocation. The existing 2.6.2 trial establishes scoped historical behavior; 2.7.0 availability does not erase it. [OpenBao lease semantics](https://openbao.org/docs/concepts/lease/), [existing trial](https://github.com/seathatflowsinourveins/native-agent-stack/blob/720e294b5c10211d8f75a939bc478af734279d74/evidence/artifacts/gap-wave2-20260923/us-equities__security-supply-chain/6-openbao-secret-lifecycle.json).

9. **Cisco and Docker deserve stronger source-reviewed treatment.** Cisco’s pinned documentation provides static, offline YARA scanning without API keys, making it a concrete bounded challenger. Docker’s pinned security document confirms both configurable egress restrictions and rejection of tool-name collisions. These are no longer merely third-party claims. Docker also explicitly says egress is not globally denied by default. Neither documentation claim constitutes local acceptance. [Cisco 4.8.4](https://github.com/cisco-ai-defense/mcp-scanner/blob/4.8.4/README.md), [Docker v0.44.1 security model](https://github.com/docker/mcp-gateway/blob/v0.44.1/docs/security.md).

10. **ToolHive is a strong missing challenger.** Its documented permission profiles, configured authentication, Cedar authorization, and audit middleware directly address the MCP-authority question. Compare it against Docker using allowed/denied operations and bypass tests before selection. For the separate provenance gap, consider **SLSA Verifier** where upstream artifacts publish compatible provenance; it evaluates source/build expectations beyond a checksum signature. [ToolHive v0.51.1 architecture](https://github.com/stacklok/toolhive/blob/v0.51.1/docs/arch/02-core-concepts.md), [SLSA Verifier](https://github.com/slsa-framework/slsa-verifier).

11. **Several rejection rationales need correction even where deferral remains reasonable.** Snyk’s token prerequisite is confirmed. Warpgate supports noninteractive connections, so “HUMAN” is too restrictive. Dependabot supports security updates, and Trail of Bits supplies workflows using actual analyzers. TradeMemory has implemented timestamp-client code and documented limitations, warranting source review rather than a description-only dismissal. The trading-policy paper is reasonably excluded on scope; its age does not establish “unmaintained.” [Snyk](https://github.com/snyk/agent-scan/blob/v0.6.4/README.md), [Warpgate](https://github.com/warp-tech/warpgate), [Dependabot](https://github.com/dependabot/dependabot-core#debugging-security-updates), [Trail of Bits](https://github.com/trailofbits/skills), [TradeMemory limitations](https://github.com/mnemox-ai/tradememory-protocol/blob/master/LIMITATIONS.md), [paper](https://arxiv.org/abs/2010.11388).
