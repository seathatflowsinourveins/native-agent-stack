1. **FactorMiner’s “no code repository exists” rejection is false as written.** A public implementation provides an MIT license, Python packaging, installation instructions, and factor-mining workflows. Its equivalence to the paper’s original implementation remains unverified; admit it for source review rather than treating code availability as settled. [Repository](https://github.com/minihellboy/factorminer), [packaging](https://github.com/minihellboy/factorminer/blob/main/pyproject.toml).

2. **RD-Agent has an omitted correctness defect.** Its published bandit code looks up the annualized-return metric with a trailing space, defaulting to zero. The derived “Sharpe” also becomes zero—and actually computes return/drawdown. The corrective PR remains open. Require metric-extraction acceptance before the proposed performance trial; release count does not establish maturity. [Source](https://github.com/microsoft/RD-Agent/blob/main/rdagent/scenarios/qlib/proposal/bandit.py), [fix PR](https://github.com/microsoft/RD-Agent/pull/1479).

3. **Qlib’s rejection is inconsistent with accepting RD-Agent(Q).** Qlib supplies the underlying research platform and already implements date-grouped IC and Spearman rank IC. Missing licensed US data remains a shared evaluation gate; it does not make Qlib functionally irrelevant while its dependent qualifies. Preserve a conditional role and reassess the claimed factor-IC gap. [IC implementation](https://github.com/microsoft/qlib/blob/main/qlib/contrib/eva/alpha.py), [RD-Agent integration](https://github.com/microsoft/qlib/blob/main/README.md).

4. **The skfolio/Riskfolio trial misstates existing acceptance.** The local frozen plan configures `purged_size=6`; zero is the upstream default, not that experiment’s configuration. Its reserved 2021Q1 segment is explicitly already inspected. Reuse it for regression checks, not fresh superiority evidence. The VaR/EVaR fixes support updating skfolio, but reproducing variance-optimizer Sharpe alone does not exercise those fixes or establish a comparative winner. [WalkForward contract](https://skfolio.org/generated/skfolio.model_selection.WalkForward.html), [VaR fix](https://github.com/skfolio/skfolio/pull/343), [EVaR fix](https://github.com/skfolio/skfolio/pull/359).

5. **EdgarTools’ alleged 13F blast radius is overstated.** The release establishes failure of the `edgar_read` holdings section, not failure of every underlying 13F SDK workflow. Its repaired section lists only the top 30 securities. Retaining EdgarTools remains defensible, but qualify the affected interface explicitly and distinguish its summary from complete holdings extraction. [Release notes](https://github.com/dgunning/edgartools/releases/tag/v5.59.1).

6. **Alphalens’ trial omits a documented leakage hazard.** Its forward-return helper defaults to `filter_zscore=20`; upstream explicitly warns that this filtering introduces lookahead bias. Freeze supplied labels or disable that filter, verify IC by date, and check quantile returns and turnover separately. Matching one correlation does not qualify the complete tear sheet. [Forward-return implementation](https://github.com/stefan-jansen/alphalens-reloaded/blob/main/src/alphalens/utils.py), [IC implementation](https://github.com/stefan-jansen/alphalens-reloaded/blob/main/src/alphalens/performance.py).

7. **AlphaInspect is a missed direct challenger to Alphalens.** It provides Polars-based rank IC, factor-return and turnover analysis, with an MIT-licensed PyPI release dated October 23, 2025—newer than the proposal’s Alphalens release. Its equal-weight and cost-exclusion limitations require evaluation, but “no fresher alternative found” is no longer supportable. [Repository](https://github.com/wukan1986/AlphaInspect), [PyPI](https://pypi.org/project/alphainspect/).

8. **Kronos’ rejection relies partly on incumbency.** Five months without a push does not breach the proposal’s twelve-month rule, and pretrained weights are distributed through Hugging Face despite absent GitHub Release objects. Financial OHLCV tokenization supplies a concrete comparison hypothesis against generic forecasting baselines. Existing catalog coverage alone does not refute it. [Upstream architecture and model releases](https://github.com/shiyu-coder/Kronos/blob/master/README.md).

9. **PyPortfolioOpt and tsfresh receive unequal evidence standards.** PyPortfolioOpt implements the relevant portfolio optimizers and can consume externally generated chronological splits; lacking its own splitter is not categorical disqualification. tsfresh documents sklearn-compatible extraction and selection pipelines. “Not previously reviewed” warrants investigation, not rejection, especially when metadata-only challengers are admitted. [PyPortfolioOpt](https://github.com/PyPortfolio/PyPortfolioOpt), [tsfresh integration](https://tsfresh.readthedocs.io/en/latest/text/sklearn_transformers.html).

10. **The comparison set remains incomplete.** Qlib itself supplies XGBoost and CatBoost benchmarks alongside LightGBM, so Qlib usage does not uniquely justify LightGBM. Cvxportfolio also deserves screening for portfolio research involving transaction costs, turnover constraints and multiperiod optimization. These are candidates for bounded comparisons, not demonstrated replacements. [Qlib model zoo](https://github.com/microsoft/qlib/tree/main/examples/benchmarks), [Cvxportfolio documentation](https://www.cvxportfolio.com/en/stable/).
