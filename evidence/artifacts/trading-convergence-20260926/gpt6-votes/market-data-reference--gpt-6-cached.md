VERDICT: needs_changes

1. **The winner claims exceed the comparative evidence.** I confirmed the published versions of [alpaca-py 0.44.0](https://pypi.org/project/alpaca-py/) and [exchange_calendars 4.13.2](https://pypi.org/project/exchange_calendars/). The retained acquisition demonstrates a working ingestion path; bar counts and matching hashes do not establish survivorship coverage, historical availability, or superiority over untested providers. Scope `earns_it` to demonstrated capabilities.

2. **“Never run side by side” is demonstrably false for calendars.** The [retained comparison output](evidence/artifacts/gap-wave2-20260923/us-equities__market-data-reference/raw/6-calendar-check.fix1.json) matches its receipt hash and records **3,016 sessions, 24 early closes, and zero open/close disagreements** between exchange_calendars XNYS and pandas_market_calendars NYSE. It also records substantial IEX discrepancies. Reuse this historical integration evidence. Specify PMC’s native `NYSE` calendar: its documentation explicitly says it also [mirrors exchange_calendars calendars](https://pandas-market-calendars.readthedocs.io/en/latest/), making an unspecified “XNYS arm” vulnerable to circular comparison.

3. **The CRSP rejection mistakes one distributor’s restrictions for the product’s limits.** CRSP’s current owner explicitly serves investment practitioners and financial firms, and lists flat files, programming libraries, Linux access, Snowflake and managed file transfer alongside WRDS. Reclassify this as **subscription eligibility, cost and license review pending**, rather than an established commercial-use prohibition. [Primary source](https://indexes.morningstar.com/research-data-products).

4. **The fedfred rejection is factually wrong.** Its documented observation method accepts `realtime_start`, `realtime_end`, `vintage_dates`, and output modes for initial releases and revisions; it also exposes vintage-date discovery. It warrants a bounded macro-vintage comparison. This establishes documented capability, not completed acceptance. [Observations API](https://nikhilxsunder.github.io/fedfred/api/_autosummary/fedfred.FredAPI.get_series_observations.html), [vintage-date API](https://nikhilxsunder.github.io/fedfred/api/_autosummary/fedfred.FredAPI.get_series_vintagedates.html).

5. **Massive deserves a conditional trial under the same standard applied to Databento and Sharadar.** Its documented dividends response contains the specifically missing **currency** field, while its ticker endpoint supports historical-date queries and delisted status. Rejecting it because its free tier lacks deep history is asymmetric when paid challengers remain eligible. These features still require coverage and entitlement validation. [Dividends schema](https://massive.com/docs/rest/stocks/corporate-actions/dividends), [ticker reference](https://massive.com/docs/rest/stocks/tickers/all-tickers).

6. **Norgate’s operational rejection is overstated.** It has a documented Python interface, including historical index-constituent queries; its package documentation explicitly supports Python running under WSL2 with mirrored networking. The Windows updater remains required. Its overview also permits historical-price exports, although other features and post-subscription rights require separate examination. Replace “no API” with the actual local-service constraint. [Python package documentation](https://pypi.org/project/norgatedata/), [vendor access limitations](https://norgatedata.com/).

7. **The EdgarTools 13F failure is exaggerated, and the proposed comparison needs normalization.** Version 5.59.1 fixes the `edgar_read` holdings-output path; that does not establish that every 13F parsing path was broken. Its repaired output shows the **top 30 securities**, and the release explicitly distinguishes securities from information-table rows. Comparing that output directly with complete holdings can manufacture discrepancies. Test parser extraction and tool presentation separately, with explicit units, aggregation and amendment handling. The stale-pin finding itself is supported. [5.59.1 release](https://github.com/dgunning/edgartools/releases/tag/v5.59.1), [5.59.0 correctness changes](https://github.com/dgunning/edgartools/releases/tag/v5.59.0).

8. **The Databento trial does not establish the historical-availability claim it targets.** Its corporate-actions API defaults to `pit=False`, returning the latest revision. Repeated identical downloads can therefore reproduce hindsight consistently. Require `pit=True`, an explicit knowledge-time cutoff and revision-selection rule, and checks against retained source events. The proposed bars/corporate-actions comparison also leaves its claimed halt/LULD advantage untested. [Reference API and PIT semantics](https://databento.com/docs/api-reference-reference).

9. **Sharadar’s trial has an unnecessary purchase gate and an unsupported acceptance condition.** Sharadar documents a public AAPL sample key and its own REST API, so a bounded sample investigation can start without purchasing NDL access. Its published actions schema has **no currency column**, already weakening the proposed dividend-currency test. Score fundamentals and corporate actions separately. AR dimensions use filing **dates**, with scheduled delivery and reporting lag; that does not establish intraday availability timestamps. [Sample access](https://sharadar.com/docs/auth), [actions schema](https://sharadar.com/docs/actions), [fundamentals timing](https://sharadar.com/docs/fundamentals).

10. **OpenBB’s license is explicit.** Its LICENSE declares AGPLv3. GitHub returning `NOASSERTION` does not make that declaration ambiguous. A provenance or duplication argument may justify deferral, but the proposal should identify concrete license requirements for the intended deployment. [Repository LICENSE](https://raw.githubusercontent.com/OpenBB-finance/OpenBB/develop/LICENSE).

11. **Two strong omitted comparison baselines deserve evaluation.** **Arelle** offers an Apache-2.0 XBRL processor, Python/CLI interfaces, standards validation and SEC filing-rule support—an appropriate independent comparator for EdgarTools’ numeric XBRL extraction. **The SEC’s own Form 13F datasets** provide flattened as-filed holdings without a commercial intermediary. Their quarterly publication and documented extraction corrections must remain separate from original filing availability. [Arelle documentation](https://arelle.readthedocs.io/en/latest/), [SEC datasets](https://www.sec.gov/data-research/sec-markets-data/form-13f-data-sets).

12. **Some exclusions remain defensible, but the verification record needs qualification.** [yfinance](https://raw.githubusercontent.com/ranaroussi/yfinance/main/README.md) explicitly describes unofficial access and personal-use restrictions; [FinanceDatabase](https://raw.githubusercontent.com/JerBouma/FinanceDatabase/main/README.md) describes a symbol/classification catalog rather than historical-universe evidence. I could not independently reopen Rossod4’s repository. Moreover, [PyPI’s `quantlab`](https://pypi.org/project/quantlab/) is a different, BSD-licensed notebook project from 2017; its metadata cannot substantiate the proposal’s Rossod4 license claim.
