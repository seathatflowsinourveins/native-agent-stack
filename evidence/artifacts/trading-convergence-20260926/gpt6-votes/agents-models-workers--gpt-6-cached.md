The proposal needs changes to its selection criteria and trial plan. I checked upstream sources and inspected local evidence at its cited revision, `19092db0`; I did not run new model comparisons.

1. **The proposed worker comparison uses superseded evidence and is not ready to execute.** The worker receipt already records September 23 successes for root-scoped research, extraction with automatic approval review, and resumed-thread retrieval. Calling the older extraction failures “currently blocked” omits those results. The suggested command also uses obsolete `--deadline-seconds`; the runner accepts `--turn-deadline-seconds`. Meanwhile, OmniRoute’s fixture supplies the answers in its prompt and explicitly forbids tools. It cannot establish equivalent file-extraction capability. Freeze a common task and permission configuration before comparing. Sources: [requalification receipt](blueprints/us-equities/workers/receipt.json:222), [runner](blueprints/us-equities/workers/native_worker.py:255), [OmniRoute request](blueprints/us-equities/routing/omniroute-astra-request.json).

2. **The winner/rejection standard favors incumbents.** Absence of matched comparisons supports retaining an operational baseline; it does not establish comparative superiority for ai-memory or SocratiCode, or justify rejecting untested alternatives. Claude Agent SDK likewise has no retained local trial, yet receives challenger status. Apply the same admission standard throughout: operationally qualified incumbent, credible challenger, unqualified candidate, or demonstrated rejection. The repository itself explicitly distinguishes operational fit from a recall or cost win. Sources: [existing catalog](catalogs/landscape/us-equities.json:3388), [ai-memory upstream](https://github.com/akitaonrails/ai-memory).

3. **Claude Agent SDK’s claimed freshness advantage is invalid.** Codex `0.157.1` was released September 26; Claude Agent SDK `0.2.160` on September 25. Comparing an installed Codex pin with a freshly selected Claude version measures local adoption lag, not superior upstream maintenance. Claude remains a credible trial candidate: its release fixes follow-up failures involving hooks, permission callbacks and SDK MCP servers—a concrete hypothesis worth testing. Sources: [Codex release](https://github.com/openai/codex/releases/tag/rust-v0.157.1), [Claude SDK release](https://github.com/anthropics/claude-agent-sdk-python/releases/tag/v0.2.160).

4. **The OpenAI Agents SDK rejection overstates its authentication requirement.** It does not inherently require a paid OpenAI API entitlement: official documentation supports other model providers and explains operation without an OpenAI platform key, including disabling tracing. That does **not** confer Codex subscription entitlement. Nine days between releases is also insufficient evidence of poor maintenance. Assess a specified provider configuration and required capabilities. Sources: [provider documentation](https://openai.github.io/openai-agents-python/models/), [September 17 release](https://github.com/openai/openai-agents-python/releases/tag/v0.22.3).

5. **Hindsight and Graphiti merit conditional challenger status.** Hindsight’s paper reports 91.4% on LongMemEval, and upstream documents coding-agent integrations and local providers. Graphiti explicitly implements bi-temporal tracking and fact invalidation, directly relevant to dated-source retrieval. These do not prove superiority on this stack, but supply stronger trial hypotheses than release cadence alone. “Not tested here” is an acceptance gap, not a failed candidate. Sources: [Hindsight paper](https://arxiv.org/abs/2512.12818), [Hindsight implementation](https://github.com/vectorize-io/hindsight), [Graphiti](https://github.com/getzep/graphiti).

6. **The conceptual-code-search sweep missed substantial competitors.** Semble offers CPU-only semantic/BM25 retrieval through MCP; grepai supplies local embeddings, file watching and call graphs; ChunkHound provides semantic search and source-cited code research. SocratiCode’s uncontested status therefore reflects incomplete coverage. Semble also publishes comparative evaluation code, although its queries and relevance labels are generated and judged by the same LLM—useful upstream evidence, not an independent holdout. Sources: [Semble](https://github.com/MinishLab/semble), [benchmark methodology](https://github.com/MinishLab/semble/blob/main/benchmarks/README.md), [grepai](https://github.com/yoanbernabeu/grepai), [ChunkHound](https://github.com/chunkhound/chunkhound).

7. **The memory sweep omitted close requirement matches.** `mcp-memory-service` documents local storage, local embeddings and cross-client MCP access. Basic Memory supplies Markdown-backed knowledge, hybrid retrieval and native Claude/Codex integration. Basic Memory and OpenViking are already listed in the repository’s candidate set but disappear from this proposal’s dispositions. Evaluate them explicitly before calling the sweep sufficient. Sources: [mcp-memory-service](https://github.com/doobidoo/mcp-memory-service), [Basic Memory](https://github.com/basicmachines-co/basic-memory), [OpenViking](https://github.com/volcengine/OpenViking).

8. **GitHub Copilot SDK is a missed native-worker comparator.** Its official SDK exposes the Copilot CLI engine, supports Python and other languages, and documents native CLI authentication, subscription billing and BYOK. That directly addresses the proposal’s native-runtime/authentication criteria. Account availability and matched sandbox enforcement remain trial prerequisites; neither capability nor superiority should be assumed. Source: [official Copilot SDK](https://github.com/github/copilot-sdk).

9. **“Only two catalog fields need refreshing” overstates ai-memory’s acceptance.** At the proposal’s cited revision, the manifest records a host-specific `2.4.1` cutover, seven Codex hooks awaiting re-trust, and a Mac pin remaining at `2.3.2`. Upstream `2.4.1` exists, but release freshness is not complete cross-client or cross-host qualification. Preserve those boundaries in `winner_status`. Sources: [cited manifest revision](https://github.com/seathatflowsinourveins/native-agent-stack/blob/19092db0/manifests/stack.json#L135), [upstream release](https://github.com/akitaonrails/ai-memory/releases/tag/v2.4.1).

10. **Narrow the paper claims; retain justified scope exclusions.** KTD-Fin studies market-knowledge leakage and return attribution, not project-memory retrieval quality. InKH explicitly evaluates a synthetic architecture benchmark. Keeping both as methodological references is reasonable; absence from local catalogs cannot establish absence of public code. TradeMemory’s maintenance status and TradingAgents’ trading-framework scope are independently supported, so their exclusion from this particular replacement trial is defensible. Sources: [KTD-Fin](https://arxiv.org/abs/2605.28359), [InKH](https://arxiv.org/abs/2606.01886), [TradeMemory](https://github.com/mnemox-ai/tradememory-protocol), [TradingAgents](https://github.com/TauricResearch/TradingAgents).

VERDICT: needs_changes
