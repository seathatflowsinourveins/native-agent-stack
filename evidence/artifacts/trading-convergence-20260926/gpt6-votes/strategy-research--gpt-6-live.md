VERDICT: needs_changes

1. **The empty winner list is justified; the blanket continuation rejection is not.** The 0/1,012 result establishes failure of the tested rules under their data and cost assumptions. It does not falsify all early-entry continuation strategies. V3 remains an unfrozen draft. [Study results](https://github.com/seathatflowsinourveins/native-agent-stack/blob/main/blueprints/us-equities/mover-early-entry/README.md), [V3 protocol](https://github.com/seathatflowsinourveins/native-agent-stack/blob/main/blueprints/us-equities/mover-v3/protocol-core-draft.json).

2. **NoEdge-Bench’s proposed acceptance criterion is invalid.** Failing to distinguish results from a permutation null does not establish absence of leakage or implementation bugs. Conversely, distinguishability can reflect genuine predictability. The upstream implementation is a synthetic IID-feed classification demonstration using 60 permutations, not a general strategy-integrity auditor. Separate causality checks from statistical significance. An omitted, better-matched comparator for the expanded strategy search is **arch’s SPA/StepM**, which supports block bootstraps and multiple comparisons. [NoEdge source](https://github.com/nexusfinancial-dev/noedge-bench/blob/v1.0.0/noedge_bench.py), [StepM documentation](https://arch.readthedocs.io/en/stable/multiple-comparison/generated/arch.bootstrap.StepM.html).

3. **The exitkit/riskkit trials cannot call the existing validation split “untouched.”** Its outcomes are already reported and inform this proposal. New exit and sizing searches require a new preregistered selection procedure and genuinely reserved evaluation. The stated “200 trades, positive mean” criterion also omits V1’s significance requirement, adjusted validation test, and robustness conditions. Preserve those requirements explicitly. [Published outcomes](https://github.com/seathatflowsinourveins/native-agent-stack/blob/main/blueprints/us-equities/mover-early-entry/README.md), [Original acceptance criteria](https://github.com/seathatflowsinourveins/native-agent-stack/blob/main/blueprints/us-equities/mover-early-entry/protocol.json).

4. **exitkit’s proposed adapter does not faithfully implement all its policies.** At `v0.1.0`, partial and scaling policies emit `partial_ratio`/`scaling_ratio`, but the adapter unconditionally calls `trade.close()`. That API defaults to closing the entire trade. Therefore, the proposed adapter cannot substantiate a comparison of all 27 advertised policies without correction and execution-semantic checks. [Policy source](https://github.com/charlieyanhx/exitkit/blob/v0.1.0/exitkit/take_profit.py), [Adapter](https://github.com/charlieyanhx/exitkit/blob/v0.1.0/exitkit/adapters/backtesting_py.py), [Trade.close implementation](https://github.com/kernc/backtesting.py/blob/master/backtesting/backtesting.py).

5. **The custom orderflow-metrics port is unnecessary.** The exact `v0.40.0` upstream Python implementation already provides the proposed OFI, VPIN, volume buckets, Kyle’s lambda, tick rule, Lee–Ready, and depth-imbalance functions. A newer npm version does not establish a missing Python capability. Evaluate the supported Python package before proposing another implementation. [Versioned Python documentation](https://github.com/twowaymind/orderflow-metrics/blob/v0.40.0/python/README.md), [Python exports](https://github.com/twowaymind/orderflow-metrics/blob/v0.40.0/python/src/orderflow_metrics/__init__.py).

6. **“No author code exists” for ClusterLOB is false.** The paper’s first footnote links the authors’ repository, which contains `cluster_lob.py`, `main.py`, and `metric.py`. Replace the from-scratch implementation plan with a review of that implementation. Its results still require qualification for the mover population, licensed data, and realistic execution. [Full paper](https://arxiv.org/html/2504.20349v3), [Author repository](https://github.com/YichiZhang-Oxford/ClusterLOB).

7. **Wiseek’s dataset size and reproducibility are overstated.** Its August metadata reports **8,357 archived event rows**, before exclusions and deduplication; **13,760** is the measured T+1 aggregate count across scores. Scores 1–6 lack event-level rows. The metadata also records late captures, a `move_cap_300` exclusion, and a benchmark panel fixed at month-end. These affect extreme-mover coverage and point-in-time interpretation; price-series agreement alone is insufficient acceptance. [Release metadata](https://github.com/WiseekAI/wiseek-datasets/blob/main/data/2026-08/meta.json).

8. **The TLM rejection rests on an incomplete reading.** Sections 5.2–5.3 provide datasets, chronological splits, and numerical results: 2,070 earnings calls, 414 test observations, and reported 58% accuracy, plus an overnight-gap experiment. However, it still warrants scrutiny: under conventional positive-class definitions, Table 5’s precision, recall, and class balance imply approximately **45.8% accuracy**, not 58%. Correct the rejection to unresolved reproducibility/metric consistency rather than absent results. [Full paper and tables](https://arxiv.org/html/2607.21625v1).

9. **The LPPLS trial risks hindsight selection.** Selecting eventual ≥100%/≥200% winners and fitting “pre-peak windows” can establish retrospective fit without demonstrating an executable exit. Specify window endpoints using information available at decision time, include failed candidates, and evaluate net outcomes. The cited MAX paper concerns monthly cross-sectional returns; it does not validate intraday peak timing. [LPPLS methodology](https://github.com/Boulder-Investment-Technologies/lppls), [Original MAX paper](https://pages.stern.nyu.edu/~rwhitela/papers/max%20jfe11.pdf).

10. **A substantial omitted strategy comparator is the Stocks-in-Play ORB study.** Zarattini–Barbon–Aziz specify US-equity selection using opening relative volume, breakout entries, ATR stops, risk-based sizing, a leverage cap, and session-end exits. This merits comparison against the claim that only a crypto system has the combined structure. It also differs materially from V2’s ≥20% gap-up universe and range-low stops. Treat it as a replication candidate; its reported performance does not establish +200% detection or accepted execution realism. [Author-hosted paper, §§2–4](https://concretumgroup.com/wp-content/uploads/2026/02/A-Profitable-Day-Trading-Strategy-For-The-U.S.-Equity-Market.pdf).

11. **Broker-held exit acceptance is incorrectly presented as existing behavior.** The cited September 24 sweep explicitly records `native_execution: none`; the current adapter accepts only LIMIT/DAY orders. Alpaca’s documentation also says trailing stops do not trigger outside regular hours and cannot currently serve as bracket/OCO stop legs. Rewrite “already go through” as a proposed, unqualified execution path. [Sweep receipt](https://github.com/seathatflowsinourveins/native-agent-stack/blob/main/catalogs/us-equities/mover-v3-sweep-20260924.json), [Adapter](https://github.com/seathatflowsinourveins/native-agent-stack/blob/main/blueprints/us-equities/adaptive-paper/native_adapter.py), [Alpaca documentation](https://docs.alpaca.markets/us/docs/orders-at-alpaca).
