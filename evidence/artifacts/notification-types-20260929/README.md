# Notification types, the push notification bell and tmux (2026-09-29)

The checks behind the "Update 2026-09-29 (late)" section of [the terminal decision](../../../docs/decisions/2026-09-28-terminal-experience.md) and its
[receipt](../../receipts/notification-types-20260929.json). Each is read-only apart from the private temporary directories it removes (the replacement script writes only
the settings file it is pointed at, after a backup, and only with `--apply`); each prints booleans, counts and generic names only. Run them with `python3 -B` so no
`__pycache__` appears here. Each was run on the workstation the receipt names.

| Script | What it measures | How it was run |
| --- | --- | --- |
| `notification_types_scan.py` | Every Notification type the installed native Claude Code binary knows: the matcher values of the Notification event (a 15-item base array plus `elicitation_complete` and `elicitation_response`, resolved through the catalog's spread identifier: the array literal assigned to that name as a complete initializer, exactly one, never an array chosen by its contents or length; a member assignment such as `obj.<name>=[...]` is another variable, also through whitespace or a comment (`obj. <name>`); every place the client declares a matcher catalog must be one the reader recognizes, so an unsupported second catalog fails the scan instead of being ignored; documented limits that the three release binaries do not trigger: scope is not resolved (a plain assignment of the same short name in another scope beside a parameterized catalog would be taken for it) and a later mutation of the array (`.push`) is invisible to a static read; `$` is allowed in the minified name, as `P$o` in 2.1.283) and the `notificationType:"<type>"` literals at emitting call sites (a lower bound: other emit sites use other spellings). It holds `DECISIONS`, the one table the repository's test also imports: each type is `ring` or `quiet`, with whether the hooks reference documents it and its reason. The script exits 1 on a type with no entry (`UNKNOWN`), on a decision that disagrees with the overlay's matcher, and on a reader that finds no base array or no catalog (a scan that reads nothing must not pass) | `python3 -B notification_types_scan.py [<binary>] <checkout>` (from a checkout; the default binary is `~/.local/bin/claude`) |
| `scan_reader_mutants.py` | Negative controls for the scan's reader: on each release binary named on the command line, the catalogs the reader resolved (spread name, array assignments found, base size) and the matcher values read, and the repository's `ScanReaderTests` (twelve tests) run against eleven mutated copies of the scan (no `$` in the name, an exit code that ignores a blind reader, the base taken from any array, a property assignment counted as the catalog's array, member access through whitespace or a comment not recognized, a suffix after the array accepted, an unsupported catalog beside a supported one not counted, a `Set` counted as an array, two assignments accepted, only the first catalog counted, a base without the required names); each mutant must make exactly the named tests fail | `python3 -B scan_reader_mutants.py <checkout> [<release binary> ...]` |
| `push_notification_probe.py` | Whether a model-initiated PushNotification raises a `Notification` hook event, of which type, whether a bell hook for that type rings, and which branch of the client's presence rule decided (the terminal's focus report when it has reported focus, otherwise input within the last 60 s; read from the binary). A real interactive session in a pty (Haiku); its BEL counter decodes UTF-8 and ignores C1 characters, SIGINT, SIGTERM and SIGHUP remove the raw payload directory and stop the client (a handler only latches the first signal and the probe then ends BY it, as in `alert_probe.py`; `terminal-experience-20260928/pty_probe_mutants.py` covers this probe too), the hooks-disabled control exits 1 on a BEL like `alert_probe.py` (an end-to-end case checks the real exit status), the run exits 2 when the tool call was never observed, and it prints message lengths, not message text (the screen tail only with `--show-screen`); the model runs `sleep N`, then calls the tool; the probe waits for the client to enable focus reporting before it types, prints whether it sent a focus-out report and the seconds from Enter to the tool call, and a BEL counter that follows Windows Terminal's output state machine counts the bell bytes after the tool call. Derived from `evidence/artifacts/terminal-experience-20260928/alert_probe.py` (sha256 prefix `1282ff2b` at the derivation): the `push` kind, `--bell-hook`, `--no-user-settings`, `--sleep`, `--no-focus-report`, the focus-out report and the timing lines are the additions. `--selftest` checks the counter | arms A `push --no-user-settings`, B `... --bell-hook`, C `push` (the user's own settings), D `... --no-focus-report --sleep 75`, E `... --no-focus-report --sleep 15` |
| `tmux_bell_probe.py` | Whether tmux passes a pane's BEL to the outer terminal, so the bell still rings for an agent-team lead in a tmux pane: a private tmux server with an empty configuration, a client in a Python pty (which stands for Windows Terminal only in that a bare BEL is what the hook writes), five arms (default, `bell-action any` set explicitly, `bell-action none` as the negative control, `visual-bell on`, a pane that prints no BEL), all five required to read 1, 1, 0, 0, 0 for exit 0 (`--selftest` shows that a wrong count in any single arm fails, and three shutdown-failure controls with a wrapper that refuses `kill-server`: one that answers honestly must still end with no tmux process left; one that lies about the server's pid (init's) must keep the socket and fail the probe; one that answers the pid of another private tmux server must leave that server alone and fail the probe, which only the command-line check of the identity can do, as `terminal-lane-cross-family-review-20260930/tmux_identity_mutant.py` shows by deleting it). The private server is stopped and verified gone (its pid, start time, a state other than zombie and a command line that holds the private socket path) before its socket directory is removed | `python3 -B tmux_bell_probe.py` (needs tmux) |
| `replace_bell_group.py` | How the settings files were brought to the overlay when its matcher changed: the repository's merge tool never changes the matcher of a group that already runs the bell command, so the script removes that group on a private copy, merges the overlay again with the repository's own tool, checks that only the bell group and the overlay's own top-level keys (`$schema`, `preferredNotifChannel`, and those only when the file lacks them) differ, and with `--apply` installs the copy through the merge tool's own `write_backup` (never overwrites) and `atomic_write` (a random staging name in the same directory), only over the bytes it read: it compares the live file with its read before the backup, the backup with its read and the live file again right before the replace, and refuses when another writer saved before the last of them; a save between that comparison and the rename is lost and is in neither file (a documented residual with a case of its own; `local` only: the second-distro target was removed with that distro). It refuses a bell group that holds another hook or a key beyond `matcher` and `hooks`, a bell hook with a key beyond `type` and `command`, a matcher that names a type the overlay's does not (or none), an existing different `preferredNotifChannel`, two bell groups, a symlinked file, an unknown target or flag; finds a hand-requoted spelling of the bell command; and exits nonzero on a failed write or read-back. "Nothing to do" is reported only when the bell group equals the overlay's and merging would change nothing | `python3 -B replace_bell_group.py <checkout> local [--apply]` |
| `replace_bell_group_controls.py` | 27 cases for the script above, each a subprocess against a synthetic `HOME` (never a real settings file): the safe cases succeed (an old matcher, a hand-requoted bell command, a file with no bell group, a file that already equals the overlay, an unrelated group beside the bell group), each refusal leaves the file byte-identical with no backup, and `--apply` installs the merged copy after a backup equal to the original, keeps a mode other than 0600 on the file and its backup, leaves no staging file, does not follow a symlink at the old fixed staging name, and is idempotent; five cases inject another writer's save through `concurrent_writer_harness.py`: after the merge, at the backup, while the backup is being copied (an atomic save) and after the backup must each be refused and keep that save, and at the rename itself (the documented residual) the run exits 0 and that save is in neither the installed file nor the backup; each case requires the harness's marker line, so an injection that did not happen fails it | `python3 -B replace_bell_group_controls.py <checkout>` |
| `replace_bell_group_mutants.py` | Negative controls for the cases above: the unmutated script, then fifteen copies each with one guard removed (the fixed staging name, the extra-key checks on the hook and on the group, the matcher comparison, two variants of the strict "nothing to do", the overwrite check, the backup, the three lost-update comparisons (before the backup, of the backup, right before the replace), the mode, the other-hook check, the two-group check, the symlink check); each mutant must make exactly the cases named for it fail | `python3 -B replace_bell_group_mutants.py <checkout>` |
| `concurrent_writer_harness.py` | Test harness for the controls above: runs the replacement tool in one process and injects another writer's save of the live settings file at a chosen moment (after the merge on the private copy, at the backup, while the backup is being copied as an atomic save, after the backup, or at the rename); it edits the `model` key only and prints one marker line on stderr when it does. Not a measurement of its own | used by `replace_bell_group_controls.py`; `python3 -B concurrent_writer_harness.py after-merge|at-backup|during-backup|after-backup|at-replace <script> <checkout> <tool arguments ...>` |

`recorded/` holds the actual returned output of the runs the receipt cites, as text (no screen contents, no paths, no session ids): `push_probe_arms.txt` (arms A to E, and the first attempts of A and B that ended without a tool call under a heavily loaded host), `notification_types_scan_2.1.283.json`, `..._2.1.284.json`, `..._2.1.285.json` (the scan's report per release), `scan_reader_negative_control.txt` (the output of `scan_reader_mutants.py`), `tmux_bell_probe.txt`, `replace_bell_group_controls.txt`, `replace_bell_group_mutants.txt`, `replace_bell_group_live_dry_runs.txt` (the final tool without `--apply` on this host's and the second distro's settings), `overlay_noop_check.txt` (the earlier check that the live file carries the overlay), `unit_tests.txt` and `exit_codes.txt` (the exit code of each command).

Not retained: the raw hook payloads of the probes (session ids, paths), which the probe removes, and the coordinator's own output of the same probe on this host's settings before the change, which is recorded in the
receipt as values.
