# Terminal experience acceptance scripts (2026-09-28)

The probes behind [the decision](../../../docs/decisions/2026-09-28-terminal-experience.md) and its
[receipt](../../receipts/terminal-experience-20260928.json). They are read-only or write only to the system temporary
directory, with one exception: `alert_probe.py plan` asks the real client to write its plan file, which the client stores in its own plans directory
(default `~/.claude/plans`), outside the probe's temporary directory, and the probe does not remove it. None of them edits a settings file and none writes into this folder. `alert_probe.py` deletes its private payload
directory, also when interrupted or failing; `color_capture.py` deletes its throwaway configuration directory when it finishes;
`validate_fragment.py` keeps a downloaded copy of the schema there as a cache. Each was run on the workstation the receipt names.

| Script | What it measures | How it was run |
| --- | --- | --- |
| `wt_tab_titles.ps1` | Windows Terminal tab titles through UI Automation: counts of tabs, tabs still showing the static profile title, distinct dynamic titles and the largest duplicate group. Never prints a title | `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <path>` |
| `wt_tab_sentinels.ps1` | The same read, plus the raw name of tabs whose title starts with `trial-` or is `title-trial-ok` (trial sentinels carry no session content), and a SHA-256 prefix of the sorted names | same |
| `color_capture.py` | The colour classes Claude Code emits: runs `claude --bare` for 7 s in a pty with a throwaway `CLAUDE_CONFIG_DIR` (deleted afterwards) and a dummy API key and counts `38;2`, `48;2`, `38;5`, `48;5` and basic SGR sequences (the parameters are read as the pinned Windows Terminal parser reads them, `adaptDispatchGraphics.cpp` at v1.24.11911.0: a number saturates at 65535, a missing component is 0, a `38`/`48` group applies a colour only when its components are within a byte (colon form: and its colour-space field is empty; trailing sub-parameters are ignored), and a group the parser reads but does not apply is counted apart in `not_applied_groups`), once with `COLORTERM` unset and once with `truecolor` | `python3 color_capture.py` (needs `claude` on `PATH`) |
| `alert_probe.py` | Whether a pending `AskUserQuestion` (`ask`) or plan approval (`plan`) raises a Notification event and a bare BEL byte, and how long after the dialog opens. Its BEL counter decodes the pty stream as UTF-8 and ignores C1 control characters like the pinned output engine (revised 2026-09-30). The run exits 2 when the dialog never opened and 1 when the hooks-disabled control saw a BEL; SIGINT, SIGTERM and SIGHUP are LATCHED by a handler that only records the first one and returns (a handler that raises can fire between any two statements: Python's `signal` documentation says such an exception "may be raised after any bytecode instruction"); the latch stays installed until the handoff, `end_by_latched_signal`, which `main` runs once, in its `finally`, as the last safe point: it blocks the handled signals, reads the latch and then either ends the process BY the first signal or, with none latched, gives every handler that is still the latch back to the default action before the mask returns (so a signal that lands after the snapshot ends the process instead of being latched and lost, and a second signal after the cleanups cannot replace the first); the spawn and the observation loop check the latch at explicit safe points, the cleanups always run to their end and the probe then ends BY the latched signal (it resets the signal to its default action, unblocks it and sends it to itself, with no output before the kill: the measurement collects its result lines with `say` and `emit_report` prints them after the handoff, so a closed or full stdout cannot keep the probe from ending by the signal, a signal during the output takes its default action, and a failed write sends what is left in the buffer to devnull so that the final flush cannot turn the exit status into 120). That matters to a shell that waits cooperatively: with SIGINT sent to the process group, as Ctrl-C does, a bash loop stops after a child that died by SIGINT and goes on after one that merely exited 130, while it goes on either way when only the child gets the signal (the shell must receive it too), and dash stops on its own SIGINT whatever the child does; only bash and dash were measured, by `terminal-lane-cross-family-review-20260930/shell_loop_control.py` (Cracauer, cons.org/cracauer/sigint.html). "First" means first dispatched, since signals pending together run their handlers in ascending number (`signal_order_probe.py` there); a signal the parent ignored (nohup, a background job) stays ignored; the prompt is typed with a latch check between keystrokes and the Enter is checked and written with the handled signals blocked, so no Enter is ever written after the latch is set; `--selftest` covers it end to end: one and two SIGTERMs, two SIGINTs, SIGTERM then SIGINT (the first signal is the one that ends the probe: the exit is the negative signal number, and every run of the sweep must end BY SIGTERM: an exit status 143 no longer passes), a SIGTERM delivered at each line a dry run reaches (122 of the 184 lines with code in `main`, `with_private_dir`, `measure`, `end_by_latched_signal` and `emit_report`: every line that acquires or releases the private directory, the pty, the client and the handlers, the handoff and the output after it, 45 of them up to the spawn guard, where no client may have been created: the driver counts the `subprocess.Popen` calls of the client, and it ends like the probe's own `__main__` block; the lines after the prompt is typed, the observation loop, the report and the branches the dry run does not take are NOT swept; the client must have been running when the signal fired at ten lines or more), the measurement's own exit status (2 when the dialog never opened, 1 for a hooks-disabled control that saw a BEL, 0 for a quiet one), a closed stdout (with a latched signal, and with none: the exit status must stay the measurement's), a full pipe nobody reads (with a latched signal, or with one sent once the child is seen blocked in its write) or a blocked signal that does not keep the probe from ending by the signal (the real `main` with a measurement that signals itself, its children run without PYTHONUNBUFFERED), a second signal after the cleanups that does not replace the first, and two negative controls (a client that never starts, or exits at once, is rejected); in-process tests check the latch, the private directory, an inherited SIG_IGN (also at the end of the process), the typing (five situations), a truncated sweep record that is reported while the stand-in is killed, and that `measure` and `type_prompt` write nothing to stdout or stderr themselves; the selftest refuses to run when SIGINT, SIGTERM or SIGHUP is ignored in its process (a background job of a non-interactive `sh` ignores SIGINT, and the probe honors an inherited ignore); `pty_probe_mutants.py` shows each guard's removal failing exactly its cases. Drives a real short session from an already-trusted directory with `--setting-sources user` plus an observer hook overlay, sends no keys while waiting, and never accepts a workspace-trust dialog. `ask` runs in the user's own default permission mode and prints the mode read from the on-screen footer (`--permission-mode` forces one); `plan` runs in plan mode. `--control` runs the same setup with every hook disabled and detects the dialog from its on-screen text (0 BEL bytes expected, which attributes the BEL to the hook; the Notification count is not observable in that mode). `--selftest` checks the BEL byte counter, which models the pinned Windows Terminal output parser, against 28 cases, and the private-directory cleanup after an interruption and a failure | `python3 -B alert_probe.py ask`, `... plan`, `... ask --control`, `... plan --control`, `... ask --permission-mode default`, `... --selftest` |
| `validate_fragment.py` | Every profile of a Windows Terminal fragment against `doc/cascadia/profiles.schema.json` at tag `v1.24.11911.0`, with the draft the schema declares (2020-12); the schema is cached in the system temporary directory (needs `gh`) | `uv run --no-project --with jsonschema python validate_fragment.py <fragment.json>` |
| `fragment_check_mutants.py` | Negative controls for the host repository's `checks/check-terminal-profiles.py`: nine single-defect mutants of the fragment (title suppression, a loud sound, a relative `bellSound`, an AI `bellStyle` without `taskbar`, `bellStyle` `all` and a `notification` list on static profiles, `audible` on a static profile, no `COLORTERM` key, `COLORTERM` in the command line) must each fail exactly one rule, the expected one (eight distinct rules), and the unmutated fragment must pass in fixture mode. Needs `~/code/nativestack-practice`; writes only to a temporary directory | `python3 -B fragment_check_mutants.py` |
| `pty_probe_mutants.py` | Negative controls for the signal handling of `alert_probe.py` and of its derivative `notification-types-20260929/push_notification_probe.py`: each of twenty-four mutants (no handler, a handler that raises as the earlier design did, the last signal winning, an observation loop that does not poll the latch, a cleanup that does not stop the client, a directory that is not removed, a spawn that is not guarded (it must fail through the sweep's client-start observation, not because its marker vanished), a latched signal that ends in an exit status instead of the signal, a measurement that ignores `exit_status`, an ignored signal that is latched anyway, four typing guards (each keystroke, the wait, the Enter, the signal block), a truncated sweep record that raises, a flush that comes back before the kill, handlers restored before the process ends, a signal that is not unblocked, a snapshot of the latch read without a block, a latch that is not given back to the default action when nothing was latched, an ignored signal given back to the default action too, a diagnostic printed before the handoff, a failed report that leaves its bytes for the final flush, a measurement that writes a result line itself) is a copy of the probe with one guard removed, and the twelve cases of the probe's selftest that can see a guard (one SIGTERM, two SIGTERMs, two SIGINTs, SIGTERM then SIGINT, a SIGTERM at each line a dry run reaches, the exit status, an inherited SIG_IGN, the typing, a closed or stuck stdout or a blocked signal, a second signal after the cleanups, a truncated sweep record, no output while the latch is installed) must fail exactly for the mutant they belong to; thirteen mutants whose guard only the seven quick cases can see run only those (the line says how many cases it ran); the unmutated probe must pass all twelve; a skipped case ends the run; a failing case kills its own stand-in client, so a run leaves none behind (a run killed from outside can leave `sleep 3137<digits>` processes and `/tmp/sweep-*` directories: remove them by that exact name). Needs `~/code/native-agent-stack`; more than an hour per probe (the sweep runs about a hundred and thirty single-line runs against the unmutated probe and every slow mutant, and a mutant whose loop never stops waits for the 30 s limit of each signal case and can push the sweep case past the runner's 900 s limit, which counts as a failed case); `--quick` runs only the seven quick cases and `--only <text>` only the mutants whose name holds the text, for development; neither is a record; it refuses to run when SIGINT, SIGTERM or SIGHUP is ignored in its process; set `PYTHONUNBUFFERED=1` to see each verdict as it is reached | `python3 -B pty_probe_mutants.py <checkout> [alert] [push]` |
| `wav_levels.py` | Peak and RMS level (dBFS) and duration of candidate Windows notification sounds | `python3 wav_levels.py` |

Not retained: the observer hooks' raw Notification payloads (they carry session identifiers and paths; `alert_probe.py`
writes them to a private temporary directory and deletes it before it exits), the tab titles of live sessions, and the
trial profiles' identifiers. The counts and timings are in the receipt. Run scripts with `python3 -B` (or set
`PYTHONDONTWRITEBYTECODE=1`) so no `__pycache__` appears here.
