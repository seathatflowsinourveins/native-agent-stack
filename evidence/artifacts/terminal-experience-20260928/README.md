# Terminal experience acceptance scripts (2026-09-28)

The probes behind [the decision](../../../docs/decisions/2026-09-28-terminal-experience.md) and its
[receipt](../../receipts/terminal-experience-20260928.json). They are read-only or write only to the system temporary
directory, with one exception: `alert_probe.py plan` asks the real client to write its plan file, which the client stores in its own plans directory
(default `~/.claude/plans`), outside the probe's temporary directory, and the probe does not remove it. None of them edits a settings file and none writes into this folder. `alert_probe.py` deletes its private payload
directory, also when interrupted or failing; `color_capture.py` deletes its throwaway configuration directory when it finishes;
`validate_fragment.py` keeps a downloaded copy of the schema there as a cache. Each was run on the workstation the receipt names.

| Script | What it measures | How it was run |
| --- | --- | --- |
| `wt_tab_titles.ps1` | Windows Terminal tab titles through UI Automation: counts of tabs, tabs still showing the static profile title, distinct dynamic titles and the largest duplicate group. Never prints a title | `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <path>` |
| `wt_tab_sentinels.ps1` | The same read, plus the raw name of tabs whose title starts with `trial-` or is `title-trial-ok` (trial sentinels carry no session content), and a SHA-256 prefix of the sorted names | same |
| `color_capture.py` | The colour classes Claude Code emits: runs `claude --bare` for 7 s in a pty with a throwaway `CLAUDE_CONFIG_DIR` (deleted afterwards) and a dummy API key and counts `38;2`, `48;2`, `38;5`, `48;5` and basic SGR sequences (the parameters are read as the pinned Windows Terminal parser reads them, `adaptDispatchGraphics.cpp` at v1.24.11911.0: a number saturates at 65535, a missing component is 0, a `38`/`48` group applies a colour only when its components are within a byte (colon form: and its colour-space field is empty; trailing sub-parameters are ignored), and a group the parser reads but does not apply is counted apart in `not_applied_groups`), once with `COLORTERM` unset and once with `truecolor` | `python3 color_capture.py` (needs `claude` on `PATH`) |
| `alert_probe.py` | Whether a pending `AskUserQuestion` (`ask`) or plan approval (`plan`) raises a Notification event and a bare BEL byte, and how long after the dialog opens. Its BEL counter decodes the pty stream as UTF-8 and ignores C1 control characters like the pinned output engine (revised 2026-09-30). The run exits 2 when the dialog never opened and 1 when the hooks-disabled control saw a BEL; SIGINT, SIGTERM and SIGHUP are LATCHED by a handler that only records the first one and returns (a handler that raises can fire between any two statements: Python's `signal` documentation says such an exception "may be raised after any bytecode instruction"); the spawn and the observation loop check the latch at explicit safe points, the cleanups always run to their end and the probe then ends BY the latched signal (it resets the signal to its default action and sends it to itself: a parent shell tells a death by SIGINT from an exit 130, and only the first stops a loop after Ctrl-C, which `terminal-lane-cross-family-review-20260930/shell_loop_control.py` measures; Cracauer, cons.org/cracauer/sigint.html); "first" means first dispatched, since signals pending together run their handlers in ascending number (`signal_order_probe.py` there: SIGHUP, then SIGINT, then SIGTERM); a signal the parent ignored (nohup, a background job) stays ignored; the prompt is typed with a latch check between keystrokes and before Enter; `--selftest` covers it end to end: one and two SIGTERMs, two SIGINTs, SIGTERM then SIGINT (the first signal is the one that ends the probe: the exit is the negative signal number), a SIGTERM delivered at each line a dry run reaches (110 of the 160 lines with code in `main`, `with_private_dir` and `measure`: every line that acquires or releases the private directory, the pty, the client and the handlers, 45 of them up to the spawn guard, where no client may have been started; the lines after the prompt is typed, the observation loop, the report and the branches the dry run does not take are NOT swept; the client must have been running when the signal fired at ten lines or more), the measurement's own exit status (2 when the dialog never opened, 1 for a hooks-disabled control that saw a BEL, 0 for a quiet one) and two negative controls (a client that never starts, or exits at once, is rejected); in-process tests check the latch, the private directory, an inherited SIG_IGN and the typing; `pty_probe_mutants.py` shows each guard's removal failing exactly its cases. Drives a real short session from an already-trusted directory with `--setting-sources user` plus an observer hook overlay, sends no keys while waiting, and never accepts a workspace-trust dialog. `ask` runs in the user's own default permission mode and prints the mode read from the on-screen footer (`--permission-mode` forces one); `plan` runs in plan mode. `--control` runs the same setup with every hook disabled and detects the dialog from its on-screen text (0 BEL bytes expected, which attributes the BEL to the hook; the Notification count is not observable in that mode). `--selftest` checks the BEL byte counter, which models the pinned Windows Terminal output parser, against 28 cases, and the private-directory cleanup after an interruption and a failure | `python3 -B alert_probe.py ask`, `... plan`, `... ask --control`, `... plan --control`, `... ask --permission-mode default`, `... --selftest` |
| `validate_fragment.py` | Every profile of a Windows Terminal fragment against `doc/cascadia/profiles.schema.json` at tag `v1.24.11911.0`, with the draft the schema declares (2020-12); the schema is cached in the system temporary directory (needs `gh`) | `uv run --no-project --with jsonschema python validate_fragment.py <fragment.json>` |
| `fragment_check_mutants.py` | Negative controls for the host repository's `checks/check-terminal-profiles.py`: nine single-defect mutants of the fragment (title suppression, a loud sound, a relative `bellSound`, an AI `bellStyle` without `taskbar`, `bellStyle` `all` and a `notification` list on static profiles, `audible` on a static profile, no `COLORTERM` key, `COLORTERM` in the command line) must each fail exactly one rule, the expected one (eight distinct rules), and the unmutated fragment must pass in fixture mode. Needs `~/code/nativestack-practice`; writes only to a temporary directory | `python3 -B fragment_check_mutants.py` |
| `pty_probe_mutants.py` | Negative controls for the signal handling of `alert_probe.py` and of its derivative `notification-types-20260929/push_notification_probe.py`: each of eleven mutants (no handler, a handler that raises as the earlier design did, the last signal winning, an observation loop that does not poll the latch, a cleanup that does not stop the client, a directory that is not removed, a measurement that ignores `exit_status`, a spawn that is not guarded, a latched signal that ends in an exit status instead of the signal, an ignored signal that is latched anyway, typing that ignores the latch) is a copy of the probe with one guard removed, and the eight cases of the probe's selftest that can see a guard (one SIGTERM, two SIGTERMs, two SIGINTs, SIGTERM then SIGINT, a SIGTERM at each line a dry run reaches, the measurement's exit status, an inherited SIG_IGN that stays ignored, typing that stops at a latched signal) must fail exactly for the mutant they belong to; the unmutated probe must pass all eight; a failing case kills its own stand-in client, so a run leaves none behind (a run killed from outside can leave `sleep 3137<digits>` processes: remove them by that exact argv). Needs `~/code/native-agent-stack`; about three quarters of an hour per probe (the sweep runs about a hundred single-line runs against the unmutated probe and every mutant, and a mutant whose loop never stops waits for the 30 s limit of each signal case and can push the sweep case past the runner's 900 s limit, which counts as a failed case and leaves a few `/tmp/sweep-*` scratch directories behind: remove them by name); set `PYTHONUNBUFFERED=1` to see each verdict as it is reached | `python3 -B pty_probe_mutants.py <checkout> [alert] [push]` |
| `wav_levels.py` | Peak and RMS level (dBFS) and duration of candidate Windows notification sounds | `python3 wav_levels.py` |

Not retained: the observer hooks' raw Notification payloads (they carry session identifiers and paths; `alert_probe.py`
writes them to a private temporary directory and deletes it before it exits), the tab titles of live sessions, and the
trial profiles' identifiers. The counts and timings are in the receipt. Run scripts with `python3 -B` (or set
`PYTHONDONTWRITEBYTECODE=1`) so no `__pycache__` appears here.
