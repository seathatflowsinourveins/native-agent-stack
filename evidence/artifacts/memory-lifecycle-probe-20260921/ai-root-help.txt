`ai-memory` binary entry point.

Usage: ai-memory [OPTIONS] <COMMAND>

Commands:
  init                  Initialise the data directory layout
  status                Print runtime status (counts, paths, version)
  doctor                Check capture coverage: compare local harness session stores for this project against what the server captured, and warn when a harness ran here recently but has no captured sessions (its hook is likely missing)
  backfill              One-time import of this project's existing local harness session history into a brand-new (empty) ai-memory store, so installing hooks mid-project doesn't start amnesiac. No-op once the store has any sessions unless `--force`
  run                   Launch an agent in an opt-in, cross-harness managed workstream. Native arguments are forwarded except exact wrapper flags such as `--yolo` and `--fresh`
  show                  Pick a local project and installed harness, then launch from that checkout. Removes the `cd` step `run` requires
  continue              Resume the most recently launched managed checkout from anywhere, without `cd` and without picking from a list
  resume                Interactively pick a recent managed workstream and launch harness
  handoffs              List open cross-agent handoffs so a stale one can be cancelled by id
  message               Send, list, pop, or cancel cross-project agent messages (a directed, claim-once mailbox between two projects — see `docs/agent-messaging.md`)
  workstreams           List recent managed workstreams selectable from the current checkout
  rename-workstream     Rename a managed workstream in the current checkout. Metadata only: the ledger, linked harnesses, and which workstream a bare `ai-memory run` resumes are all unchanged
  workstream-search     Search the complete visible event ledger for a managed workstream
  audit-contamination   Audit the store for likely cross-project contamination (read-only, SQL-only). Flags sessions whose cwd resolves to a different project and observations whose project disagrees with their session
  search                Full-text search the wiki via FTS5
  read-page             Fetch and display the full body of a wiki page. Accepts either `--path` (exact path) or a positional query that searches FTS5 and fetches the top matching page
  write-page            Write or update a wiki page atomically (also indexes it in the store)
  delete-page           Delete a single wiki page. The server routes scope resolution through `resolve_ws_proj`, so a delete targeting a project that exists in multiple workspaces never silently lands in the wrong slot (the MCP `memory_delete_page` had that gap until this build)
  serve                 Run the MCP server (with watcher) over stdio or HTTP
  reset                 Wipe the data directory's wiki/, db/, raw/ contents
  compact               Reclaim free database pages. Deletes nothing
  backup                Snapshot wiki/, db/, and config.toml into a gzipped tarball
  export-okf            Export one project's wiki as an OKF v0.2 bundle tarball
  restore               Restore a backup tarball into the data directory
  reindex               Rebuild the SQLite index from the wiki/ markdown (the "DB is rebuildable from files" guarantee). Recreates workspaces/projects from each scope's `_meta.md` manifest and reindexes every page. Run with the server stopped, against a freshly-migrated (clean) data dir
  install-hooks         Print (or apply) lifecycle-hook configuration for an agent CLI
  hook                  Emit a single lifecycle hook natively (reads the event payload from stdin), avoiding a shell spawn. Used by the WindowsNative hook config; mirrors hooks/<agent>/<event>.sh
  install-mcp           Print MCP server registration snippets for any supported client. Current values are listed under `--client`; see docs/mcp-install.md for the full guide
  commit                Stage + commit the wiki tree under git
  checkpoints           List recent wiki git checkpoints for recovery
  restore-page          Restore a single wiki page from a git checkpoint and reindex it
  llm-test              Smoke-test an LLM provider by sending one prompt
  forget-sweep          Run the M8 retention sweep over episodic pages
  lint                  Run the M8 lint pass (stale / duplicates + optional LLM contradiction)
  curator               Run the rule-based curator report
  auto-improve-report   Run a read-only auto-improvement telemetry report
  auto-improve          Run auto-improvement for one completed session
  finalize-session      Manually finalize the latest open session for one agent in this project
  pending-writes        Review, approve, or reject staged auto-improvement proposals
  embed                 Compute + store embeddings for every latest page (M9)
  generate-auth-token   Generate a random hex bearer token for AI_MEMORY_AUTH_TOKEN
  setup-agent           One-shot agent setup for docker deploys: extract the bundled hook scripts to a host-mounted directory AND print the matching config snippet. Replaces the "clone the repo + cargo build" workflow for users who never want a local Rust toolchain
  bootstrap             Pre-load an existing project's history into the wiki by LLM-summarising git log, README, docs/, and module headers into seed wiki pages. Run once when adopting ai-memory in a project that's been around for a while. Requires AI_MEMORY_LLM_PROVIDER configured on the server
  install-instructions  Install the ai-memory usage snippet and managed Agent Skills into the project (or any markdown file / skill root you specify). Idempotent — bracketed by `<!-- ai-memory:start -->` / `<!-- ai-memory:end -->` markers so re-running replaces the block in place without duplicating
  install-skills        Install core-managed ai-memory Agent Skills into agent skill directories
  reorg                 Retro-fit existing sessions + observations to per-cwd projects based on the cwd captured at session-start. Pages are marked `is_latest=false` (they were a multi-project mash-up) so the next consolidation can regenerate them per-project. Idempotent
  purge-project         Delete a project: its pages, sessions, observations, handoffs, embeddings, managed workstreams and on-disk wiki files
  purge-session         Permanently delete ONE session and everything derived from it
  rename-project        Rename a project within its workspace. No files move on disk — the wiki is flat and pages are differentiated by project_id only. Useful after renaming the project's directory on disk so the hook router keeps writing into the same logical project
  move-project          Move a project into another workspace. A fresh destination is a lossless TRUE MOVE (re-stamp workspace_id, keep project_id, rename the dir) — sessions/observations/handoffs and history all survive. A destination that already holds a same-named project MERGES via copy+purge (only durable pages migrate, source purged). Either way the operation is irreversible — requires `--confirm`
  move-session          Move one session (or every session of a project) to another project, re-stamping its observations, handoffs, consolidation jobs and its `sessions/<id>.md` page in one transaction. Without `--confirm` it prints what would move (a real dry run, rolled back server-side)
  uninstall             Remove ai-memory's wiring (hooks, MCP, instructions, and default-root managed skills) from all detected agents. Dry-run unless `--apply`
  auth                  Manage optional upstream LLM provider authentication
  user                  Manage human users and deprecated 1.x compatibility tokens. All subcommands require the root bearer token
  api-key               Manage native `aim_` API credentials. All subcommands require the root bearer token and `[auth].token_pepper`
  completions           Print a shell-completion script to stdout. Generated from this binary's own command tree, so it never drifts from the real CLI surface. See `docs/shell-completions.md` for install paths
  help                  Print this message or the help of the given subcommand(s)

Options:
      --data-dir <DATA_DIR>
          Override the data directory.

          Defaults to a platform path under `dirs::data_local_dir()`. The config loader also honours `AI_MEMORY_DATA_DIR`.

      --config <CONFIG>
          Path to an explicit config file (defaults to `<data_dir>/config.toml`)

  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version
