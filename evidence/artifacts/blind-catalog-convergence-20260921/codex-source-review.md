# Independent source review: 20 functional layers

Frozen 2026-09-22 02:33:43 UTC; review date September 21, 2026, America/New_York.

All 20 layers have a provisional stack, challengers, primary-source evidence and a comparison that could change the choice. **None is locally accepted:** no installations, model runs, backtests, orders, paid hosting or restore trials were performed. The [JSON companion](./codex-blind-review.json) contains the complete per-layer rationale, 94 distinct evidence URLs, source-depth limits, failed fetches and 20 upstream head pins.

**Blinding is partial.** The neutral requirements file was the only local input read. No catalog artifact, ranking artifact, project memory or other review was opened. However, the ambient conversation supplied tool/skill names and project instructions naming a NautilusTrader preference. General model knowledge also influenced discovery. This is an independent source review before other-review disclosure, not proof of pristine selection or training-bias absence.

Primary means first qualification candidate for this requirement. Multiple tools often perform complementary jobs. No ranking was derived from stars, model agreement or vendor performance percentages.

Native clients and instructions have documented lifecycle and precedence differences that should be tested in the actual accounts. Claude's current [workflows documentation](https://code.claude.com/docs/en/workflows) includes returned failures and cancellation; a pipeline must preserve null/error results. Worktree ownership and operating-system isolation remain separate requirements.

The weakest shortlist is semantic code retrieval. Code-memory's compact architecture makes it a reasonable first experiment, but the [pinned test inspected](https://raw.githubusercontent.com/kapillamba4/code-memory/5a8db166ca11a90c093ba4a9a54d266cde756f54/tests/test_tools.py) exercises input validation, not conceptual retrieval accuracy. No embedding-service compatibility or retrieval-quality comparison was run. The composed Qdrant/LlamaIndex/FastEmbed alternative and reuse of the document retrieval stack remain open.

For durable memory, [Basic Memory](https://github.com/basicmachines-co/basic-memory) merits a portability trial, subject to its current AGPL licensing and prerelease dependency path. Its deletion and restoration behavior was not exercised. No advertised managed-service benchmark was transferred to an open-source memory implementation.

The equities engine choice remains unresolved. LEAN is the provisional candidate because both requested [IBKR](https://github.com/QuantConnect/Lean.Brokerages.InteractiveBrokers) and [Alpaca](https://github.com/QuantConnect/Lean.Brokerages.Alpaca) repositories were found, and pinned equity fill/dividend tests were inspected. Its [CLI requires a paid organization and Docker](https://www.quantconnect.com/docs/v2/lean-cli/key-concepts/getting-started); the [engine documents a direct source build](https://github.com/QuantConnect/Lean), whose broker setup remains untested. These are different deployment paths.

[NautilusTrader](https://github.com/nautechsystems/nautilus_trader) is a serious execution-oriented challenger. Current source documents a v2 release candidate, IB support and live-state limitations; this review did not establish an official Alpaca integration. In two sampled [risk tests](https://raw.githubusercontent.com/nautechsystems/nautilus_trader/82b66fee382086c803e27b9fd5c06f94d24d2831/crates/risk/tests/risk_engine.rs), the event count is asserted but the denial-variant boolean is not. Other sampled tests assert stronger outcomes. This bounded source observation is not an executed failure or a judgment of the entire suite.

[Databento's corporate-action reference](https://databento.com/docs/venues-and-datasets/corporate-actions) distinguishes retained point-in-time records from a latest view. [Alpaca's feed documentation](https://docs.alpaca.markets/us/docs/historical-stock-data-1) distinguishes IEX from consolidated SIP. SDK availability does not settle coverage, historical eligibility or data rights; no data was purchased or benchmarked.

Two operational details should survive later adjudication: [otel-tui](https://github.com/ymtdzzz/otel-tui) needs an explicit loopback bind for local-only collection, and [vLLM documents x86 CPU serving](https://docs.vllm.ai/en/latest/getting_started/installation/cpu/). A blanket GPU-only exclusion is unsupported. Neither inference stack was benchmarked.

Evidence is predominantly official documentation and READMEs. Selected immutable test assertions and systemd manual sources were read, but no test suite was run. Remote head pins identify sources, not installed or accepted versions; most documentation was read at moving URLs. Hosting, durable memory, semantic retrieval and the composed equity-agent/foundation layers remain especially dependent on untested integration assumptions. Exact resolved model/effort and provider usage/cost were unavailable.

The next decision requires workload evidence: complete worker failure accounting and enforced boundaries, attributable scoped retrieval and clean restoration, then licensed causal financial data, deterministic risk/accounting checks and separately qualified paper behavior for each broker. Agreement between independent reports cannot replace those results.
